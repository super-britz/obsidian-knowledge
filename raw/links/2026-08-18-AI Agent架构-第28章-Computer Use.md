# AI Agent 架构：第 28 章 Computer Use

- **原文标题：** 第 28 章：Computer Use
- **URL：** https://waylandz.com/ai-agent-book/%E7%AC%AC28%E7%AB%A0-Computer-Use/
- **访问日期：** 2026-08-18
- **资料类型：** 在线书籍章节页

## 来源摘要

本章讨论让 Agent 通过截图理解界面，并以鼠标、键盘等动作操作没有 API 的网页或桌面系统。其基本循环是感知（截图/OCR/元素识别）→ 决策（规划和坐标）→ 执行（点击、输入、滚动）→ 验证（再次观察实际结果）；视觉驱动比 DOM 选择器自动化更能适应界面变化，但每次视觉模型调用成本更高，且会带来坐标、加载时机和状态误判问题。

原文建议在 Agent 与执行层之间传递归一化坐标，再由执行层换算实际像素，处理分辨率和 DPI 差异。操作应包含置信度、预期结果和是否需确认；执行后等待页面稳定，再通过截图对比或视觉判断验证结果。失败恢复需要有限重试和恢复策略，避免无限循环。

章节把误操作、敏感截图泄露、网页提示注入、越权访问和资源失控列为主要风险。缓解措施包括沙箱、域名白名单、敏感区域遮盖、最大迭代限制、OPA 策略，以及删除、提交、付款、发送、登录凭证等关键操作的人类确认。生产中宜混合使用：稳定、已知页面优先 DOM 自动化，未知或变化界面才使用 Computer Use。

## 使用边界

- Computer Use 是高副作用执行能力，不应以模型置信度替代权限校验、策略限制和人工确认；界面文字本身也可能是不可信指令。
- 截图会离开执行环境并可能包含个人信息、密码或业务数据；遮盖、最小化截图和受控模型/数据边界是独立要求。
- “页面视觉上变化”不必然等于业务操作已成功；不可逆操作应使用系统回执、状态查询或人工复核，而不只依赖截图。

# AI Agent 架构：第 45 章 Computer Use 上下文管理

- **原文标题：** 第 45 章：Computer Use 上下文管理

- **访问日期：** 2026-08-19
- **资料类型：** 在线书籍章节页

## 来源摘要

本章指出 Computer Use 同时累积文本观察、浏览器/GUI 截图和用户或其他工具产生的图像；它们的可操作性与老化速度不同，不能用一个上下文数量或图像上限统一处理。公开快照将控制拆为四类：单次观察文本上限、文本观察滑动窗口、浏览器/GUI 图像窗口，以及更宽松的全局含图消息上限。单项大小、条目数量、来源专属老化与全局兜底分别处理不同故障。

超大 GUI 观察应在进入上下文时按 rune 安全截断，并加入包含原始长度的明确标记；较旧观察则在组装请求时替换为单行存根。这区分“新鲜时也过大”与“曾经有用、现在过期”。浏览器截图过滤要按 GUI 工具身份和 `tool_use_id` 限定，只裁剪过时视口，不惩罚用户上传或批量视觉任务；全局图像过滤随后提供更宽的保护。

裁剪时不能删除 `tool_result` 块或破坏 `tool_use_id` 配对，而要用稳定、明确的占位文本替换过期文本或像素。过滤器必须幂等，保证同一历史重复组装后字节稳定，避免 Prompt Cache 反复失效；首次修改应留下可观测事件与哈希。Prompt 中不再携带的内容不等于删除审计记录、截图文件或用户上传，这些存储生命周期应由不同策略拥有。

## 使用边界

- 具体窗口、rune 上限和全局图像数来自有日期的 Kocoro 快照；应按导航、状态比较、批量图像与多语言页面等真实任务调优，而非照抄数字。
- 上下文裁剪降低请求载荷，不替代截图文件清理、审计保留、用户素材所有权、权限控制或数据治理。
- 浏览器导航通常偏好最新视口，视觉比较和画布任务可能需要多步历史；激进策略必须按生成方和任务边界限定。

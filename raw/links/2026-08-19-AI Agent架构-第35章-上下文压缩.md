# AI Agent 架构：第 35 章 上下文压缩

- **原文标题：** 第 35 章：上下文压缩
- **URL：** https://waylandz.com/ai-agent-book/%E7%AC%AC35%E7%AB%A0-%E4%B8%8A%E4%B8%8B%E6%96%87%E5%8E%8B%E7%BC%A9/

- **资料类型：** 在线书籍章节页

## 来源摘要

本章把上下文压缩定义为有损的 Prompt 整形，而不是单一的“满了就摘要”。摘要本身也要调用模型并占用窗口，因此仅在超限后才压缩会让恢复动作同样无法执行。可靠设计使用三道互补闸门：在估算使用量接近阈值时主动压缩、发送请求前再次 Preflight 检查、Provider 返回上下文超限时触发一次 Reactive 回退。阈值应由本轮请求、预留响应和压缩空间的 token 余量倒推，而不能只选择一个看似合理的百分比。

压缩后的历史应保留开场约束、已验证摘要和有硬下限的近期对话；截断近期消息时还要修复工具调用与结果的配对边界。摘要器自身需使用更受控的输入：设置独立上限、避免反复压缩已有摘要、拒绝空摘要并保留上一份可用摘要、在 Reactive 路径中最多重试一次且不复位标志。不同压缩失败路径应有可区分遥测。

压缩会重写 Prompt 历史，而 Prompt Cache 依赖稳定前缀。若截断边界由当前历史长度决定，边界会逐轮漂移，缓存不断失效；边界应由上下文窗口或会话目标等稳定输入推导。单个超大工具结果应外溢到 Prompt 外并留下指针；审计留存与用户交付内容应完整另存，不能被工作上下文压缩替代。

## 使用边界

- 压缩是为模型工作上下文腾出空间，不是存档、证据保留或用户交付物的删除策略。
- 三道闸门处理不同失效模式：估算偏差、请求组装后的突增和 Provider 的最终裁决，不能用单一阈值替代。
- 公开源码中的具体百分比、消息数量和字节上限属于有日期的实现快照；可迁移原则是保留余量、分级兜底、摘要器受限和缓存边界稳定。

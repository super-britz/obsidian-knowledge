# AI Agent 架构：第 20 章 三层架构设计

## 来源摘要

本章提出将生产级 Agent 系统拆分为三层：Orchestrator 负责持久化工作流、路由、预算和结果综合；Agent Core 在沙箱与资源限制中执行工具；LLM Service 对接模型、Embedding 与 AI 生态。原文以 Go、Rust、Python 分别说明并发/工作流、隔离执行和模型生态的优势，但也明确三层部署会增加服务、调试与通信成本，低风险原型未必需要拆分。

层间通过 gRPC/HTTP 交互，并传播 Workflow ID 以支持分布式追踪、资源归属和问题定位。超时从外向内递减；健康检查、依赖重试、优先级队列、配置热重载和环境变量注入用于提升生产运行的可用性与可运维性。跨层调用不具备天然的原子事务，原文建议由持久化工作流活动承担重试与恢复。

## 使用边界

- 三层职责分离不是语言绑定；语言和进程形态应按团队能力、运行时生态和隔离要求决定，不能把“Go/Rust/Python”当作唯一正确组合。
- 远程调用、任务重试和健康检查并不能自动保证幂等、数据一致或安全授权；接口契约、状态权威、补偿和审计仍需单独设计。
- 沙箱减少工具副作用的影响面，但不等于业务授权、租户隔离或输出可信；这些控制必须贯穿编排、执行和数据层。

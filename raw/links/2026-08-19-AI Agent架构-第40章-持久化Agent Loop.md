# AI Agent 架构：第 40 章 持久化 Agent Loop

- **原文标题：** 第 40 章：持久化 Agent Loop

- **访问日期：** 2026-08-19
- **资料类型：** 在线书籍章节页

## 来源摘要

本章把持久化 Loop 定义为“使中断的 Turn 可发现、可判断、可受限恢复”，而不是无条件续跑。Checkpoint 应落在模型调用完成、工具批次完成、昂贵摘要完成等阶段边界，并做防抖；危险副作用发生前必须先留下 Session 记录。启动时不应扫描全部 Session，而要读取持久化中断标记索引，并保持“磁盘上 InProgress 为真，当且仅当中断标记存在”的双向不变量，所有完整保存和补丁路径都要维护它。

恢复至少经过三道门：全局开关可暂停自动续跑但保留证据、过期窗口拒绝陈旧意图、尝试次数限制避免启动循环。尝试数必须在模型调用前持久化，否则调用期间崩溃会让计数永远无法增加。恢复后的 Turn 无论原 Session 是桌面还是交互来源，都应视为无人值守，并沿用原 RouteKey 进入同一并发锁，避免无人值守特权继承或同一 Session 出现双写者。

Checkpoint 只记录执行意图或工具调用过程，不能证明外部副作用是否落地；邮件、支付、推送等副作用必须由工具自身提供幂等键。Checkpoint 还需版本化，无法兼容读取时应以可观测的放弃处理；用户取消必须清除恢复标记，不能在下次启动时复活已取消的任务。

## 使用边界

- 持久化提高崩溃后的恢复能力，但不替代幂等、取消、授权或副作用结果对账。
- 过期、放弃和恢复都应成为可查询事件；静默恢复和静默丢弃都会制造不可解释行为。
- 公开源码中的防抖时间、过期时长与尝试次数属于有日期的实现快照；可迁移原则是“阶段性 Checkpoint、索引化发现、恢复三道门、当前时刻权限、工具层幂等”。

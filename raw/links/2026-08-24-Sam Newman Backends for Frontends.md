# Sam Newman：Backends for Frontends

- **作者：** Sam Newman
- **URL：** https://samnewman.io/patterns/architectural/bff/
- **访问日期：** 2026-08-24
- **资料类型：** BFF 模式原始说明文章

## 来源摘要

文章提出用面向单一用户体验的服务端组件替代不断膨胀的通用 API 后端。BFF 与特定 UI 紧密关联，通常由同一团队维护，使客户端和服务端接口可以围绕同一体验共同演进，而不必让一个中心团队平衡所有客户端的优先级。

文章也讨论了 BFF 数量、多个下游调用、复用、服务端页面生成、缓存、自治和通用边界能力。作者提醒团队结构会变化，不能只按当前团队图机械决定永久服务边界；身份认证、日志等通用外围责任也可能更适合放在上游基础设施中。

## 使用边界

- 原文给出的是架构模式和经验，不是要求所有前端必须拥有独立 Node.js 服务。
- “面向一个用户体验”强调变化和所有权一致，不等于按屏幕尺寸、路由或技术栈逐个拆服务。
- 同团队拥有前端和 BFF 可以减少协调，但不会消除下游契约、部署兼容、容量与值班责任。

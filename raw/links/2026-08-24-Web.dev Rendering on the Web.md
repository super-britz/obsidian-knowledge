# web.dev：Rendering on the Web

- **机构：** Google / web.dev
- **URL：** https://web.dev/articles/rendering-on-the-web
- **访问日期：** 2026-08-24
- **资料类型：** 官方 Web 性能文章

## 来源摘要

文章统一定义了 Server-side Rendering、Client-side Rendering、Prerendering 与 Hydration，并从 TTFB、内容出现、主线程工作和交互响应比较它们的成本。SSR 可以在服务端完成取数与 HTML 生成，减少浏览器生成内容前的往返和 JavaScript 工作，但请求时计算可能增加 TTFB；Static Rendering 可以预先生成 HTML 并交给 CDN 复用，但页面数量、构建成本和数据变化会限制它的适用范围。

文章明确指出，一个站点可以为不同页面采用不同渲染方式。服务端和客户端共同渲染属于具有独立代价的组合方案：Hydration 可能同时发送 HTML、初始数据和客户端实现，页面也可能先可见、后可交互。流式、渐进或局部激活能重新安排等待与客户端工作，但仍会增加边界和协调责任。

## 使用边界

- 文章提供渲染术语和性能取舍，不替具体项目决定数据权威、缓存新鲜度、权限或部署拓扑。
- 文中的工具示例和部分经验判断会随框架演进；长期可迁移的是构建时、请求时、客户端计算与 Hydration 之间的成本交换。
- 单个通用性能指标不能证明业务任务完成，仍需结合真实用户旅程和项目预算。

# web.dev：Critical Rendering Path

- **机构：** Google / web.dev
- **URL：** https://web.dev/learn/performance/understanding-the-critical-path
- **访问日期：** 2026-08-24
- **资料类型：** 官方性能课程

## 来源摘要

web.dev 将浏览器的初始渲染路径概括为：从 HTML 构建 DOM、从 CSS 构建 CSSOM、执行会改变二者的 JavaScript、构建 Render Tree，再进行 Style、Layout、Paint 与 Composite，最终把像素显示到屏幕。

浏览器会渐进处理 HTML，不必等全部文档、图片、字体和非阻塞脚本下载完才开始首次渲染；但头部的阻塞 CSS 和同步脚本可能延迟初始内容。页面后续资源到达或状态变化时，还会重复部分渲染步骤。

## 使用边界

- Critical Rendering Path 主要解释首次像素为何被阻塞，不等于页面所有功能就绪的完整关键路径。
- FCP 或 LCP 改善不自动证明交互响应、业务数据正确或任务已经完成。
- 浏览器可以并行发现、下载和处理部分资源，因此完整等待时间由依赖关系与最长链路决定，不能把所有步骤简单相加。

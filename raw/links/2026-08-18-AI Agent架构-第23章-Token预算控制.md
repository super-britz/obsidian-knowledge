# AI Agent 架构：第 23 章 Token 预算控制

- **原文标题：** 第 23 章：Token 预算控制
- **URL：** https://waylandz.com/ai-agent-book/%E7%AC%AC23%E7%AB%A0-Token%E9%A2%84%E7%AE%97%E6%8E%A7%E5%88%B6/
- **访问日期：** 2026-08-18
- **资料类型：** 在线书籍章节页

## 来源摘要

本章将 Token 预算定位为 Agent 系统的成本防火墙：单次任务、会话累计和单个 Agent 各有预算，以阻止单个复杂任务、连续交互或多 Agent 协作耗尽资源。原文给出硬限制、接近阈值时预警以及超额审批三种处理方式；Token 估算存在误差，实际输入/输出 Token 与成本需在执行后记录。

原文还介绍了接近预算上限时的背压、连续超限时的熔断、输入/输出分开计价、预算感知的 Agent 执行与双路径记录。背压延迟应在 Temporal Workflow 层而非 Activity 层等待，避免占满 Worker；并发预算更新需要同步保护；重试和多层记录必须用幂等机制避免重复计费。

章节建议暴露已用 Token、累计成本、超限次数、背压延迟和熔断状态等指标，并对超限率、熔断状态设置告警。

## 使用边界

- Token 预算限制的是模型调用资源，不等同于结果质量、业务价值、权限或真实全部成本；高价值任务可能需要审批、降级或人工接管，而非简单截断。
- 预估 Token 只用于事前决策，不能当作最终账单；实际用量与定价配置仍需在执行后记录、核对和审计。
- 背压适合逐步减少可延迟的工作，不替代硬性上限；熔断是保护措施，不应成为隐藏系统错误或误伤正常用户的借口。

# AI Agent 架构：第 13 章 编排基础

- **原文标题：** 第 13 章：编排基础
- **URL：** https://waylandz.com/ai-agent-book/%E7%AC%AC13%E7%AB%A0-%E7%BC%96%E6%8E%92%E5%9F%BA%E7%A1%80/
- **访问日期：** 2026-08-17
- **资料类型：** 在线书籍章节页

## 来源摘要

本章从单 Agent 在独立任务上的串行时延、通才深度和单点故障出发，说明多 Agent 的价值不在于增加模型实例，而在于通过分工获得并行、专化或冗余。原文同时强调，多 Agent 会新增通信、同步、结果整合和成本控制开销；简单任务应继续由单 Agent 处理。

原文将编排器定义为协调层，主要负责任务分解、按能力分发、依据依赖与并发限制调度，以及对结果去重、过滤、处理矛盾并综合交付。路由可在简单单步任务、标准 DAG 工作流和复杂的 Supervisor 协调之间选择；并行适用于无依赖任务，串行适用于前序结果是后续输入的任务，混合模式则按依赖就绪状态执行。

章节还将 Token 总预算分配、并发限流、暂停/恢复/取消信号向子工作流传递，以及失败子任务与部分结果的处理列为编排的运行时责任。结果综合不能把原始文本直接拼接：应保留任务状态和来源，先处理重复、失败和冲突，再以统一结构交付。

## 使用边界

- 原文的复杂度阈值、子任务数量和具体框架实现是示例，不应直接作为通用生产阈值；实际路由需结合任务依赖、限流、工具、风险、预算和验收要求评估。
- 角色提示或多个模型输出不会自动形成专业能力、事实正确性或容错；关键事实、写入副作用和最终交付仍需工具回执、策略与验收控制。
- 并发只在独立工作和资源允许时减少时延；共享资源、写冲突、配额、失败传播或综合开销可能使串行或单 Agent 更合适。

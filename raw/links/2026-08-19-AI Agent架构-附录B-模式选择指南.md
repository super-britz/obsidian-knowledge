# AI Agent 架构：附录 B 模式选择指南

- **原文标题：** 附录 B：模式选择指南 (Pattern Selection Guide)

- **访问日期：** 2026-08-19
- **资料类型：** 在线书籍附录页

## 来源摘要

原文用决策树、对比矩阵、反模式、成本—质量—延迟权衡、案例和配置示例，回答“什么场景用什么模式”。单 Agent 部分依次比较直接 Prompt、ReAct、Planning、Reflection、CoT、ToT、Debate 与 Research；多 Agent 部分比较并行、串行、DAG、Supervisor 与 Handoff。

主线是“优先选择简单模式，只在必要时升级”：先判断是否需要外部工具、任务是否存在稳定依赖、是否需要质量校验、是否必须探索多个候选或协调动态角色；再接受相应的调用次数、延迟、上下文、调度与可观测性成本。原文还警告不要为多 Agent 而多 Agent、不要过度拆分、不要把有依赖的任务强行并行、不要让反思或迭代无限进行。

## 使用边界

- 原文中的 Token、延迟、并发与配置数值是示例性估算，不是可直接复制的生产基准；应使用本地任务集和验收指标校准。
- “模式选择”不能只按任务名称判断，必须先确认目标的外部完成证据、步骤是否可预知、失败代价和执行权限。
- 模式能补足推理、调度或协作的缺口，但不能替代工具真实性、权限控制、预算、审计与恢复机制。

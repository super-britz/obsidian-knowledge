# 推理时计算与推理模型原始资料

这组一手资料用于核验 Test-Time Compute、强化学习推理、长推理轨迹和推理蒸馏的机制与实验边界。

## 来源

- Snell et al., *Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters*（2024）：https://arxiv.org/abs/2408.03314
- DeepSeek-AI, *DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning*（2025）：https://arxiv.org/abs/2501.12948
- Kimi Team, *Kimi k1.5: Scaling Reinforcement Learning with LLMs*（2025）：https://arxiv.org/abs/2501.12599
- OpenAI 官方 API 文档，*o1 Model*：https://developers.openai.com/api/docs/models/o1

## 使用边界

- Test-Time Compute 可以表现为更长的单条轨迹、多次采样、搜索、验证或工具执行；“更多思考 Token”只是其中一种实现，收益依赖题目难度、候选质量和验证器。
- Snell 等人的“较小模型超过 14 倍大模型”结论限定在 FLOPs 匹配、基础模型已有非平凡成功率的部分问题上，不是任意小模型都可通过延长输出超过大模型。
- OpenAI 官方资料公开 o1 使用强化学习进行复杂推理并在回答前产生内部推理链，但未在该文档披露参数量、完整训练 Pipeline、PRM 或搜索实现；本地笔记不补全这些未公开细节。
- DeepSeek-R1-Zero 没有把 SFT 作为 RL 前置阶段，但仍从已经预训练的 DeepSeek-V3-Base 开始；最终 DeepSeek-R1 使用 Cold-Start 数据与多阶段训练。不能把它概括成“从零纯 RL 学会推理”。
- GRPO 省去单独训练的 Critic / Value Model，以同一 Prompt 的组内奖励估计相对优势；它仍依赖采样、奖励、参考策略约束和训练稳定性，不保证固定比例的成本下降。
- 推理蒸馏让学生模仿教师生成的轨迹或答案，但不会自动继承真实性、校准和分布外泛化；教师输出仍需筛选与验证。

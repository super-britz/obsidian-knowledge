# AI Agent 架构：第 7 章 上下文工程

- **原文标题：** 第 7 章：上下文工程

- **访问日期：** 2026-08-17
- **资料类型：** 在线书籍章节页

## 来源摘要

本章将上下文窗口类比为 LLM 的工作内存：它有限、易失且有推理与费用成本。上下文工程的任务不是只打磨提示词措辞，而是在每次模型调用时，组织系统指令、当前请求、历史、检索资料、长期信息、工具定义和输出约束等内容，使模型获得完成当前决策所需的最小高信号信息集。

原文指出，长上下文会带来超限、成本、关键信息被淹没和无关噪音干扰等问题；窗口变大不等于信息利用质量线性提高。为此给出四种策略：Write 将目标、进度和中间产物外置；Select 按当前任务检索相关内容；Compress 保留摘要和恢复线索以缩减历史；Isolate 让子任务在独立上下文中处理大量中间信息，只返回主任务所需结果。

章节还讨论 Token 预算、分层预算与背压，以及 Prompt Cache。缓存依赖稳定前缀和可预测的上下文组织，能降低重复输入的成本与延迟；它是成本优化，不替代信息选择、压缩或外部状态管理。

## 使用边界

- 上下文是一次决策的工作集，不等同于跨会话记忆；持久化什么、何时失效与怎样召回应由记忆和状态机制进一步定义。
- 压缩不应抹去恢复路径：重要结论应保留来源、文件位置、版本或可重新取得的原始证据。
- 检索内容、工具输出与外部文件仍是外部数据，进入上下文前需考虑相关性、时效性、可信度和注入风险。
- Context Rot、缓存命中率与 Token 成本受具体模型、供应商和任务影响，必须用实际任务成功率与成本数据验证。

# AI Agent 架构：第 3 章 工具调用基础

## 来源摘要

本章从 LLM 无法获取实时信息、执行精确计算、访问外部系统或私有数据这一能力缺口出发，说明工具使模型从“生成回答”转向“请求外部能力”。Function Calling 的核心不是模型直接执行函数，而是模型输出结构化的工具调用意图，由程序解析、校验并执行，再将结果返回模型。

原文用元数据、参数定义和执行逻辑描述一个工具：名称、说明、分类、认证、限流、超时、沙箱、危险标记与单次成本等元数据定义能力及其约束；JSON Schema 将工具与参数说明暴露给模型；执行逻辑需要异步执行、安全校验，并以含成功标记、输出、错误与运行元数据的结构化结果返回。

章节强调 description 和参数描述直接影响工具选择与填参质量；模型输出不应被假设为完美格式，执行侧需要类型容错、范围校验和失败处理。多工具场景应按任务、风险和成本过滤暴露的工具，并通过限流、超时与安全执行避免重复调用、卡死、越权或执行不安全表达式。

## 使用边界

- Shannon 的类、字段和具体实现用于说明，不构成跨框架的唯一工具模型。
- 工具成功只表示本次调用完成，不等于用户目标已经完成；仍须由 ReAct 的完成条件和外部验收判断。
- 工具授权、策略治理与安全执行会在后续章节继续展开；本页只沉淀工具契约与调用边界的基础机制。

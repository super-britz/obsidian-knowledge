# Angular Style Guide

- **机构：** Angular 官方文档
- **URL：** https://angular.dev/style-guide
- **访问日期：** 2026-08-21
- **资料类型：** 官方框架风格指南

## 来源摘要

Angular 风格指南建议把应用代码按功能区域或共同主题组织，并让紧密相关的文件位于同一目录；它同时建议避免以 `components`、`directives`、`services` 等代码类型作为应用的主要目录划分。

该建议表达的是代码位置应服务于功能上下文和导航，而不是要求所有项目采用某个固定目录模板。指南也明确说明这些风格约定并非 Angular 运行所必需。

## 使用边界

- 这是 Angular 生态的风格建议，不是语言标准，也不能单独证明某个业务边界划分正确。
- 按功能放置文件只改善代码邻近性；若仍允许任意深度导入，目录本身不会形成封装。
- 跨功能的基础设施、设计系统和真正共享的领域能力仍可能按其他变化原因组织。

# AI Agent 架构：第 11 章 Reflection 模式

- **原文标题：** 第 11 章：Reflection 模式
- **URL：** https://waylandz.com/ai-agent-book/%E7%AC%AC11%E7%AB%A0-Reflection%E6%A8%A1%E5%BC%8F/
- **访问日期：** 2026-08-17
- **资料类型：** 在线书籍章节页

## 来源摘要

本章讨论以“评估 → 反馈 → 带反馈重生成”的循环改善 Agent 输出质量。单次 LLM 生成存在质量波动；Reflection 先按任务特定标准给当前回答评分并指出缺陷，未达标时将旧回答和具体反馈一同传入下一次生成，直到达到阈值或用尽重试次数。

原文将评估拆成分数和可操作反馈，并建议按研究、代码等任务使用不同准则。其实现配置包括是否启用、最大重试次数、质量阈值、评估标准和超时；生产中应限制重试，评估/重生成失败时优雅返回初始结果，并只对复杂或高价值的输出启用。

章节强调成本与评估可靠性：一次反思会增加额外评估与重生成调用，可能使 Token 和延迟接近翻倍；模糊反馈不会带来稳定改进；LLM 自评可能有偏见、标尺不一致或过度自信。缓解方式包括使用确定性规则检查短回答、引用和格式，必要时使用不同模型或多评估者，但核心仍是受限的迭代而非无限自我批评。

## 使用边界

- Reflection 适合高价值、可定义质量标准且允许额外延迟的报告、技术文档和复杂综合；简单问答、实时交互或评价标准高度主观的任务通常不值得启用。
- 评分是改进优先级信号，不是正确性证明；事实、代码、格式、安全和合规应优先由来源校验、测试、解析器、策略规则或人工审批验证。
- 自我反思不能弥补模型没有的知识或外部证据，也不能把错误的前提自动变成正确事实。
- 阈值、重试次数、模型选型和启用条件是业务参数，应以真实质量增益、成本、延迟和失败数据校准。

# AI Agent 架构：第 4 章 MCP 协议详解

- **原文标题：** 第 4 章：MCP 协议详解

- **访问日期：** 2026-08-17
- **资料类型：** 在线书籍章节页

## 来源摘要

本章将 MCP 定位为 Agent 工具的统一互操作协议：不同 Client 能以统一方式发现并调用不同 Server 提供的能力，减少每个 Agent 都为每个外部服务重复编写认证、适配和错误处理代码的多对多集成成本。它标准化的是能力发现、调用与授权边界，不会自动提升工具本身的质量。

章节介绍 Client、Server 和 Transport 的分工，以及 Tools、Resources、Prompts 等能力的不同控制方和交互形态。Client 与 Server 在初始化时交换能力；本地场景可使用 stdio，远程场景使用 Streamable HTTP。普通 HTTP Adapter 只是远程函数调用模式，不等同于完整 MCP 协议兼容。

原文还强调互操作带来的安全面：工具输出可包含 Prompt Injection，多个低权限工具可组合成数据外传链路，恶意 Server 可能伪装为可信工具。生产环境需要 Server 身份与允许列表、最小权限、输出隔离、响应大小限制、超时、熔断、错误处理和敏感凭据管理。Registry 有助于发现与获取 Server 元数据，但不能替代运行时策略与执行隔离。

## 使用边界

- 本页记录当前章节的协议模型与工程判断；协议版本、传输细节、Registry 状态和生态数据均应以 MCP 官方规范和文档为准。
- Tools、Resources、Prompts 的区别不应被简化为“写 / 读”；应按控制方、发现方式和交互形态理解。
- MCP 统一接口，但不替代工具设计、输入验证、授权、输出安全、成本治理和任务验收。

# AI Agent 架构：第 25 章 安全执行（WASI 沙箱）

- **原文标题：** 第 25 章：安全执行（WASI 沙箱）

- **访问日期：** 2026-08-18
- **资料类型：** 在线书籍章节页

## 来源摘要

本章讨论 Agent 调用代码执行等工具时的执行隔离。原文以 Wasmtime/WASI 为例，采用能力模型：默认不授予文件、网络和环境变量访问，仅显式预打开必要目录，且目录和文件只读。执行前还会验证权限、WASM 模块大小/格式与内存声明；路径使用 canonicalize 和边界检查来防范符号链接与路径逃逸。

原文从 CPU、时间、内存等维度限制不可信代码：Fuel 限制指令配额，Epoch 中断限制执行时间，StoreLimits 限制内存、实例、表和 memory 数量。Fuel 不能处理 I/O 等待，因此需与 Epoch 超时组合。WASM 执行放到阻塞线程，避免阻塞异步运行时。

章节将安全执行组织为输入验证、沙箱执行和输出审核三道防线；建议部署后测试文件系统逃逸、网络访问、无限循环、Fuel 耗尽和内存耗尽等攻击路径。Python 等解释器可以在 WASM 内运行，工具会话需设置过期与数量限制。

## 使用边界

- WASI 以原文所述的 Preview 1 能力边界为例，默认没有网络 API；实际可用能力会随运行时、WASI 版本和配置变化，需在目标环境实测验证。
- 沙箱缩小不可信代码的影响面，不替代输入验证、输出审核、策略授权、依赖供应链校验或多租户数据隔离。
- 资源上限是业务与运行时的共同契约：过小会误杀正常任务，过大则留出滥用空间；解释器运行所需的表、内存和启动资源也应被纳入基线测试。

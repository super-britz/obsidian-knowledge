# Node.js Package Entry Points

- **机构：** Node.js 官方文档
- **URL：** https://nodejs.org/api/packages.html#package-entry-points
- **访问日期：** 2026-08-21
- **资料类型：** 官方运行时文档

## 来源摘要

Node.js 包可以通过 `package.json` 的 `main` 或 `exports` 声明入口。`exports` 可以声明一个或多个公开入口，并阻止使用包名导入未声明的子路径，从而让包作者更明确地定义公共接口。

已有包新增 `exports` 时，原先能够深层导入的路径可能失效，因此这可能是破坏性变更。官方文档也说明这种导出封装不是绝对安全边界：知道文件绝对路径的代码仍可能直接加载内部文件。

## 使用边界

- `exports` 解决的是包解析入口，不会判断导出的能力是否稳定、内聚或符合业务边界。
- 单仓库源码目录若不作为独立包解析，通常还需要 lint、依赖图或构建规则限制深层导入。
- 具体字段能力和工具兼容性会随 Node.js 与构建工具版本变化，落地时应重新核对目标运行环境。

# AI Agent 架构：第 9 章 多轮对话设计

- **原文标题：** 第 9 章：多轮对话设计
- **URL：** https://waylandz.com/ai-agent-book/%E7%AC%AC09%E7%AB%A0-%E5%A4%9A%E8%BD%AE%E5%AF%B9%E8%AF%9D%E8%AE%BE%E8%AE%A1/
- **访问日期：** 2026-08-17
- **资料类型：** 在线书籍章节页

## 来源摘要

本章将上下文工程和记忆架构落到连续对话运行时。原文讨论 Session 的身份、租户、历史、过期时间、成本和元数据；使用本地缓存与 Redis 持久化降低延迟，并在读取与创建时执行租户隔离和防会话劫持检查。历史通过滑动窗口和 Token 预算限制长度。

章节还覆盖在摘要和存储前进行 PII 脱敏、生成可检索的会话标题、以 MMR 降低语义召回的重复度，以及 Redis 依赖故障时使用 Circuit Breaker 和本地降级路径防止超时扩散。常见问题包括 ID 碰撞、UTF-8 截断、遗漏租户检查、PII 覆盖不足、重复召回和标题重复生成。

## 使用边界

- Session 是当前连续交互的归属和生命周期边界，不等同于长期记忆、模型上下文或业务系统的权威事实。
- 缓存提升性能但不应成为唯一事实来源；持久化不可用时的降级必须明确告诉系统哪些一致性和恢复能力被牺牲。
- PII 脱敏应发生在摘要、日志、缓存、检索和持久化之前，并配合访问控制、保留期与删除机制。
- MMR、自动标题、缓存容量和熔断阈值都是具体实现参数，应由实际延迟、错误率、恢复成功率和用户体验数据校准。

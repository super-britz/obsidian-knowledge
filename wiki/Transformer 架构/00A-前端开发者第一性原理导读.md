# 大模型为什么需要这些组件

[[00-索引|← Transformer 索引]]

> [!abstract] 先只记住一件事：大模型读取已有 Token，判断下一个 Token 的可能性，选出一个追加到后面，再重复。Transformer 的组件都在帮助这次预测更准确、更稳定或成本更低。

**读完本页后：** [[04-Tokenization|Tokenization]] → [[09-12-Attention|Attention]] → [[13-15-Transformer Block 与前向传播|完整模型]] → [[16-17-训练、推理与参数更新|训练与推理]]。这是按问题选读的入门建议，不是先修要求；性能与部署内容遇到需要时再查索引。

## 一条消息怎样变成一个新 Token

```text
用户消息 + 系统规则 + 工具结果
→ Chat Template：整理成模型约定的输入格式
→ Tokenization：文字变成 Token ID
→ Embedding + Position：ID 变成带顺序信息的数字表示
→ 多个 Transformer Block
   ├─ Attention：从前文取得当前需要的信息
   ├─ FFN：加工当前 Token 已有的信息
   └─ Residual + Norm：让信息稳定穿过很多层
→ LM Head：为词表中的候选 Token 打分
→ 解码：选择下一个 Token
→ 追加并重复
→ 通过流式响应返回前端
```

每个组件都在解决这条链中的一个问题：文字需要数字表示，顺序需要位置编码，当前 Token 需要读取上下文，多层计算需要残差和归一化维持稳定。

参数保存训练学到的模式，回答则在当前上下文中逐步生成。因此模型不等于数据库、搜索引擎或 JavaScript 解释器；Attention 也不保证精确召回或事实正确。[[附录-解码与采样策略|解码参数]]改变选择 Token 的方式，不保证回答更真实。

## 训练和推理有什么区别

- **训练：** 用正确 Token 对比预测，计算误差并更新参数。
- **推理：** 参数通常保持不变；预测一个 Token，追加到输入，再预测下一个。

因此，[[16-17-训练、推理与参数更新|训练]]改变长期使用的参数，[[28-Prompt 工程|Prompt]]改变当前调用的条件；RAG 提供外部资料，Tool 执行查询或动作。要先辨认缺的是行为、资料还是系统能力，再选择手段。

## 性能优化在解决什么

- **计算与搬运：** [[21-22-Flash Attention 与 KV Cache|Flash Attention 与 KV Cache]]分别减少 Attention 的中间内存搬运、历史重复计算。
- **缓存占用：** [[23-MHA、MQA 与 GQA|MQA / GQA]]通过共享 K/V 减少缓存；[[32-状态空间模型与混合架构|SSM]]压缩历史状态，但可能丢失细节。
- **微调成本：** [[26-27-LoRA、QLoRA 与量化#LoRA 为什么能降低训练成本|LoRA / QLoRA]]减少需要训练的参数状态，仍有基座计算与激活开销。
- **权重占用：** [[26-27-LoRA、QLoRA 与量化#部署量化解决什么|部署量化]]用更少位数保存权重，实际速度与质量仍需测量。

优化名称不等于用户收益。最终仍要测首 Token 延迟、后续生成速度、并发、内存、费用和回答质量。

## 前端开发 AI 应用要关心什么

- **上下文有预算：** 历史消息、文件和工具结果都会占 Token，需要裁剪、摘要或按需检索。
- **流式输出可能不完整：** UI 要处理取消、超时、断线以及不完整的 Markdown 和 JSON。
- **模型输出不可信：** JSON 要校验 Schema，引用要回查来源，工具动作要读取真实回执。
- **随机性属于产品行为：** 记录模型、Prompt 和解码配置，才能复现和比较问题。
- **权限必须在服务端：** 数据访问、金额和写操作不能只依赖 Prompt。
- **延迟要分阶段测量：** 网络、排队、首 Token、后续生成和工具调用不是同一个瓶颈。

你是在用概率模型构建产品，而不是调用一个保证确定返回值的普通函数。

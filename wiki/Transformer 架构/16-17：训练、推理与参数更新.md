# 第 16～17 章：训练为什么会学习，推理为什么不会

> [!abstract] 训练和推理都先让模型计算 logits，区别发生在后面：训练把预测与正确答案比较，用误差修改模型参数；推理不改参数，只从 logits 选出一个 Token，追加后继续预测。Prompt 能改变本次回答，训练才能改变模型以后处理所有请求时使用的参数。

> [!info] 放回完整生成链
> - **训练：** 模型发布前或微调时发生，输入是文本样本和目标 Token，输出是更新后的参数。
> - **推理：** 用户请求到来时发生，输入是当前上下文，输出是连续生成的 Token，参数保持不变。
> - **前端视角：** 改 Prompt 类似改变本次函数调用的参数；训练则改变函数内部长期使用的大量权重。这个类比只描述生命周期，不代表模型是确定性函数。

## 共同起点，两条分支

```text
输入 Token
→ Transformer 前向传播
→ logits

├─ 训练：logits + 正确目标 → Loss → 梯度 → 更新参数
└─ 推理：最后位置 logits → 选 Token → 追加 → 再预测
```

最重要的边界是：

> **前向传播负责计算预测；训练用预测修改参数，推理用预测继续生成。**

因此，用户在聊天中纠正模型，并不会自动把这条知识写进模型参数；除非系统另外保存反馈，并在之后进入训练或知识库流程。

## 训练怎样从文本得到学习信号

训练数据会把文本错开一位：

```text
完整文本：我 喜欢 学习 AI
输入：    我 喜欢 学习
目标：    喜欢 学习 AI
```

模型为每个位置预测下一个 Token，Loss 衡量预测和正确目标的差距。反向传播计算“哪些参数应向什么方向变化”，优化器再执行更新：

```text
前向预测 → 计算 Loss → backward 得到梯度 → optimizer.step 更新参数
```

训练时整段正确前缀已经存在，所以多个位置可以一起计算；因果 Mask 仍然阻止每个位置读取未来内容。也就是说：

```text
计算上可以并行
信息上仍然只能看过去
```

## 推理为什么要逐 Token 进行

推理时未来 Token 尚不存在：

```text
Prompt
→ Token₁
→ Prompt + Token₁
→ Token₂
→ ……
```

后一轮依赖前一轮真正选出的 Token，因此同一条回答无法一次并行生成完。一次前向内部和多个请求之间仍可并行，但一条序列的 Decode 步骤存在先后依赖。

前向传播只输出 logits；Greedy、Temperature、Top-K 和 Top-P 等解码策略负责从中选择 Token。解码策略会改变回答的随机性，不会改变模型参数或补充知识。

## 学习率控制什么

用最简化的公式表示参数更新：

```text
新参数 = 旧参数 - 学习率 × 梯度
```

- **学习率过大：** Loss 可能震荡、发散或出现 NaN。
- **学习率过小：** 更新太慢，在有限训练预算里学不到足够内容。
- **Warmup + Decay：** 常见做法是训练初期逐渐放大步长，后期再逐渐减小。

实际的 AdamW 还维护额外优化状态，学习率也必须结合 Batch、模型规模、数据和训练步数选择；不存在可以复制到所有任务的万能数值。

## 应用开发者真正会遇到什么

| 现象 | 它主要属于哪一层 | 应该怎样处理 |
| --- | --- | --- |
| 模型不知道刚发生的新闻 | 推理上下文缺少事实 | 用检索、数据库或工具提供最新资料 |
| 同一 Prompt 输出略有变化 | 解码存在采样 | 记录模型与参数，关键结果做校验 |
| 想长期改变回答风格或任务能力 | 参数或训练数据问题 | 先评估 Prompt，必要时再微调 |
| 首字迟迟不出现 | Prefill、排队或工具调用 | 分阶段记录延迟，不只看总耗时 |
| 后续字符生成缓慢 | Decode 串行与服务吞吐 | 测 Token/s、并发和 KV Cache |

对前端而言，流式输出正是逐 Token Decode 的产品表现。UI 需要处理取消、不完整 Markdown、断线和错误，而不能假设服务端一次返回完整字符串。

## 实现细节：两个容易混淆的开关

如果直接写 PyTorch 推理代码：

```python
model.eval()                  # 关闭 Dropout 等训练行为
with torch.inference_mode():  # 不记录反向传播所需信息
    logits = model(input_ids)
```

`eval()` 不等于关闭梯度；`inference_mode()` 也不会替你切换所有模块的训练行为。调用 `model(input)` 更不会自动让参数学习。

## 别误解

- **“训练能并行，所以模型能看到未来答案。”** 因果 Mask 仍限制每个位置只能读取过去。
- **“在 Prompt 里告诉模型一个事实，它就永久学会了。”** 这个事实只存在于当前上下文，除非系统另行保存或训练。
- **“温度越低，回答就越正确。”** 它只让采样更集中，无法修复错误知识或证据。
- **“生成慢是因为 GPU 完全不能并行。”** 单次矩阵计算可以并行，串行约束来自每个新 Token 依赖上一个结果。

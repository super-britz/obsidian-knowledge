# 训练与推理：模型什么时候会改变

> [!abstract] 前向传播用当前参数计算预测和损失；反向传播计算每个可训练参数的梯度；优化器根据梯度修改参数。推理只使用参数生成，不会让模型永久学习本次对话。

## 训练的最小闭环

训练的目标是让预测越来越接近正确答案：

```text
前向传播：当前参数会得到什么结果？
反向传播：每个参数对错误影响多大？
优化器：参数接下来怎样修改？
```

三者连续执行并不断重复，模型才会逐渐改变。

## 前向传播：计算结果

数据沿模型从输入流向输出：

```text
输入 Token
→ Embedding
→ Transformer Blocks
→ logits
→ 与正确 Token 比较
→ 损失
```

损失把“预测错了多少”表示成数字。前向传播只计算，不修改参数；训练时还会保存部分中间结果，也就是激活值，供反向传播使用。

## 反向传播：计算梯度

反向传播从损失出发，沿计算链反方向使用链式法则：

```text
损失
→ 输出层的影响
→ 前一层的影响
→ ……
→ 每个可训练参数的梯度
```

梯度表示损失对参数变化的敏感程度，提供调整方向和影响大小。反向传播不是反向生成，也不直接修改参数。

## 优化器：更新参数

优化器结合梯度、学习率和历史状态更新参数：

```text
旧参数 - 学习率 × 梯度 → 新参数
```

新参数进入下一轮前向传播，继续检查损失是否下降。因此完整训练流程是：

```text
前向计算预测和损失
→ 反向计算梯度
→ 优化器更新参数
→ 重复
```

## 训练与推理在哪里分开

```text
前向传播得到 logits
├─ 训练：计算损失 → 反向传播 → 更新参数
└─ 推理：选择 Token → 加入上下文 → 再次前向传播
```

Prompt 改变本次输入，RAG / Tool 提供本次请求所需的外部信息；只有训练或微调会修改以后所有请求共同使用的参数。

## 为什么训练更占显存

训练除了模型权重，还要保存：

```text
激活值 + 梯度 + 优化器状态 + 临时计算空间
```

上下文和 Batch Size 越大，激活值通常越多。推理通常不保存梯度和优化器状态，所以资源需求较低。

使用 LoRA 时，冻结的基座模型仍参与前向计算；反向传播经过整条计算链，但只更新 Adapter。冻结表示“不更新”，不表示“不计算”。

## 别误解

- **“反向传播就是倒着运行模型。”** 它是在反向计算影响和梯度。
- **“反向传播会更新参数。”** 反向传播计算梯度，优化器才更新参数。
- **“冻结参数就不参与计算。”** 冻结参数仍参与前向传播。
- **“告诉模型一次就会永久记住。”** 没有反向传播和参数更新，普通对话不会形成长期学习。
- **“一次前向传播生成整段回答。”** 自回归模型通常要为每个新 Token 再做一次前向计算。

## 一句话复习

> 前向传播负责做题并计算错误，反向传播负责追查参数对错误的影响，优化器负责改参数；推理只用参数，不改参数。

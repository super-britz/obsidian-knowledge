# 训练与推理：模型什么时候会改变

> [!abstract] 训练和推理都会先计算下一个 Token 的候选分数。训练会用正确答案产生误差并修改模型参数；推理只使用已有参数继续生成，不会让模型永久学会本次对话。

## 两者从同一个地方分开

```text
已有 Token
→ Transformer 前向传播
→ 候选 Token 的 logits

训练：与正确 Token 比较 → 产生误差 → 修改参数
推理：选出一个 Token → 追加到后面 → 再预测
```

前向传播只负责“算出候选分数”。训练和生成是接在它后面的两种不同流程。

## 训练怎样学习

训练材料中，后面的正确 Token 已经存在。模型会尝试预测它，再比较预测与答案的差距。

```text
模型预测
→ 与正确答案比较
→ 判断哪些参数应怎样调整
→ 更新参数
→ 下一次预测稍有变化
```

这个过程要在大量文本上反复进行，模型才逐渐学到语言、知识和任务模式。训练不是把句子原样写进数据库，而是调整大量数字权重。

## 推理为什么逐 Token 进行

用户提问时，后面的答案还不存在。模型只能先选出一个 Token，把它加入上下文，再预测下一个：

```text
Prompt
→ 第一个新 Token
→ Prompt + 新 Token
→ 第二个新 Token
→ ……
```

因此，流式输出会逐渐出现；前面的选择也会影响后面的内容。Temperature 等解码设置改变选择方式，但不会修改参数或补充知识。

## Prompt 为什么不等于训练

- **Prompt：** 改变本次推理看到了什么，只在当前上下文中生效。
- **RAG / Tool：** 把外部事实或执行结果带入当前请求。
- **训练 / 微调：** 修改以后所有请求都会使用的模型参数。

用户在聊天中纠正一次错误，模型可以在当前对话里按照纠正继续回答，但不会自动永久记住。系统必须另外保存知识、反馈或训练数据。

## 做项目时记住

1. 最新事实优先放在可更新的知识库、数据库或工具中，不要依赖重新训练。
2. 想长期改变固定行为时，先验证 Prompt 是否足够，再考虑微调。
3. 流式 UI 要处理取消、超时、断线和不完整内容，因为生成是逐 Token 进行的。
4. 模型生成的参数仍需业务规则和权限校验，训练得更“听话”也不等于获得执行权限。

## 别误解

- **“告诉模型一次，它就永久学会了。”** 普通对话不会更新参数。
- **“训练时有完整文本，所以模型可以偷看未来。”** 因果 Mask 仍限制每个位置只能使用已有前文。
- **“温度低就是答案正确。”** 温度只影响候选选择的随机性。
- **“一次前向传播就生成整段回答。”** 一段回答需要多次预测和追加。

## 一句话复习

> 训练用错误修改参数，推理用参数逐 Token 生成；Prompt 改变本次条件，不会自动改变模型本身。

# 微调与量化总览：改变行为还是降低成本

> [!abstract] LoRA / QLoRA 用更少训练资源改变模型的长期行为；量化用更少空间保存和运行模型。两者可以组合，但解决的不是同一个问题。

## 先判断你遇到什么问题

```text
模型长期、重复地不符合任务要求
→ 考虑 LoRA / QLoRA

模型太大，设备装不下或运行成本过高
→ 考虑模型量化
```

- **[[26：LoRA 与 QLoRA|LoRA]]：** 保留原模型，只训练少量附加参数。
- **QLoRA：** 进一步用低比特保存训练时冻结的原模型。
- **[[27：模型量化与 GGUF|量化]]：** 用更少位数保存推理权重，降低文件和内存占用。
- **GGUF：** 一种模型文件格式，不是训练或量化算法。

## 正确的决策顺序

1. 缺少最新事实，先用 RAG 或数据库。
2. 需要确定性计算和动作，使用 Tool。
3. Prompt 无法稳定解决长期行为问题，再评估 LoRA。
4. 部署资源不足时再量化，并重新测试质量和速度。

无论微调还是量化，都会产生一个新模型版本。必须记录基座、Tokenizer、配置和评测结果。

## 别误解

- **“LoRA、4-bit 和 GGUF 是同一种优化。”** 它们分别属于训练、数字表示和文件格式。
- **“微调适合保存新闻和库存。”** 经常变化的事实应放在外部系统。
- **“位数越低一定越快。”** 还取决于硬件和运行时支持。

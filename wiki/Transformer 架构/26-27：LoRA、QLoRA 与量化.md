# LoRA、QLoRA 与量化：改变行为还是降低成本

> [!abstract] LoRA / QLoRA 用更少训练资源改变模型的长期行为；量化用更少空间保存和运行模型。两者可以组合，但解决的不是同一个问题。GGUF 又只是保存模型的一种文件格式。

## 先判断遇到什么问题

```text
模型长期、重复地不符合任务要求
→ 考虑 LoRA / QLoRA

模型太大，设备装不下或运行成本过高
→ 考虑量化
```

缺少最新事实应使用 RAG 或数据库；需要确定性计算和业务动作应使用 Tool。微调和量化都不能代替这些外部系统。

## LoRA 怎样改变模型行为

完整微调要修改整个模型的大量参数。LoRA 会冻结原模型，只在部分位置加入小型 Adapter，并只训练这些附加参数：

```text
冻结原模型
→ 加入小型 Adapter
→ 只训练 Adapter
→ 推理时让两者一起工作
```

Adapter 记录的是对原模型行为的修改，不能脱离对应的基座模型独立运行。

LoRA 适合高频、稳定、可以明确评测的行为，例如固定任务模式或输出要求；不适合保存新闻、库存和政策等持续变化的事实。

## QLoRA 又节省什么

LoRA 虽然只更新 Adapter，训练时仍要加载原模型。QLoRA 会用低比特保存这个被冻结的原模型，进一步降低训练内存。

QLoRA 不是把整个模型进行低比特全参数训练。真正被更新的仍然是 Adapter。

## 量化怎样降低部署成本

模型权重原本用较高精度数字保存。量化会用更少位数近似这些数字，从而减小文件、运行内存和带宽需求。

```text
较高精度权重
→ 转换成较低位数表示
→ 文件更小、内存需求更低
```

近似会产生数值误差。位数越低通常越省资源，但质量风险也可能更高；真实速度还取决于硬件和运行时是否支持对应的低比特计算。

## GGUF 是什么

GGUF 是常用于本地模型的文件格式，可以保存模型权重、数字类型、模型结构和 Tokenizer 等元数据。

GPTQ、AWQ 等属于量化方法；GGUF 是承载量化结果的容器。一个 GGUF 文件可以包含不同程度的量化权重。

## 正确的决策顺序

1. 缺事实先用 RAG，确定性动作先用 Tool。
2. Prompt 无法稳定解决长期行为问题，再评估 LoRA。
3. 部署资源不足时再量化，从较保守的版本开始。
4. 在目标设备比较质量、加载、内存、首 Token 延迟和生成速度。

Adapter、合并后的模型和量化模型都是新的版本，需要记录基座、Tokenizer、配置和评测结果。

## 别误解

- **“LoRA、4-bit 和 GGUF 是同一种优化。”** 它们分别属于训练、数字表示和文件格式。
- **“LoRA 参数少，训练内存也只剩同一比例。”** 原模型计算和中间状态仍然存在。
- **“QLoRA 是低比特全参数训练。”** 低比特基座被冻结，Adapter 才是更新对象。
- **“4-bit 一定比 16-bit 快四倍。”** 存储比例不是速度比例。
- **“模型能加载就可以上线。”** 还需要真实任务和失败回归测试。

## 一句话复习

> LoRA / QLoRA 低成本改变长期行为，量化降低部署资源，GGUF 负责保存模型；三者处在不同层次。

# Prompt 工程：把一次任务交代清楚

> [!abstract] 模型看不到人的真实意图，只能依据当前 Token 继续预测。Prompt 工程把模糊意图整理成明确的任务、资料、边界和输出契约，让通用模型在本次调用中朝正确方向工作。

## 第一性原理：为什么需要 Prompt

同一个模型可以翻译、写代码、分类、总结或调用工具，但模型参数只表示“会什么”，不能自动知道“这一次要做什么”。

```text
模糊输入
→ 存在多个合理任务和输出方向
→ 模型难以稳定选择

补充任务、资料、边界和格式
→ 缩小可能的输出范围
→ 结果更容易控制和验证
```

Prompt 不会让模型凭空获得新能力，而是在当前上下文中调度它已有的能力。

## Prompt 在系统中的位置

```text
用户输入
+ 系统规则
+ RAG 资料
+ Tool 返回结果
+ 输出格式
→ 本次完整上下文
→ 模型生成候选结果
→ 应用验证后展示或执行
```

Prompt 改变当前推理条件，不会修改模型参数。训练决定模型长期“会什么、倾向怎样回答”，Prompt 决定本次“依据什么、完成什么”。

## 为什么叫 Engineering

偶尔聊天可以直接提问；软件系统则要求输出可重复、可解析、可测试和可维护。

因此 Prompt Engineering 不只是润色一句话，还包括：

- 组织系统规则、用户输入和外部资料；
- 定义输出结构与失败行为；
- 隔离不可信内容和高权限工具；
- 收集失败样例并维护版本；
- 比较质量、延迟和 Token 成本。

它更像模型与应用之间的输入契约，而不是寻找某种魔法句式。

## 一个清楚的 Prompt 包含什么

1. **任务：** 要完成什么，成功标准是什么。
2. **资料：** 可以依据哪些事实，哪些内容不可信。
3. **边界：** 哪些内容不能猜，缺少信息时怎么办。
4. **输出：** 需要哪些字段、格式和长度。
5. **验收：** 应用之后怎样判断结果能否使用。

当标签、格式或判断边界特殊时，可以补充少量输入—输出示例。但示例会占用上下文，也可能把错误模式带入结果，因此应由真实失败样例驱动，而不是默认堆叠。

## Prompt 解决不了什么

| 问题           | 应使用的系统层                |      |     |
| ------------ | ---------------------- | ---- | --- |
| 缺少最新文档和事实    | RAG、数据库或搜索             |      |     |
| 缺少订单、库存等实时状态 | Tool / API             |      |     |
| 需要精确计算       | 程序或计算服务                |      |     |
| 需要执行高风险动作    | 服务端权限校验与 Tool          |      |     |
| 长期、重复的行为仍不稳定 | [[26-27：LoRA、QLoRA 与量化 | 微调]] |     |
| 模型部署成本过高     | 量化和推理优化                |      |     |

反复写“请务必准确”不能补充缺失证据，也不能建立真正的权限边界。

## 安全和验证必须在模型外

模型输出是候选结果，不是已经验证的事实或执行指令。应用仍需要：

- 校验字段类型、范围和业务规则；
- 只开放当前任务必要的工具；
- 在敏感操作前验证身份、权限和用户确认；
- 根据真实来源验证引用；
- 根据工具回执判断动作是否成功。

合法 JSON 只代表结构正确，不代表内容真实、合理或已经授权。Prompt 可以表达规则，但真正的安全边界必须由程序执行。

## 怎样持续改进

```text
收集真实失败样例
→ 建立最简单的基线
→ 判断失败来自任务、资料、边界还是格式
→ 每次只修改一个变量
→ 用测试集比较质量、延迟和成本
→ 记录 Prompt 与模型版本
```

没有失败证据时继续增加角色、示例和强调语，通常只会让 Prompt 更长、更难维护。

## 别误解

- **“Prompt 越长越好。”** 无关内容会占用上下文并干扰重点。
- **“存在一个适用于所有任务的最佳 Prompt。”** Prompt 必须与任务、模型和评测共同设计。
- **“模型返回合法 JSON 就可以执行。”** 还需要语义、权限和业务校验。
- **“模型写出推理步骤就证明答案正确。”** 仍然需要验证证据与结果。
- **“Prompt 能完全防住提示注入。”** 权限隔离和输入验证必须由应用负责。

## 一句话复习

> 模型参数决定通用能力，Prompt 为本次调用选择任务和条件；Prompt Engineering 则把这种选择变成可测试、可维护的应用契约。

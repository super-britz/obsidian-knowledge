# 第 28 章：Prompt 工程——为一次推理设计输入契约

> [!abstract] Prompt 工程不是寻找“魔法咒语”，而是为一次模型调用组织任务、证据、约束和输出格式。它改变当前推理的条件，不修改模型参数，也不能代替最新事实、服务端权限和程序验证。

> [!info] 放回 AI 应用架构
> - **位置：** 应用层到模型推理之间，决定模型本次看到什么、需要生成什么。
> - **输入 → 输出：** 任务、上下文和约束 → 一次条件生成。
> - **前端重点：** UI 收集用户意图；私有上下文、密钥、权限、Prompt 组装和工具执行通常放在服务端。

## Prompt 只负责输入条件

```text
用户输入
→ 服务端补充系统规则、可信资料和工具状态
→ Prompt / messages
→ 模型生成候选输出
→ Schema、事实和权限校验
→ 展示或执行
```

模型本质上仍在根据已有 Token 预测后续 Token。Prompt 可以让某种输出更可能出现，却不能：

- 自动获得训练截止之后的事实；
- 获得数据库、文件或支付权限；
- 保证输出真实、合法或执行成功；
- 把一次上下文中的信息永久写入参数。

这些缺口分别需要 RAG、Tool、服务端授权、验证器或微调解决。

## 一个可调试的 Prompt

不必套固定咒语，只需让五类信息足够清楚：

1. **任务：** 要做什么，成功标准是什么。
2. **证据：** 可以依据哪些事实，来源和时间是什么。
3. **边界：** 不得假设什么，信息不足时怎样返回。
4. **输出：** 字段、类型、枚举和长度。
5. **验收：** 程序之后怎样判断结果能否使用。

```text
任务：把工单归入一个现有类别。
证据：工单正文、类别定义、产品版本。
边界：不得创建新类别；证据不足返回 unknown。
输出：{"category": enum, "evidence": [string]}。
验收：Schema 通过，evidence 必须能在输入中定位。
```

“你是资深专家”可以影响表达视角，但不会赋予模型真实资历、最新知识或法律责任。

## Prompt、RAG、Tool 和微调怎么分工

| 手段 | 改变什么 | 适合解决 | 不能替代 |
| --- | --- | --- | --- |
| Prompt / Few-shot | 本次任务条件 | 目标、格式、局部示例 | 最新事实、硬权限 |
| RAG | 本次可见资料 | 私有或变化的知识 | 事实核验本身 |
| Tool / Workflow | 外部查询与动作 | 计算、搜索、写入 | 授权和结果验收 |
| Fine-tuning | 长期参数倾向 | 高频、稳定的行为适配 | 经常变化的事实 |

先判断失败属于哪一层，再选择手段。缺资料时继续加“请认真回答”没有用；需要精确计算时，应调用计算器或代码；需要写操作时，必须由服务端授权并读取真实回执。

## Few-shot 和分步推理什么时候用

- **Zero-shot：** 先作为最低成本基线。
- **Few-shot：** 标签含义特殊、格式陌生或决策边界复杂时，提供少量高质量示例；示例也会占上下文并带来顺序偏差。
- **CoT：** 难题可能受益于分步计算，但更长的自然语言推理不是正确性证明。
- **Self-Consistency：** 多次采样再聚合，增加成本；多数一致不等于事实正确。
- **ToT：** 显式生成、评价和搜索多个分支，适合规划类任务，不适合默认套在每次调用上。

这些方法分别增加中间 Token、采样次数或搜索控制。只有真实评测证明收益时才值得增加复杂度。

## 安全边界必须在模型外

网页、邮件、文档、用户输入和工具结果都属于不可信数据，里面可能包含伪装成指令的内容。Prompt 中写“忽略恶意指令”不能形成安全边界。

服务端至少需要：

- 只向模型暴露当前任务所需的最小权限；
- 对工具参数做类型、范围和业务规则校验；
- 高风险写操作要求确认，并提供审计或回滚；
- 将引用回查到真实来源，将动作状态绑定真实回执；
- 测试越权、注入、缺失证据和异常工具返回。

JSON Schema 只证明结构可解析，不证明内容真实或动作被授权。

## 从失败样例迭代

```text
定义任务指标和失败样例
→ 建立最简单 Prompt 基线
→ 每次只针对一种失败补充证据、示例或步骤
→ 程序校验输出
→ 比较质量、延迟、Token 和安全回归
→ 版本化 Prompt、模型、工具和测试集
```

前端侧应记录用户输入、请求版本、流式状态和可恢复错误；服务端记录最终 Prompt 的安全版本、模型参数、工具结果和验证状态。涉及敏感数据时，日志还要执行脱敏和访问控制。

## 别误解

- **“Prompt 越长越好。”** 无关内容会消耗预算并干扰模型使用真正证据。
- **“合法 JSON 就可以直接执行。”** 结构正确不代表字段真实、合理或有权限。
- **“展示完整推理过程就证明答案可靠。”** 中间文字也可能错误，应验证可检查的证据和结果。
- **“Prompt 能阻止所有注入。”** 权限、参数校验、确认和审计必须由模型外系统实现。

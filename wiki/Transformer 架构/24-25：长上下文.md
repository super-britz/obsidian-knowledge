# 第 24～25 章：长上下文——信息访问、记忆与位置外推

> [!abstract] “支持更长上下文”至少包含三件事：模型能表示更远的位置、Attention / 记忆机制能以可承受成本访问历史、模型经过训练后能可靠利用远处信息。Sparse、Linear、Infini-attention 与 RoPE、ALiBi、YaRN 分别改变不同环节；只扩展其中一环，不等于获得完整、便宜且可靠的长上下文。

> [!info] 阅读粒度
> 本页把第 24 章的访问 / 记忆机制与第 25 章的位置表示合成一条长上下文约束链，因此标为“深入机制”；快速阅读时先看“三份契约”、两张对比表和“做项目时记住”。

## 先拆开长上下文的三份契约

```text
位置契约：位置编号和相对距离能否在目标长度上保持合理？
访问契约：当前 Token 能直接看哪些历史，代价怎样增长？
能力契约：模型是否在训练中学会使用远处信息，并在真实任务上保持质量？
```

配置写着 `context_length = 128k`，最多只能证明系统允许构造这么长的输入。它不能单独证明所有 Token 两两直接连接、显存足够、远处细节可精确回忆，或目标任务质量没有退化。

## 访问与记忆：到底怎样处理旧 Token

| 方法 | 改变什么 | 历史保留方式 | 关键边界 |
| --- | --- | --- | --- |
| Full + Flash Attention | 执行与 IO | 窗口内精确 Dense Attention | 不物化完整分数矩阵，但主要配对计算仍近似二次 |
| Sparse / Sliding Window | 允许的连接图 | 只直接保留窗口、全局或随机边 | 必须有能利用稀疏结构的内核；窗外信息可能丢失或需多层传播 |
| Linear Attention | 相似度函数与计算顺序 | 历史压入递推状态 | 不是标准 Softmax Attention 的等价重排，质量取决于新相似度与训练 |
| Infini-attention | Segment 间记忆 | 当前 Segment 做局部 Attention，旧 Segment 压入固定状态 | 状态相对历史长度有界，但跨 Segment 记忆有压缩损失 |

### Sparse Attention 为什么可能近似线性

Full Attention 为长度 `T` 构造位置对，主要工作随 `T²` 增长。若每个 Query 只连接固定窗口 `w`、少量全局位置 `g` 和随机位置 `r`，边数约为：

```text
O(T × (w + g + r))
```

只有当 `w、g、r` 不随 `T` 同比例增长，而且内核真的跳过未连接区域时，才得到实际收益。在完整 `T×T` 分数矩阵上填 `-∞` 可以得到正确 Mask 结果，却没有省掉已经完成的稠密计算。

Sliding Window 的直接代价低，但窗口外的旧 K/V 会被淘汰；旧信息只能通过较新的隐藏状态间接传播。Longformer 的局部 + 任务全局连接、BigBird 的局部 + 全局 + 随机连接展示了其他稀疏图，但论文中的表达能力与任务结果不能推广为“任意稀疏图都等价于 Full Attention”。

### Linear 与 Infini-attention 为什么不是无损无限历史

Kernel Linear Attention 用特征映射改写 Q/K 相似度，并利用结合律维护递推状态，从而避免显式位置两两配对。它精确实现的是新的 Kernel Attention，不是把带 Softmax 的标准 Attention 简单换括号。

Infini-attention 则把输入分成 Segment：当前 Segment 内保留局部因果 Attention，跨 Segment 历史累积进压缩记忆。固定的是跨 Segment 状态大小，不是总运行时间，也不是所有旧 Token 的逐项存档。“Infinite”表示可以持续处理 Segment 流，不表示任意历史细节都能被无损随机访问。

## 位置表示：怎样描述远近关系

| 方案 | 注入位置 | 核心机制 | 长度边界 |
| --- | --- | --- | --- |
| Sinusoidal | 加到输入表示 | 多频率 sin / cos 表示位置 | 可以计算训练长度外的位置，但可靠外推仍取决于训练与模型 |
| RoPE | 旋转 Q、K | 相对旋转进入 QK 点积 | 原生 RoPE 超出训练分布仍可能退化 |
| ALiBi | 加到 Attention 分数 | 按 Head 对距离施加线性偏置 | 论文展示特定长度外推，不代表无限长度均可靠 |
| Position Interpolation / YaRN | 调整 RoPE 的位置或频率尺度 | 把目标长度映射到更熟悉的旋转范围，并通过训练适配 | 扩展位置范围仍需质量验证，也不降低 Dense Attention 成本 |

### RoPE 为什么表达相对位置

RoPE 把每对 Q/K 维度当作二维平面，并按位置旋转。位置 `m` 的 Q 与位置 `n` 的 K 点积中，旋转关系可化为相对旋转 `n-m`；因此位置信息直接进入 Attention 匹配，而不是先与 Token Embedding 相加。

这并不意味着“采用 RoPE 就能无限外推”。超过训练长度时，模型会遇到未适配的旋转模式；Position Interpolation、YaRN 等方案通过缩放位置 / 频率和继续训练扩展窗口。它们改变位置分布，不会替模型补上缺失的长程训练，也不会减少长 Prefill、KV Cache 或 Decode 带宽。

### ALiBi 为什么能外推，但仍有边界

ALiBi 不增加位置向量，而是在 QK 分数上加入与距离成比例的负偏置，不同 Head 使用不同斜率。规则可以直接应用到更长序列；原论文展示了从 1024 训练长度到 2048 测试长度的外推结果。

但“公式能继续计算”与“任意更长长度质量不变”仍是两回事。线性距离偏置带有偏向近邻的归纳偏置，对需要精确远距依赖的任务是否合适，必须通过目标数据验证。

## 三类失败表现怎样定位

- **位置失败：** 一超过训练长度，困惑度、重复或错位明显恶化；优先核对 Position ID、RoPE Scaling、Cache Position 和训练长度。
- **访问失败：** 目标信息在窗口外或未连接位置时突然不可用；优先检查 Sliding Window、全局 Token、Segment 边界和记忆更新顺序。
- **能力失败：** 系统能接收长输入、资源也够，但模型忽略中段信息或只在简单 Needle 测试成功；说明训练分布、任务能力或信息组织仍不足。
- **资源失败：** 长 Prompt 导致 TTFT、峰值显存或 KV Cache 超预算；需要回到 Flash Attention、GQA / MQA、稀疏内核和服务调度分别定位。

## 做项目时记住

1. **先定义需要哪种“长”。** 是局部流式处理、少量全局锚点、跨 Segment 摘要记忆，还是对任意旧 Token 的精确随机访问？不同需求对应不同结构。
2. **扩窗要同时核对四项。** 模型训练 / 微调长度、位置配置、Attention / Cache 实现和推理服务上限必须一致；只改一个 `max_position_embeddings` 通常不够。
3. **用长度与位置扫描验证。** 在训练窗口内外分别测困惑度或任务质量，把关键信息放在开头、中间、结尾和跨 Segment 边界；同时记录 TTFT、TPOT、吞吐、峰值显存与 Cache 占用。
4. **不要只用单一 Needle 测试。** 再加入多事实组合、长文摘要、远距依赖和真实业务数据；能找到一个随机字符串不等于能理解整份长文档。
5. **应用层仍要管理上下文。** 即使模型支持长窗口，检索、分段、摘要和来源选择仍能降低成本与干扰；动态事实也仍需外部来源验证。

## 别误解

- **“Flash Attention 已把长上下文计算降成线性。”** 它优化精确 Dense Attention 的中间存储与 IO，不消除主要位置配对。
- **“Sparse Mask 自然会更快。”** 稠密计算后再 Mask 不省算力，收益依赖结构化稀疏内核和实际形状。
- **“固定记忆状态等于保存全部历史。”** Linear / Infini 类状态会聚合信息，不能等同于逐 Token 的精确 Cache。
- **“RoPE / ALiBi 能计算更远位置，所以模型一定会正确使用。”** 位置公式、训练分布与任务能力是不同层次。
- **“标称 128k 就表示 128k 内信息同样可靠。”** 有效利用常随位置、任务和干扰变化，必须测量。

## 复习

1. 为什么长上下文必须同时满足位置、访问和能力三份契约？
2. Sparse、Linear、Infini-attention 分别牺牲或改变了什么？
3. RoPE 为什么能把相对位置带入 QK 点积，为什么仍可能在训练窗口外退化？
4. 如果模型能接收 128k，却总忽略中间证据，应怎样区分位置、访问、能力和资源问题？

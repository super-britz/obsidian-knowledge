# LoRA 与 QLoRA：低成本改变模型行为

> [!abstract] 完整微调要修改整个模型的大量参数。LoRA 冻结原模型，只训练一小组附加参数；QLoRA 再把冻结的原模型以更低位数保存，从而进一步减少训练所需内存。

## 为什么需要 LoRA

如果模型在大量重复任务中始终需要很长 Prompt 才能达到稳定格式或行为，可以通过微调改变它的长期倾向。

完整微调会更新整个模型，训练和保存成本很高。LoRA 的做法是：

```text
冻结原模型
→ 在部分位置加入小型 Adapter
→ 只训练 Adapter
→ 推理时让原模型和 Adapter 一起工作
```

Adapter 记录的是对原模型行为的修改，不是一个可以独立运行的完整模型。

## QLoRA 又做了什么

LoRA 虽然只更新 Adapter，训练时仍要加载完整原模型。QLoRA 会用低比特保存这个被冻结的原模型，再训练 Adapter，因此更适合显存有限的设备。

QLoRA 不是把整个模型的所有参数都用低精度重新训练。真正被更新的仍是 Adapter。

## 什么时候适合使用

适合：

- 高频、稳定、可以明确评测的输出行为；
- Prompt 很难稳定表达的领域任务模式；
- 同一个基座需要多个可切换的行为版本。

不适合：

- 新闻、库存和政策等持续变化的事实；
- 严格权限控制和确定性业务动作；
- 少量示例已经能通过 Prompt 解决的问题；
- 没有独立测试集、只能凭感觉评价的任务。

## 使用时要保留什么

Adapter 必须与训练时的基座模型、Tokenizer、Chat Template 和配置匹配。升级基座、合并 Adapter 或再次量化后，都要当作新版本重新测试。

评测至少要比较原模型与微调模型的目标任务效果，同时检查通用能力和安全行为是否退化。

## 别误解

- **“LoRA 参数少，所以训练内存也只剩很小一部分。”** 原模型的计算和中间状态仍然存在。
- **“QLoRA 是低比特全参数训练。”** 低比特基座被冻结，Adapter 才是更新对象。
- **“微调能可靠记住最新事实。”** 它改变行为倾向，不是可更新数据库。

## 一句话复习

> LoRA 通过训练小型 Adapter 改变模型行为；QLoRA 再压缩冻结基座，进一步降低训练门槛。

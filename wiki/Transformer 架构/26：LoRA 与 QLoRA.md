# 第 26 章：LoRA 与 QLoRA——低成本改变模型行为

> [!abstract] 完整微调要更新大量模型参数；LoRA 冻结基座，只训练附加的小型低秩 Adapter。QLoRA 又把冻结基座以低比特保存，进一步降低训练时的权重占用，但实际更新的仍然是较高精度 Adapter。

> [!info] 放回模型生命周期
> LoRA / QLoRA 发生在训练阶段，产物会影响之后所有推理；Prompt 只影响当前请求。它适合稳定、重复、可评测的行为改变，不适合保存经常变化的事实。

## LoRA 怎样减少训练状态

普通微调直接更新大权重 `W`。LoRA 保留 `W₀` 不动，只学习一个较小增量：

```text
实际权重效果 = 冻结基座 W₀ + 小型 Adapter 增量
```

低秩分解让 Adapter 参数远少于原矩阵，因此无需为全部基座参数保存梯度和优化器状态。推理时可以保留独立 Adapter 便于切换，也可以验证后合并进基座。

这不表示总训练显存按“可训练参数比例”同步下降：前向和反向仍会经过基座，激活、临时工作区和长序列开销依然存在。

## QLoRA 又省了什么

```text
低比特冻结基座
→ 前向时按计算精度参与运算
→ 梯度穿过基座计算图
→ 只更新 LoRA Adapter
```

QLoRA 主要进一步压缩冻结基座的存储。它不是让整个模型做 4-bit 全参数训练，也不意味着激活和优化器状态全部变成 4-bit。

## 什么时候值得微调

适合：

- 高频出现且稳定的输出风格或格式；
- Prompt 很难稳定表达的领域任务模式；
- 有足够训练样本和独立评测集；
- 需要在同一基座上管理多个行为版本。

不适合：

- 新闻、库存、政策等持续变化事实；
- 需要严格权限控制的动作；
- 少量示例就能通过 Prompt 稳定解决的问题；
- 无法定义成功标准、只有“感觉更好”的任务。

## Adapter 是一份版本化依赖

Adapter 不是完整模型。加载时必须匹配：

- 基座模型与具体版本；
- Tokenizer 和 Chat Template；
- 注入的目标模块与 Rank 等配置；
- 训练数据、任务说明和评测版本。

合并 Adapter 或再次量化会产生新的数值 Artifact，需要重新做质量和加载测试。

## 最小验证闭环

1. 小数据跑通训练、保存和重载，确认只有预期 Adapter 可训练。
2. 对比基座与微调模型的目标任务质量。
3. 同时检查通用能力、安全、拒答和过拟合回归。
4. 在独立测试集上验收，不用训练 Loss 代替产品效果。

## 别误解

- **“LoRA 参数少，所以训练内存也只剩同一比例。”** 激活和基座前向仍然存在。
- **“QLoRA 是 4-bit 全参数训练。”** 低比特基座被冻结，Adapter 才是更新对象。
- **“微调能让模型可靠记住最新事实。”** 它改变统计行为，不是可查询、可更新的数据库。

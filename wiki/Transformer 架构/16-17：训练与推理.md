# 第 16～17 章：训练与推理

> [!abstract] 训练的目标是更新参数，让模型学会预测下一个 Token；推理的目标是固定参数后生成内容。训练能并行计算一整段已知文本的所有位置，生成却必须等上一个新 Token 选出来后才能继续。

## 先看两条流程

```text
训练：完整文本
→ 输入与目标错开一位
→ 一次前向得到所有位置 logits
→ loss → backward → optimizer.step()
→ 参数更新

推理：Prompt
→ Prefill 处理已有 Prompt
→ 用最后位置 logits 选一个 Token
→ 接回上下文
→ Decode 重复生成
→ 参数不更新
```

训练时给模型的是正确前文，这叫 Teacher Forcing；因果 Mask 仍会禁止当前位置偷看后面的正确答案。

## 关键理解

- **训练能并行，生成有逐 Token 依赖。** 训练样本的所有目标都已知，所以可同时算各位置 loss；生成的下一个 Token 未知，必须先选出来才能成为下一步输入。
- **前向、反向和更新不是同一步。** 前向只产生 logits 和 loss；`backward()` 计算梯度；`optimizer.step()` 才真正修改参数。
- **推理模式不算梯度，也应关闭训练期随机性。** 例如 Dropout 在正常推理时关闭；推理系统可批量处理多个请求，但同一条回答仍需按生成顺序推进。
- **学习率决定每次更新走多大步。** 太大可能震荡、发散或出现 NaN；太小会让训练极慢。它不是“百分比”，也没有脱离 batch、优化器、精度和调度的万能数值。
- **Warmup 和衰减是训练配方的一部分。** 常见做法是先 Warmup、再衰减，但必须和总训练步数、token 预算、优化器配置一起验证，不能只抄某个公开模型的学习率。

## 做项目时记住

1. **分清训练代码和生成代码。** 训练需要目标、loss、梯度和优化器；推理需要解码策略、上下文预算和停止条件。
2. **调学习率先做短跑实验。** 在相同数据、batch 和 token 预算下比较小范围候选，并同时观察 loss、验证指标、gradient norm 与 NaN / Inf。
3. **把推理延迟拆成 Prefill 和 Decode。** Prompt 很长主要增加 Prefill 工作；回答很长主要增加逐 Token Decode 时间。KV Cache 会在后续主题专门解释。

## 别误解

- **“训练时也要一个 Token 一个 Token 地跑完整序列。”** 因果关系仍在，但已知完整文本可以让 GPU 并行计算所有位置。
- **“调用 model 就会让模型学习。”** 没有 loss、反向传播和优化器更新，参数不会改变。
- **“低学习率一定更稳定、更好。”** 过小会浪费训练预算；目标是找到稳定且有效的区间。

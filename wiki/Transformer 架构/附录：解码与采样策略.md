# 解码与采样：模型怎样选出下一个 Token

> [!abstract] 模型只会给候选 Token 打分；解码负责从候选中选出一个。它可以调节稳定性、多样性、重复和长度，但不能补充知识或验证事实。

## 一次选择怎样发生

```text
LM Head 产生 logits
→ 调整候选分布
→ 缩小候选范围
→ 选出一个 Token
→ 追加到已有内容
→ 继续下一轮
```

前端看到文字逐渐出现，就是这个循环不断产生 Token 后再转换成文字。

## Greedy 和 Sampling

- **Greedy：** 每一步都选择当前分数最高的 Token。结果更稳定，但当前最高分不代表整段回答最好或事实正确。
- **Sampling：** 根据候选概率随机选择。输出更多样，但同一输入可能得到不同结果，也可能选中较差候选。
- **Beam Search：** 同时保留多条候选路径再比较，计算更贵，开放式聊天不一定受益。

## Temperature、Top-K 和 Top-P

- **Temperature：** 调整候选概率是更集中还是更分散。低温更稳定，高温更多样。
- **Top-K：** 只在分数最高的固定数量候选中选择。
- **Top-P：** 只保留累计概率达到一定范围的候选，数量会随当前分布变化。

这些参数只改变“怎样选”，不会修复错误上下文、缺失知识或幻觉。调试时一次只改一个参数，才能知道变化来自哪里。

## 生成为什么会停止

生成可能因为以下原因结束：

- 模型生成结束 Token；
- 达到最大输出长度；
- 命中预设停止字符串；
- 用户取消、请求超时或服务出错。

所以流式输出可能停在半句话、不完整 Markdown 或不完整 JSON。应用必须区分正常结束、长度耗尽和异常中止。

## 结构化输出不只是降低温度

需要 JSON 或工具参数时，应优先使用模型服务提供的 Schema 或受约束输出：

```text
模型生成结构化数据
→ 检查 Schema
→ 检查字段含义和业务规则
→ 检查权限
→ 执行工具
→ 读取真实回执
```

Schema 只能保证结构。字段内容仍可能错误、越权或不合理。

## 怎样选择

- 分类、抽取和工具参数：使用较稳定的生成方式，并做 Schema 与业务校验。
- 普通问答和摘要：从服务默认值开始，用真实失败样例调整。
- 文案和创意：可以允许更多随机性，并生成多个候选供选择。
- 数学、代码和业务动作：使用计算器、测试或工具验证，不靠低温证明正确。

## 可复现的边界

固定随机种子有助于重复实验，但模型版本、运行框架和服务环境变化仍可能改变结果。需要逐字固定的文本，应由代码或模板生成，而不是依赖模型每次生成完全一致。

## 别误解

- **“Temperature 为 0 就不会幻觉。”** 它只减少随机性。
- **“Top-P 越小越准确。”** 候选更少不等于事实更真。
- **“Seed 相同就永远得到同样文本。”** 还依赖模型和运行环境。
- **“合法 JSON 可以直接执行。”** 结构、内容、权限和执行结果需要分别验证。

## 一句话复习

> 解码决定怎样从 logits 选出 Token；它影响输出风格和随机性，但事实与动作仍由外部系统验证。

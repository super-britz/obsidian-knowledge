# RLHF 与偏好学习：模型为什么更像助手

> [!abstract] RLHF 把人类对多个回答的比较转化为训练信号，让模型更倾向生成有帮助、符合指令和安全规范的回答。它改变的是回答倾向，不是真实性保证。

## 第一性原理：为什么需要 RLHF

预训练主要让模型学习：

```text
给定前面的 Token
→ 下一个最可能出现什么
```

但“像训练文本”不等于“适合作为助手”。模型可能继续编故事、回避问题，或者生成流畅但不可靠的回答。

“好回答”的全部规则很难写成精确公式，但人通常更容易判断：

```text
面对同一个问题
回答 A 和回答 B
哪个更好？
```

RLHF 的核心就是把这种相对比较转化为模型可以优化的信号。

## RLHF 怎样工作

典型流程是：

```text
模型生成多个候选回答
→ 人类比较或排序
→ 奖励模型学习这种偏好
→ 奖励模型为新回答评分
→ 强化学习提高高分回答的生成概率
```

人类不直接修改参数，而是提供偏好数据；奖励模型也不是事实判断器，只是对标注规则和评价者偏好的近似。

## 预训练、SFT 和 RLHF 的分工

| 阶段 | 学习信号 | 主要作用 |
|---|---|---|
| 预训练 | 下一个 Token | 学习语言、知识和续写模式 |
| SFT | 问题与目标回答 | 模仿怎样完成指令 |
| RLHF | 多个回答的偏好排序 | 提高更受偏好回答的概率 |

因此可以简化为：

```text
预训练：学会续写
→ SFT：学会回答
→ RLHF：学习哪种回答更受偏好
→ 质量与安全评测
```

RLHF、DPO、RLAIF 都属于偏好学习相关方法，但训练流程不同：典型 RLHF 使用人类偏好、奖励模型和强化学习；DPO 直接利用成对偏好训练策略；RLAIF 则主要使用 AI 反馈。

## 它在系统中的位置

偏好学习通常发生在模型发布前，会修改以后所有请求共同使用的参数。用户在聊天中点一次“踩”或纠正一次回答，不会立即改变模型；反馈需要经过收集、筛选和训练流程。

```text
Prompt：改变本次调用条件
RLHF：长期改变回答倾向
RAG / Tool：提供外部事实或执行结果
```

## 为什么更受偏好不等于更正确

评价者只能在给定候选中比较，两个回答可能都错；流畅、更长或更自信的回答也可能取得表面优势。

偏好训练可能让模型：

- 更愿意遵循指令，也可能过度迎合；
- 表达更流畅，但事实仍然错误；
- 更重视安全，也可能过度拒绝；
- 奖励分数提高，但真实任务质量下降。

因此 RLHF 不能替代事实来源、权限控制和独立评测。

## 做项目时记住

1. 不同模型规模相近，回答风格和拒答边界也可能不同。
2. 使用真实任务和失败样例选模型，不只看公开排行榜。
3. 模型升级后重新测试事实、格式、拒答和工具使用。
4. 模型更听话不代表可以获得更多工具权限。

## 别误解

- **“RLHF 让模型代表全人类价值。”** 它学习的是特定数据、评价者和规范中的偏好。
- **“奖励更高就表示事实更真。”** 奖励只是目标的近似代理。
- **“用户反馈会立即写进模型。”** 普通对话不会直接更新参数。
- **“对齐后的模型不需要外部校验。”** 事实与动作仍需验证。

## 一句话复习

> 预训练让模型会续写，SFT 让模型学会回答，RLHF 让更受人类偏好的回答更常出现；它优化行为概率，但不保证事实正确。

# 第 29 章：RLHF 与偏好学习——从行为示范到偏好代理

> [!abstract] RLHF 不是把“人类价值”直接写进模型，而是把标注规范转成示范和相对偏好，再通过显式奖励模型或隐式奖励目标更新策略。它能让模型在目标分布上更符合所收集的偏好，但结果始终受标注者、候选回答、代理目标和评测覆盖范围约束。

> [!info] 阅读粒度
> 本页把 SFT、偏好数据、奖励模型、PPO、DPO、RLAIF 和上线评测串成同一条代理目标链，因此标为“深入机制”；快速阅读时先看完整流程、RLHF / DPO 对照和失败诊断。

## “对齐”首先要说明对齐谁、对齐什么

预训练优化下一个 Token 的似然，训练语料中的续写模式不等于产品需要的助手行为。后训练由此尝试提高指令遵循、有用性、安全性和诚实表达，但“人类偏好”不是一个无冲突的统一标签：用户、标注员、开发者、政策制定者和受影响群体可能有不同目标。

Helpful、Honest、Harmless（HHH）可以作为通用助手的评测维度，但三者会冲突。例如，回答越详尽可能越有帮助，也可能泄露危险细节；拒答可以降低风险，也可能造成过度拒绝。工程上必须把抽象价值写成明确标注规范、场景边界和可复现评测，而不能把“已做 RLHF”等同于“已经价值对齐”。

## RLHF 的完整代理目标链

```text
预训练模型
→ 人类示范数据 → SFT 策略
→ 当前策略生成候选回答
→ 标注员按规范排序或比较
→ 奖励模型拟合相对偏好
→ Policy 生成回答，Reward Model 打分
→ PPO 在奖励、KL 与更新幅度约束下优化
→ 独立的人类、能力与安全评测
```

每一箭头都在压缩信息：规范压缩价值判断，成对标签压缩标注理由，标量奖励再压缩多维质量，策略优化最终只看到代理信号。因此评测不能只看训练奖励。

### SFT：先学目标行为的示范

SFT 对 `(prompt, target response)` 做标准语言模型训练。它不只教“问答格式”，还模仿答案内容、拒绝边界、语气和任务策略。适合存在可写出高质量目标答案的场景，但单个示范只能告诉模型“怎样回答”，无法直接表达两个都合理的回答谁更好。

SFT 数据量不是越多越好：错误答案、相互冲突的规范、模板化措辞和不真实的任务分布会直接进入行为。应保存数据来源、规范版本、领域和质量审查结果，并以独立测试集比较基座与 SFT 模型。

### 偏好数据：把“更好”写成相对比较

对同一 Prompt 生成多个候选，让标注员根据 Rubric 选择 `chosen` 和 `rejected`。相对比较通常比为开放回答打绝对分更容易，但标签代表的是：**这批标注员在这个界面、这份规范和这组候选中更偏好哪个**。

候选策略决定标注员能看到什么；两个候选都错时，`chosen` 只是较不差。长度、排版、自信语气和引用外观也可能成为捷径。需要随机化呈现顺序、允许平局或“两者都差”、记录分歧，并按领域、语言、风险和输入来源切分数据与评测。

## 奖励模型与 PPO 分别做什么

### Reward Model：拟合比较，不测量绝对真理

奖励模型对 `(x, y)` 输出标量 `r(x,y)`。常见 Bradley–Terry 形式把回答 `y_w` 胜过 `y_l` 的概率写成：

```text
P(y_w ≻ y_l | x) = sigmoid(r(x,y_w) - r(x,y_l))
L_RM = -log P(y_w ≻ y_l | x)
```

训练约束的是同一 Prompt 下的分数差；分数的绝对零点没有独立意义，也不是校准后的正确率。模型可能学习长度、套话等与标注偏好相关的捷径，并在新领域或新策略生成的回答上失效。

### PPO：在线采样后优化受约束策略

在语言模型 RLHF 中，Policy 逐 Token 生成回答，Reward Model 通常在序列末给出奖励，Value Model 估计回报以降低策略梯度方差。参考策略的 KL 惩罚限制模型远离 SFT 分布；PPO 的概率比裁剪则限制同一批数据上的更新幅度。两者用途相关但不是同一个约束。

```text
优化信号 ≈ 偏好代理奖励 - β × 与参考策略的偏离
```

KL 能缓解漂移，却不能证明奖励正确。若优化压力持续增加，策略可能找到奖励模型盲点：代理分数上升，而人类评价、真实性或通用能力下降。这是 Reward Hacking / Reward Overoptimization，应通过独立评测、奖励与真实指标的联合曲线、KL / 长度监控和早停识别。

## DPO：把隐式奖励折进成对分类损失

DPO 使用同样的 `(x, y_w, y_l)` 偏好对，但不单独训练奖励模型，也不在训练循环中让当前策略在线生成并由 RM 打分。它比较策略相对参考策略对 chosen / rejected 的概率提升：

```text
Δθ  = log πθ(y_w|x) - log πθ(y_l|x)
Δref = log πref(y_w|x) - log πref(y_l|x)
L_DPO = -log sigmoid(β × (Δθ - Δref))
```

直觉是：相对参考模型，提高 chosen 的相对概率、降低 rejected 的相对概率。DPO 将 KL 正则化奖励优化和 Bradley–Terry 偏好模型中的隐式奖励参数化为策略对数概率比，所以“省去 RM”是计算流程简化，不是取消奖励假设。

| 维度 | 显式 RM + PPO | DPO |
| --- | --- | --- |
| 数据循环 | 当前 Policy 在线采样，可迭代收集新偏好 | 通常在固定偏好对上离线训练 |
| 训练组件 | Policy、Reference、Reward、Value 等 | Policy、Reference 或预计算参考 Log-prob |
| 优点 | 可利用可调用奖励做在线探索；RM 可单独审计 | 流程接近监督训练，稳定且易复现 |
| 主要风险 | 训练复杂、昂贵、奖励过度优化 | 数据覆盖固定、偏好噪声和分布外行为难修正 |
| 适合 | 有在线生成和可靠奖励基础设施 | 已有高质量成对数据、希望先建立简单基线 |

不存在脱离数据和任务的固定胜负，也不能把某论文的成本比例当通用结论。DPO 的 `β`、序列 Log-prob 聚合、长度归一化、参考模型和 Chat Template 都会影响结果，必须记录为训练 Artifact 契约。

## RLAIF 与 Constitutional AI 改变了监督来源

RLAIF 让另一个模型产生偏好或评价；Constitutional AI 先依据一组人写定的原则生成批评与修订，再用 AI 偏好构建训练信号。它可以扩大覆盖、降低逐条人工标注成本，并让原则更显式。

但价值选择没有消失，而是进入宪法文本、评审模型和 Prompt。评审模型可能复制自身偏差、偏爱特定文风，或无法判断超出其能力的事实。仍需要人类定义原则、审计分歧、评估高风险切片并承担部署决策。

## 失败表现怎样定位到训练链路

| 可观察问题 | 常见来源 | 优先检查 |
| --- | --- | --- |
| 回答流畅但事实错误 | 偏好更重风格，缺少事实核验 | 正确性数据、工具 / RAG、证据支持率 |
| 越训练越长、套话越多 | 标注或 RM 存在长度 / 风格捷径 | 长度分层胜率、去格式对照、RM 探针 |
| 安全题全部拒绝 | Rubric 或负样例过宽 | 合法相邻请求、过度拒绝率、细粒度边界 |
| 迎合用户错误前提 | 标注偏好“同意”而非诚实纠正 | 反迎合测试、不确定性与反事实题 |
| 训练 Reward 上升，人评下降 | Reward Overoptimization / 分布漂移 | 独立人评曲线、KL、早停、更新 RM |
| 通用能力退化 | 更新过强或数据过窄 | 基座能力回归、参考约束、数据混合 |

## 工程决策与验收

1. **先定义行为契约：** 谁的偏好、适用哪些场景、冲突目标如何裁决；把“更好”拆为正确、有用、安全、简洁等维度。
2. **按监督信息选方法：** 有可靠目标答案先做 SFT；只有相对优劣且数据固定时先做 DPO；需要当前策略在线探索、且能维护奖励与 RL 基础设施时再考虑 PPO。
3. **隔离数据角色：** 训练、验证、最终人评按 Prompt 和来源去重；测试集覆盖正常、边界、对抗、少数语言和高风险领域。
4. **不拿代理验收代理：** 不能只用训练 RM 评价其优化后的 Policy。采用盲化、随机顺序的人类成对评测，并加入事实核验、能力基准、安全与过度拒绝测试。
5. **版本化整个契约：** 基座与 SFT 检查点、Tokenizer / Chat Template、数据和 Rubric、标注群体、Reference、超参数及评测集必须可追溯。

硬权限、隐私规则、金额上限和事实计算仍应由系统、工具和程序验证执行。偏好训练改变统计行为倾向，不是访问控制器，也不能替代 [[28：Prompt 工程|推理时输入契约]] 和外部校验。

## 别误解

- **“RLHF 把全人类价值教给了模型。”** 它学习的是特定规范、标注群体、候选和分布下的偏好代理。
- **“SFT 只负责教问答格式。”** SFT 同时模仿内容、策略、风格和拒绝模式，是后续偏好优化的行为起点。
- **“奖励高等于回答真实。”** 奖励是代理分数；过度优化可能提高分数却降低真实质量。
- **“KL 惩罚能阻止 Reward Hacking。”** KL 只约束与参考策略的距离，无法修复错误奖励或遗漏场景。
- **“DPO 完全没有奖励模型。”** 它不训练显式 RM，但损失仍基于隐式奖励和偏好模型假设。
- **“AI 反馈消除了人的价值判断。”** 人仍决定原则、评审模型、评测标准和部署边界。

## 复习

1. 从标注规范到最终策略，RLHF 经过了哪些信息压缩层？
2. 为什么奖励模型分数不是回答正确率或绝对质量？
3. PPO 裁剪与参考策略 KL 分别约束什么？
4. DPO 省掉了哪些训练组件，又保留了哪些假设和依赖？
5. 为什么不能用训练奖励模型单独验收优化后的策略？

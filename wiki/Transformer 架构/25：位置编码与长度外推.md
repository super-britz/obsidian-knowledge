# 第 25 章：位置编码与长度外推

> [!abstract] 位置编码让模型区分先后和距离；长度外推则问：模型在较短序列上训练后，能否继续处理更远的位置。公式能为更大位置算出数字，不等于模型已经学会在那个范围稳定工作。

> [!info] 放回完整生成链
> 位置信号在 Embedding 之后或 Attention 的 Q/K 匹配中加入。它解决“Token 在哪里”，不解决“历史怎样低成本保存”或“模型是否学会使用远处信息”。

## 常见方案在改变什么

| 方案 | 位置信号加在哪里 | 先记住什么 |
| --- | --- | --- |
| Sinusoidal | 与输入表示相加 | 用多组周期函数区分位置 |
| RoPE | 旋转 Attention 的 Q、K | 让相对距离进入匹配分数 |
| ALiBi | 给 Attention 分数增加距离偏置 | 用固定规则惩罚更远位置 |
| Position Interpolation / YaRN | 调整 RoPE 的位置或频率尺度 | 把更长位置映射到模型较熟悉的范围 |

现代 LLM 常见 RoPE，但具体模型可能使用其他方案。应用开发者无需手算旋转矩阵，只需知道位置配置必须与模型权重和 KV Cache 一致。

## 为什么能计算不等于能外推

假设模型只在 8k 长度内训练。即使位置公式能继续算到 32k，模型仍会遇到训练中没有充分见过的距离模式。

长度扩展通常同时需要：

```text
位置缩放或新位置方案
+ 对应长度的继续训练 / 微调
+ 推理实现与 Cache Position 配置
+ 长度外质量评测
```

只修改 `max_position_embeddings`，可能让输入通过 shape 检查，却无法保证质量。

## RoPE 与 ALiBi 的直觉

- **RoPE：** 同一个 Token 在不同位置会使用不同旋转角度；Q 与 K 的点积因此包含相对距离信息。超过熟悉范围后，旋转模式可能退化。
- **ALiBi：** 距离越远，匹配分数受到越大惩罚。规则能应用到更长位置，但偏向近邻，也不保证任意远距任务都适合。

两者都是位置信号，不会减少 Dense Attention 的计算、KV Cache 或长 Prompt 费用。

## 项目中怎样验证

把同一条关键证据分别放在输入的开头、中间和结尾，并逐步增加总长度。观察：

- 是否开始出现重复、错位或忽略中段；
- 精确引用和多事实组合是否同时稳定；
- Cached 与 Uncached 生成是否一致；
- TTFT、TPOT 和费用是否仍可接受。

如果只有长度外位置失败，检查 Position ID、RoPE Scaling、Cache Position 和训练长度；如果窗口内也找不到证据，则可能是信息组织或模型能力问题。

## 别误解

- **“RoPE 天生支持无限长度。”** 它提供相对位置机制，不提供无限训练能力。
- **“ALiBi 能外推，所以任意长度质量不变。”** 论文实验范围不能推广成无限保证。
- **“扩展位置后，长上下文成本也下降。”** 位置表示和 Attention / Cache 成本是两条不同问题线。

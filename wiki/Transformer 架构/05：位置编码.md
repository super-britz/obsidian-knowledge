# 位置编码：模型怎么知道 Token 的先后顺序

> [!abstract] Embedding 告诉模型“这是什么 Token”，位置编码补充“它排在第几位”。两者合在一起，模型才有机会区分“我爱你”和“你爱我”。

> [!info] 放回完整生成链
> - **位置：** Token 变成向量之后，或在 Attention 计算 Q、K 时注入。
> - **输入 → 输出：** Token 表示与位置 → 带顺序关系的表示或匹配分数。
> - **为什么需要：** Attention 可以同时读取多个位置，却不会天然知道谁先谁后；没有位置信号，词序变化很难被可靠区分。

## 先看流程

```text
Token 的 Embedding：内容是什么
+
位置向量：它排在哪里
=
带有内容和顺序信息的输入
→ 后面的 Attention 再利用前后和距离理解句子
```

两个相同 Token 的初始 Embedding 相同。加入不同的位置信号后，模型才能区分它们处在句子的什么地方。不同模型加入位置信号的具体方式不同，第一次理解不需要掌握计算细节。

## 关键理解

- **Transformer 不会天然知道顺序。** 它不像 RNN 那样按顺序传递状态，所以需要主动加入位置信号。
- **位置信号可以在不同阶段加入。** 有些模型在输入表示中加入位置，有些模型在 Attention 匹配时加入。
- **位置编码只提供线索，不独自理解语义。** 后面的 Attention 和网络层还要结合内容、先后和距离，才能理解语法与指代。
- **能标记更远位置，不等于能理解更长文本。** 模型还需要相应训练，并在真实长文本任务中验证。

## 做项目时记住

1. **上下文不是无序文件夹。** 系统规则、当前任务、可靠资料和工具结果的排列会影响模型怎样使用它们。
2. **关键内容要有清晰层次。** 用标题、字段和短摘要让模型更容易找到当前目标，而不是用一大段混杂文本。
3. **多步 Agent 要按阶段重建上下文。** 不要无限追加历史；每个阶段重新选择真正需要的信息。

## 别误解

- **“Token 本身就带顺序。”** Token ID 只说明是什么片段，不说明它在第几位。
- **“位置编码本身懂语法。”** 它只标记位置，语义关系要由后续网络学习。
- **“支持长窗口就不必检索和摘要。”** 长上下文仍会受预算、模型训练和信息组织质量限制。

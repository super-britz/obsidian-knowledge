# 第 9～12 章：Attention（注意力机制）——从匹配分数到信息混合

> [!abstract] Attention 让每个 Token 根据当前需要，从允许查看的其他 Token 中取回相关信息。它不是单一步骤，而是一条完整链：生成 Q/K/V → 打匹配分 → 变成权重 → 混合信息 → 多头合并成新的上下文表示。

## 先看流程

```text
当前隐藏状态 X
→ XWQ、XWK、XWV：生成 Q、K、V
→ QKᵀ：每个位置给其他位置打匹配分
→ ÷ √dk + Mask + Softmax：得到注意力权重 P
→ P × V：按权重混合信息
→ 多个 Head 的结果拼接
→ WO：合并成新的 Token 表示
```

输出不是“最终答案”，而是每个 Token 结合上下文后得到的新隐藏状态；它还会继续经过残差、FFN 和后续 Block。

## 关键理解

- **Q、K、V 是同一输入 X 的三种可学习投影。** Q 可以理解为“我现在要找什么”，K 是“我可被怎样匹配”，V 是“匹配后实际提供什么信息”。它们不是固定词典标签，而是训练出来的向量视角。
- **QKᵀ 负责匹配，P×V 负责取回。** 前者产生所有位置对的分数；Softmax 后的权重决定每个位置从哪些 V 中拿多少信息。
- **Mask 决定允许看什么。** GPT 的因果 Mask 禁止当前位置看未来 Token，保证它只能根据前文预测下一个 Token。
- **多头不是多个 Agent。** 同一层会并行使用多组较小的 Q/K/V 投影，让不同 Head 学习不同类型的关系；结果拼接后再经 WO 合并。
- **Q、K、V、权重和输出都是本次输入临时算出的值。** 真正长期保存、训练时被更新的是词嵌入和 WQ/WK/WV/WO 等参数。

## 做项目时记住

1. **上下文工程是在给 Attention 提供可用信息。** 系统规则、当前任务、检索片段和工具结果要相关、清晰、有顺序；无关内容会挤占预算并干扰匹配。
2. **Attention 不能替代事实来源。** 模型只能混合已给出的上下文或参数中已有的模式；动态事实仍需检索、数据库和 API。
3. **不要把注意力热力图当成完整解释。** 高权重只说明某层某头在本次计算中的信息路由，不等于唯一因果理由或事实证据。

## 别误解

- **“Q、K、V 是三份原始文本。”** 它们是同一隐藏状态经过不同权重矩阵得到的数值表示。
- **“多头就是多个独立智能体讨论。”** 它们是同一层内并行的矩阵计算，最后会合并为一个表示。
- **“Attention 输出会直接改写模型知识。”** 前向计算只产生临时隐藏状态；训练时必须经过损失、反向传播和优化器，参数才会改变。

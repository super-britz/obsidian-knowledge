# Attention：当前 Token 怎样读取前文

> [!abstract] Attention 的作用是让当前 Token 从前文取得相关信息。它先判断“哪些 Token 与当前需要有关”，再把这些 Token 携带的信息汇总回来。

> [!info] 放回完整生成链
> Attention 位于每个 Transformer Block 内。它不会直接输出文字，只会更新每个 Token 的数字表示；更新后的表示还要继续经过 FFN 和后续 Block。

## 为什么需要 Attention

Token 刚进入模型时，主要表示自身。可是一个词在句子中的含义经常依赖前文。

例如模型已经读到：

```text
小明把牛奶放进冰箱，因为它需要……
```

为了继续生成，模型需要把“它”与前面的“牛奶”联系起来，并利用“冰箱”等信息判断后面更可能出现“冷藏”。Attention 就负责建立这种上下文联系。

可以先记成：

```text
当前 Token 提出需要
→ 在可见的 Token 中寻找相关信息
→ 汇总回来
→ 更新当前 Token 的表示
```

## 它怎样找到并取回信息

同一个 Token 的当前表示会被转换成三个不同用途的版本：

- **Q（Query）：** 当前想找什么。
- **K（Key）：** 自己可以怎样被匹配。
- **V（Value）：** 匹配后实际提供什么信息。

模型会用当前 Token 的 Q 与其他 Token 的 K 比较。越相关，得到的关注份额越大；然后再按照这些份额汇总对应的 V。

```text
Q 与 K 比较：决定关注谁
→ 把分数变成关注份额
→ 按份额汇总 V：取得信息
```

Q、K、V 不是三份文本，也不是人工定义的标签。它们是同一个 Token 表示经过不同权重重新组合后得到的临时数字，具体参见 [[08：线性变换|线性变换]]。

## 为什么不能看到后面的 Token

GPT 要根据已有内容预测下一个 Token。训练时，完整答案虽然已经存在，但当前位置不能偷看未来，否则模型只会抄答案，实际生成时却做不到。

因此，因果 Mask 会遮住当前位置之后的 Token：

```text
当前位置：可以看自己和前文
当前位置：不能看未来
```

Mask 决定“允许看哪里”，Attention 再决定“允许范围内重点看哪里”。

## 多头 Attention 是什么

一组 Attention 只有一套寻找和汇总方式。Multi-Head Attention 会并行运行多组 Q、K、V，再把结果合并。

不同 Head 有机会学习不同的关系，例如近邻联系、指代或句法关系，但这些职责不是程序员预先指定的，也不能保证每个 Head 都能对应一种容易命名的规则。

它们只是同一层中的多组并行计算，不是多个模型，也不是多个 Agent。

## 关键边界

- **Attention 读取的是模型内部的数字表示，不是在原文中执行关键词搜索。**
- **高相关不等于事实正确。** 上下文缺失、冲突或过长时，模型仍可能取错信息。
- **Attention 产生的是本次推理的临时状态。** 普通聊天不会因此修改模型参数。
- **Attention 只负责跨 Token 取得信息。** 取得信息后怎样继续加工，主要由 [[07：FFN|FFN]] 完成。

## 做项目时记住

1. Prompt、RAG 片段和工具结果，是在给 Attention 提供可以读取的上下文。
2. 相关信息不应只“塞进去”，还要避免无关内容、冲突内容和过长输入干扰读取。
3. Attention 不能替代数据库、检索和事实校验；重要结论仍要回查来源。
4. 注意力热力图只能展示某层某个 Head 的关注分配，不能单独证明模型为何得出结论。

## 一句话复习

> Attention 用 Q 和 K 判断该关注谁，再汇总对应的 V；因果 Mask 保证只能读取已有内容，多头让模型并行学习多种读取方式。

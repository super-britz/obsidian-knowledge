# Transformer Block：各组件怎样组成完整模型

> [!abstract] Transformer Block 是大模型反复处理 Token 的基本单元：Attention 从前文取得信息，FFN 加工当前信息，残差保留已有信息，Norm 让多层计算保持稳定。多个 Block 处理完成后，LM Head 才给下一个 Token 的候选项打分。

## 它在完整生成链中的位置

文字不会直接进入 Transformer Block。完整过程是：

```text
文字
→ Tokenization：变成 Token ID
→ Embedding + 位置信息：变成带顺序的数字表示
→ 多个 Transformer Block：反复读取和加工信息
→ LM Head：给词表中的候选 Token 打分
→ 解码：选出下一个 Token
```

Transformer Block 是模型主体，但它不会直接输出文字。

## 一个 Block 做什么

为了方便理解，可以只跟踪当前 Token 的表示：

```text
当前表示
→ Attention：从自己和前文取得相关信息
→ 残差连接：把取得的信息加回原表示
→ FFN：继续加工当前 Token 的信息
→ 残差连接：把加工结果加回
→ 得到更新后的表示
```

Norm 会在这些计算附近调整数字尺度，避免表示经过很多层后越来越不稳定。不同模型放置 Norm 的具体位置可能不同，第一次理解不需要区分。

## 为什么要重复很多个 Block

一次 Attention 和 FFN 只能完成一轮信息读取与加工。模型会堆叠很多个 Block，让 Token 的表示逐层变化：

```text
较初步的 Token 表示
→ 读取一次上下文并加工
→ 再读取、再加工
→ ……
→ 形成适合预测下一个 Token 的表示
```

每层结构相似，但通常拥有各自训练得到的权重，因此不是把同一套规则机械重复很多次。

## 残差连接为什么重要

Attention 和 FFN 不会把原表示完全推倒重来，而是计算一份修改，再加回原表示。

```text
原来的信息 + 本层学到的修改 = 新的表示
```

这样做让已有信息拥有一条继续向后传递的通道，也让很深的模型更容易训练。残差连接只能帮助保留和传递信息，并不保证任何信息永远不会丢失。

## 最后怎样选出下一个 Token

经过所有 Block 后，每个位置仍然只是一组内部数字。LM Head 会把最后位置的表示转换成整个词表的候选分数，也就是 logits。

```text
最后位置的表示
→ LM Head
→ 每个候选 Token 的 logits
→ 解码
→ 下一个 Token
```

logits 只是模型对候选项的相对偏好，不是事实正确率。Temperature、Top-P 等解码设置决定怎样从候选项中选择，但也不能验证事实，具体参见 [[附录：解码与采样策略|解码与采样策略]]。

## 前向传播、训练和生成不是一回事

- **前向传播：** 输入已有 Token，计算候选 logits。
- **训练：** 将预测与正确 Token 比较，再根据误差调整模型权重。
- **生成：** 从 logits 中选出一个 Token，追加到已有内容，然后再次前向传播。

因此，一次前向传播只完成“算分”；一段回答需要重复“算分 → 选择 → 追加”。具体参见 [[16-17：训练、推理与参数更新|训练、推理与参数更新]]。

## 关键理解

- **Attention 不是完整的 Transformer。** Block 还需要 FFN、残差和 Norm。
- **Block 更新的是数字表示。** 它不会直接生成文字或执行工具。
- **层数代表多轮加工。** 但层数更多不等于回答一定正确。
- **模型最后给出的是候选分数。** 事实、权限和外部操作仍需应用系统校验。

## 一句话复习

> 每个 Transformer Block 都让 Token 读取一次前文、加工一次自身信息，并把修改加回原表示；多层处理后，LM Head 才为下一个 Token 打分。

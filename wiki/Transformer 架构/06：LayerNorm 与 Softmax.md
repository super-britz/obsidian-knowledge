# LayerNorm（Layer Normalization，层归一化）与 Softmax：怎样让数字稳定、让模型做选择

> [!abstract] LayerNorm 像模型内部的“标尺”，让中间数字保持较稳定的尺度；Softmax 像“概率转换器”，把候选分数变成总和为 1 的概率，帮助模型选择下一步。

## 先看流程

```text
中间数字
→ LayerNorm / RMSNorm：把尺度拉稳

候选 Token 的分数（logits）
→ Softmax：高分变高概率，全部概率加起来等于 1
→ 取最大值或按概率采样
```

两者都处理数字，但一个负责“数字别失控”，一个负责“候选怎么选”。

## 关键理解

- **LayerNorm 处理内部尺度。** 它对一个 Token 的特征维度做标准化，再允许模型用可学习参数调整范围；现代 LLM 常用目的相近的 RMSNorm。
- **Softmax 处理候选分数。** logits 可以是任意正负数；Softmax 将它们转成正的概率，且总和为 1。
- **Softmax 出现在两个常见位置。** Attention 用它把“该关注谁”的分数变成权重；输出采样用它把下一个 Token 的分数变成概率。
- **温度缩放 logits，改变 Softmax 后的解码分布。** 低温让分布更集中，高温让分布更平坦；在正温度下通常不改变 Greedy 的 argmax，但会改变随机采样概率。它不修改模型参数、补充知识或修复错误事实。

## 做项目时记住

1. **把温度当作解码分布控制，不当作正确性开关。** 抽取、工具参数和结构化输出可使用更确定的解码；创意任务可允许更多随机性。
2. **生成和验证要分开。** 模型产生答案或参数后，仍由 Schema、数据库、API、规则、测试或用户确认判断能否执行。
3. **记录解码参数。** 发生异常时，应能回放模型、温度、top-p、Prompt 版本和工具结果。

## 别误解

- **“Softmax 概率是现实正确率。”** 它只表示模型在当前上下文中的相对偏好。
- **“温度越低，答案越准确。”** 低温通常更少样，但无法解决幻觉、错误检索和权限问题。
- **“LayerNorm 会让模型自动变聪明。”** 它帮助数值稳定，不能替代数据、训练、检索或工程验证。

## 复习

2. 为什么温度调低不能保证模型不说错话？
3. Agent 执行写操作时，为什么不能只因模型“高概率选择了参数”就直接执行？

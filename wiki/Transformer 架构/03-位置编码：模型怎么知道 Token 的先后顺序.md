# 位置编码：模型怎么知道 Token 的先后顺序

> [!abstract] 先用一句话说清楚
> Token 的初始向量只告诉模型“这是什么片段”，却没有告诉它“这个片段排在第几位”。位置编码就是额外加上的顺序标记：把“内容是什么”和“它在哪里”合在一起，模型才有机会区分“我爱你”和“你爱我”。

## 它要解决什么问题？

假设一句话里出现两个相同的 Token，例如：

```text
“我喜欢我自己”
```

两个“我”查 Embedding 表时，拿到的起点向量相同。只看这些起点向量，模型不知道第一个“我”是主语，第二个“我”是宾语。

```text
文字
→ Token ID
→ 每个 Token 的起点向量（知道“是什么”）
→ 加入位置编码（知道“排在哪里”）
→ Transformer 处理内容、顺序和距离
```

Transformer 原生没有像 RNN 那样“从左到右一步一步传递隐藏状态”的结构。因此，顺序不能靠架构自动带进来，需要主动提供给模型。

## 它怎么工作？

### 先看最短流程

```text
Token 的 Embedding：告诉模型“这是什么”
+
位置向量：告诉模型“它在第几位”
=
带有内容和顺序信息的输入向量
```

后面的 Attention 看到的不是单纯的 Token Embedding，而是这份已经带有位置信号的输入。

### 再一步一步看

1. **先得到 Token 的起点向量**

   例如，两个“我”对应同一个 Token ID，所以它们查表得到的初始 Embedding 相同。这一步只能表达 Token 本身的基础特征。

2. **为每个位置生成一个位置向量**

   原始 Transformer 使用正弦和余弦函数（sin / cos）生成位置向量。你现在不需要背公式，只要记住：

   - 每个位置会得到不同的数字组合；
   - 有些维度变化快，像秒针；有些维度变化慢，像时针；
   - 多组快慢不同的波组合起来，让每个位置拥有可区分的“位置指纹”。

3. **把两组向量直接相加**

   Token Embedding 和位置向量的长度相同，所以可以逐项相加：

   ```text
   “我”的内容向量
   +
   第 1 个位置的向量
   =
   第 1 个“我”的输入向量

   “我”的内容向量
   +
   第 4 个位置的向量
   =
   第 4 个“我”的输入向量
   ```

   这样，即使两个 Token 本身相同，进入 Transformer 的数字表示也不同。

4. **后面的 Attention 再利用顺序和距离**

   位置编码本身不会直接告诉模型“这句话的意思”。它只是把顺序信号放进输入；后续 Attention 和多层网络才能结合“谁在谁前面、相隔多远、内容是什么”，形成上下文相关的理解。

## 它有什么限制？

- **位置编码只提供顺序信号，不负责理解语义。**
  “我爱你”和“你爱我”的差别，不是位置编码单独完成的，而是后续网络利用位置和内容共同计算出来的。

- **正弦位置编码只是其中一种方案。**
  原始 Transformer 使用固定的 sin / cos；有些模型使用可学习的位置向量，许多现代 LLM 使用 RoPE、ALiBi 等不同方案。不要把“位置编码”直接等同于“sin / cos”。

- **能算出更远的位置，不代表模型一定能处理更长文本。**
  正弦公式可以为任意位置生成向量，但模型能否在训练长度之外稳定理解长文本，还取决于训练、架构和具体配置。

- **顺序仍会消耗有限上下文。**
  位置编码没有让模型拥有无限记忆；长上下文仍受 Token 预算、计算和模型能力限制。

## 你会在产品或代码中看到什么？

- 同样的词换了顺序，模型回答可能明显不同，因为它看到的输入位置变了。
- System Prompt、用户要求、检索资料和工具结果的排列顺序会影响模型更容易注意到什么。
- 把关键约束放在长上下文的某个角落，不能保证模型每次都同样重视它；信息的顺序和组织方式本身就是 Prompt 设计的一部分。
- 不同模型的长上下文表现可能差异很大，即使它们都宣传支持相同的 Token 数量。

## 做项目时该怎么办？

### 适合做的事

- 把 Prompt 组织成稳定顺序：先放任务目标和安全规则，再放用户问题、可靠资料和必要历史。
- 对检索结果保留来源、段落顺序和标题，让模型不仅拿到孤立片段，也知道它们来自哪里、彼此怎样关联。
- 在长任务中把“当前目标、已完成事项、下一步”明确写成结构化状态，而不是希望模型从很长的聊天记录中自己找出来。

### 不能只靠“把资料放进去”的地方

- 不能把上下文当成一个无序文件夹：同样的内容，排列方式不同，模型的使用效果可能不同。
- 不能因为模型支持长窗口，就把关键规则只写一次后永不检查；重要约束需要在合适的任务边界再次明确。
- 不能把长上下文能力当成替代检索、摘要和任务分解的万能方案。

### 写 Agent 时先控制什么

1. **固定上下文层次。** 例如：系统安全规则 → 当前任务 → 已确认事实 → 工具结果摘要 → 可选历史。
2. **让关键内容容易被找到。** 用标题、字段、列表和短摘要代替大段混杂文本。
3. **按任务重建上下文。** 每走到新阶段，就重新选择真正需要的信息，而不是无限追加旧消息。

## 容易误解的地方

- **误解：Token 有顺序，所以模型天然知道顺序。**
  - 更好理解的说法：Token ID 只表示“这是什么片段”；如果不额外提供位置信号，同一批 Token 的不同排列无法从初始表示中直接区分。

- **误解：位置编码本身理解了语法。**
  - 更好理解的说法：它只标记位置；语法、指代和长距离关系要由后续 Attention 和网络层结合内容来学习。

- **误解：正弦位置编码能计算任意位置，所以模型可以无限读长文。**
  - 更好理解的说法：能生成位置向量不等于模型在训练范围外仍能稳定理解；长上下文还取决于模型的训练和实现。

## 来源、我的理解与待继续学习

### 来源中明确讲到的内容

- 第 5 章指出，Token Embedding 本身不包含出现位置；Transformer 需要额外的位置信息来区分相同 Token 的不同排列。
- 原始 Transformer 使用 sin / cos 生成不同频率的位置向量，并将位置向量与 Embedding 相加后送入 Transformer Block。
- 章节说明，正弦位置编码的数值范围稳定，公式可计算更远的位置；同时区分了固定正弦编码与可学习的位置编码。

### 这里做出的整理和工程推论

- Prompt、检索资料和工具结果不仅要“放进去”，还需要按任务优先级和阅读顺序组织。
- Agent 应按当前阶段重建上下文，避免把长历史当作无序堆积物。

### 后面还要继续学习的问题

- LayerNorm 为什么能帮助多层网络保持数值稳定？
- Softmax 怎样把一组分数变成概率？
- Attention 怎样真正使用内容和位置信号选择重点？

## 最后只记住这五句话

1. **Embedding 告诉模型“是什么”，位置编码告诉模型“排在哪里”。**
2. **相同 Token 出现在不同位置时，加上不同位置向量后，模型看到的输入就不同。**
3. **位置编码不是语义理解本身；它给后续 Attention 提供顺序和距离线索。**
4. **正弦位置编码只是方案之一，现代模型可能使用不同的位置机制。**
5. **做 LLM / Agent 时，上下文顺序很重要：关键规则、当前目标和可靠资料要有清晰层次。**

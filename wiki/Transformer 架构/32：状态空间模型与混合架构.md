# 状态空间模型与混合架构：压缩历史还是直接读取

> [!abstract] Attention 保留每个历史 Token 的 K/V，方便直接读取具体位置；状态空间模型把历史持续压缩进固定状态，换取更稳定的长序列成本。混合架构同时使用两者。

> [!tip] 可以跳过吗？
> 普通聊天和 API 应用可以跳过。本页只需要记住“保存原始位置”和“压缩成状态”之间的取舍。

## 两种保存历史的方式

```text
Attention：逐 Token 保存历史
           → 当前 Token 可以直接匹配具体位置

状态空间模型：旧状态 + 新 Token
             → 更新固定大小的状态
             → 从状态产生输出
```

Attention 更容易找回某个具体位置，但历史越长，KV Cache 越大。固定状态不会随历史一直增长，但早期细节可能在不断压缩中丢失。

## Mamba 改进了什么

传统状态空间模型使用较固定的历史更新方式。Mamba 会根据当前输入决定哪些信息更值得写入、保留或读出，因此能更有选择地压缩历史。

它仍然无法保证把无限历史无损保存在固定状态中，也不等于 Attention。

## 为什么会有混合架构

两种机制各有优势：

- 状态空间层适合低成本地持续处理长序列；
- Attention 层适合按内容直接找回具体历史位置。

混合架构会使用两类层，希望在效率和精确访问之间折中。代价是系统同时要维护状态和部分 KV Cache，实现与部署更复杂。

## 什么时候需要关心

- 必须频繁引用任意早期原文：优先 Attention、检索或保留较多 Attention 的混合模型。
- 持续处理长数据流，并且历史可以压缩：可以评估状态空间模型。
- 调用托管模型：直接比较真实质量、延迟和成本，不根据架构名称预判效果。

## 别误解

- **“固定状态能无损记住无限历史。”** 固定空间只能保存压缩结果。
- **“Mamba 就是更快的 Attention。”** 两者保存和访问历史的方式不同。
- **“长序列更省成本，所以所有任务都更快。”** 真实速度还受实现、硬件和输入长度影响。
- **“混合架构自动拥有全部优点。”** 它也会叠加两套状态和运行复杂度。

## 一句话复习

> Attention 用不断增长的历史存储换精确访问；状态空间模型用固定状态压缩历史换稳定成本；混合架构在两者之间折中。

# 认知工作流：从问题澄清到行动验证

## 一、12 种方法速查

先看自己卡在哪里，再选择对应方法：

| 当前缺口 | 主要方法 | 它执行的认知操作 | 应得到的产物 |
| --- | --- | --- | --- |
| 问题大、模糊或反复纠结 | 苏格拉底提问法 | 追问目标、依据、损失和改变条件 | 一个更准确、带背景和约束的问题 |
| 概念听懂但不会用 | 双层解释法 | 用直觉建立入口，再用机制修正类比 | 直觉模型、运行机制与适用边界 |
| 看到好结果但不会复用 | 反向拆解 | 从结果反推结构、选择、前提和取舍 | 可迁移的生成规则与最低完成标准 |
| 研究对象缺少全貌 | 纵横分析法 | 沿时间解释演化，与同类按相同维度比较 | 演化因果、差异条件与当前位置 |
| 不确定一个说法是否可信 | 事实核查 | 拆开事实、推论和价值判断，检查证据链 | 被证据支持的范围、缺口和置信边界 |
| 问题涉及多种目标或利益 | 专家会诊 | 用不同目标函数观察并互相质疑 | 共识、分歧、冲突条件与风险 |
| 惯例限制了方案 | 第一性原理 | 分开目标、事实、假设和现实约束 | 从必要条件重新推导出的方案 |
| 现有领域没有好办法 | 跨领域借解 | 抽象问题结构，迁移其他领域的机制 | 可迁移机制、失配点与适配方式 |
| 两个方案都看似合理 | 双向钢人论证 | 把双方论证到最强，再找决定变量 | 条件化选择与仍需获取的信息 |
| 分析已无法减少不确定性 | 最小实验 | 用低成本、可退出行动验证关键假设 | 真实反馈、判定标准与下一步决策 |
| 不清楚自己擅长什么 | 挖掘隐藏天赋 | 从长期行为、能量和外部反馈找重复模式 | 待验证的个人能力假设 |
| 不知道未来走哪条路 | 人生设计术 | 生成多个合理未来并分别做原型 | 多个未来假设及其验证实验 |

速查表只负责找到入口；真正使用时，还需要按照第三节的最小协议执行，并检查是否得到预期产物。

## 二、方法分组与分类边界

| 阶段 | 要解决的问题 | 可用方法 |
| --- | --- | --- |
| 澄清问题 | 真正要回答的是什么 | 苏格拉底提问法 |
| 建立理解 | 概念怎样运行，优秀结果怎样生成 | 双层解释法、反向拆解 |
| 研究与判断 | 对象怎样演化，主张是否可信，多方目标怎样冲突 | 纵横分析法、事实核查、专家会诊 |
| 重新求解 | 怎样摆脱惯例，怎样从其他领域迁移机制 | 第一性原理、跨领域借解 |
| 决策与行动 | 什么条件决定选项，怎样取得现实数据 | 双向钢人论证、最小实验 |
| 个人发展应用 | 我可能擅长什么，可以尝试哪些未来 | 挖掘隐藏天赋、人生设计术 |

这些方法不是一条必须从头执行到尾的固定流水线。通常只选择一个主方法，再按需要增加一两个辅助方法。例如事实核查可以保护第一性原理使用的前提，双向钢人论证可以找出最小实验需要验证的决定变量。

> [!note] 分类边界
> 这 12 个名称沿用来源对话中的整理，是便于选择和复用的工作分类，不是公认的统一学术体系。其中前 10 项是通用认知操作，挖掘隐藏天赋和人生设计术是同一套“提出假设 → 行动验证 → 更新认识”机制在个人发展中的应用。

## 三、12 种方法的最小执行协议

| 方法 | 最小执行步骤 | 完成标志 |
| --- | --- | --- |
| 苏格拉底提问法 | 原始问题 → 真实目标 → 判断依据 → 隐含假设 → 改变条件 → 重写问题 | 新问题包含背景、目标、约束和关键未知 |
| 双层解释法 | 直觉类比 → 运行机制 → 适用边界 → 类比失效点 → 实际例子 | 既能用朴素语言解释，也能说明机制和不适用情况 |
| 反向拆解 | 观察结果 → 找支撑结构 → 识别关键选择 → 还原前提与取舍 → 提取最低复现规则 | 得到的是可迁移规则，而不是对表面特征的模仿 |
| 纵横分析法 | 确定范围 → 追踪起点与转折 → 找变化驱动力 → 按相同维度比较同类 → 给出条件化判断 | 能解释它为何演化至今，以及优势在什么条件下成立 |
| 事实核查 | 拆分主张 → 区分事实、推论和价值判断 → 核对来源与时效 → 检查推导 → 限定结论范围 | 每个关键结论都有证据等级、适用范围和未知项 |
| 专家会诊 | 定义各视角的目标与约束 → 独立判断 → 交叉质疑 → 提取共识、分歧和条件 → 交给负责人决策 | 不同视角代表真实目标冲突，而不是只更换说话语气 |
| 第一性原理 | 明确真正目标 → 区分事实、假设和约束 → 移除非必要惯例 → 从必要条件重新推导 → 比较代价 | 新方案能说明依赖哪些事实，以及付出什么成本 |
| 跨领域借解 | 抽象当前问题结构 → 寻找结构相似领域 → 提取已验证机制 → 比较相同与失配处 → 适配并验证 | 迁移的是机制，并明确类比在哪里不成立 |
| 双向钢人论证 | 建立 A 的最强论证 → 建立 B 的最强论证 → 找决定变量 → 写出各自成立条件 → 补充缺失信息 | 得到“条件 X 选 A、条件 Y 选 B”，而不是泛泛的各有优缺点 |
| 最小实验 | 锁定关键假设 → 设计最低成本行动 → 规定指标和阈值 → 限制时间与成本 → 根据结果触发后续决策 | 实验结果能够支持、反驳或更新一个真实决策 |
| 挖掘隐藏天赋 | 收集长期经历 → 标记行为、能量和外部反馈 → 寻找重复模式 → 形成能力假设 → 在真实任务中验证 | 产出待验证的个人能力模型，而不是固定性格标签 |
| 人生设计术 | 生成多个合理未来 → 写明各自假设与代价 → 为每个未来设计小型原型 → 收集体验与反馈 → 更新选择 | 不预测唯一未来，而是用行动提高对不同未来的认识 |

## 四、怎么把方法变成能力

> 提示词不是答案模板，而是认知操作：先判断当前缺少哪一种思考，再让人和 AI 按明确步骤产出可检查的中间结果。

12 个提示词不需要逐个背诵，也不应该在每个问题上全部运行。它们共同组成一个闭环：

```text
澄清问题
  → 建立模型
  → 核查证据与补足视角
  → 生成并比较方案
  → 用行动取得新证据
  → 更新对问题和自己的认识
```

AI 可以帮助追问、拆解、比较和综合，但目标、现实约束、价值取舍与最终责任仍属于人；事实是否成立，最终还要由来源、测试和现实反馈确认。

### 为什么只收藏提示词还不够

方法名称只标记“可以进行哪种思考”，不会自动告诉我们什么时候使用、按什么步骤执行，以及怎样判断结果可靠。可复用能力来自三个动作：

```text
识别当前的认知故障
→ 选择成本最低的认知操作
→ 规定可验证的输出
```

## 五、几组容易混淆的方法

### 苏格拉底提问法与第一性原理

- 苏格拉底提问法诊断：**我真正要解决的是什么？**
- 第一性原理求解：**去掉惯例和未经验证的假设后，应该怎样重新推导？**

问题尚未定义时先追问；问题已经明确，但传统方案陷入路径依赖时再从基本事实重建。

### 双层解释法、反向拆解与纵横分析法

- 双层解释法面向一个**概念**，目标是建立直觉与机制模型。
- 反向拆解面向一个**已有成品**，目标是提取生成规则。
- 纵横分析法面向一个**研究对象**，目标是解释时间演化与同类差异。

### 事实核查、专家会诊与双向钢人论证

- 事实核查判断一个可验证主张有没有足够证据。
- 专家会诊处理多个目标、职责和利益方之间的冲突。
- 双向钢人论证比较两个竞争方案各自在什么条件下最成立。

多角色赞同不能证明事实，多数票也不能代替来源、测试或数据。相关的 Agent 工程边界见[[wiki/AI Agent 架构/12：结构化推导与证据验证|结构化推导与证据验证]]与[[wiki/AI Agent 架构/18：Debate 多视角对抗与综合|Debate 多视角对抗与综合]]。

### 第一性原理与跨领域借解

- 第一性原理从当前问题的目标、事实和约束向前推导。
- 跨领域借解先识别相同的问题结构，再迁移已经被验证的机制。

跨领域迁移必须同时说明“哪里相同、哪里不同、需要怎样适配”，否则类比只能帮助解释，不能支持工程决策。

### 双向钢人论证与最小实验

- 双向钢人论证找出决定选择的变量。
- 最小实验获取这些变量在现实中的数据。

如果再写一轮利弊仍不会改变判断，说明缺少的可能不是更多论证，而是现实反馈。

## 六、最小可复用流程

面对一个新问题，不必依次执行 12 种方法。通常选择一个主方法和一两个辅助方法即可。

### 1. 写清任务契约

先补齐五项：

```text
背景：我为什么遇到这个问题？
目标：最后要理解、判断还是采取行动？
约束：时间、成本、能力、风险和不可触碰条件是什么？
已知：哪些是有依据的事实？
未知：哪项未知最可能改变结论？
```

若目标和未知都说不清，先使用苏格拉底提问法，不急着求解。

### 2. 识别当前故障

只问一句：

> 我现在卡住，是因为问题不清、机制不懂、事实不足、视角单一、选项难比，还是缺少现实反馈？

这个判断决定主方法。不要因为某个提示词听起来高级就优先使用它。

### 3. 规定中间产物

“深入分析”不是可检查的要求。应明确需要什么产物，例如：

- 重写后的问题；
- 事实、假设与约束清单；
- 概念的直觉模型、机制和边界；
- 候选方案的成立条件和退出条件；
- 结论与来源的对应关系；
- 一个有指标、时限和退出机制的实验。

结构化产物的价值是暴露缺口，不是让回答更长。

### 4. 把验证嵌入推导

每个关键结论都追问：

```text
它依赖什么事实或假设？
有什么来源、计算、测试或观察支持？
证据最多能支持到什么范围？
什么反例或条件会推翻它？
```

开放研究可进一步使用[[wiki/AI Agent 架构/27：Deep Research 证据驱动研究|证据驱动研究]]。无法验证的内容应标成假设或价值判断，不能被流畅叙事伪装成事实。

### 5. 用行动闭环

当信息继续增加却不再改变结论时，找出价值最高的未知，并设计最小实验：

```text
关键假设：这次只验证什么？
行动：最低成本怎样接触真实环境？
指标：观察到什么算支持或反驳？
边界：最多投入多少时间和成本？
后续：不同结果分别触发什么决策？
```

实验不是缩小版的大项目。它应该针对最可能改变决策的未知，而不是证明自己原本就相信的方案。

## 七、通用的人机协作提示骨架

下面的骨架用于组织一次思考，不要求逐字复制：

```text
背景：……
我要完成的判断或行动：……
现实约束：……
目前确认的事实及来源：……
目前的假设或担忧：……

请先判断我主要缺少的是问题定义、机制理解、证据、视角、方案比较，
还是现实反馈。选择一个主方法，必要时增加不超过两个辅助方法，并说明选择理由。

输出请包含：
1. 重写后的核心问题；
2. 事实、假设、约束和价值取舍；
3. 当前能成立的条件化结论；
4. 会推翻结论的证据或条件；
5. 成本最低的下一步验证。

不要把角色扮演、多数意见或解释流畅度当作事实证据。
```

这段提示的重点不是措辞，而是建立稳定接口：人提供真实背景、约束和价值取向；AI 执行认知操作并暴露不确定性；外部来源、工具和现实实验提供证据；人负责最终判断和行动。

## 八、两个使用示例

### 技术选型：要不要引入新的状态库

1. 用苏格拉底提问法把“哪个库最好”改写成“当前哪些状态问题无法由现有方案低成本解决”。
2. 用事实核查区分真实故障与对未来复杂度的担忧。
3. 用双向钢人论证比较“维持现状”和“引入状态库”的最强条件，而不是比较宣传功能。
4. 若关键未知是团队能否正确维护，用一个边界明确的页面做最小实验。

这与[[前端架构设计思想]]中的“症状 → 根因 → 最小方案 → 验证”一致：工具应由真实复杂度触发，而不是由模板或流行度触发。

### 个人发展：要不要从前端转向 AI 应用工程

1. 用挖掘隐藏天赋提出个人能力假设，但不把自我描述当结论。
2. 用人生设计术生成“前端能力升级”“AI 全栈”“独立产品”等多个未来，而不是预测唯一未来。
3. 用双向钢人论证找出每条路线成立所需的能力、机会成本和偏好。
4. 用小项目、真实协作或从业者访谈验证关键假设，再更新个人模型。

这里的目标不是一次决定五年，而是让每次行动都增加对未来决策有用的信息。

## 九、检查清单

- 我是在解决真正的问题，还是表面问题？
- 我缺的是概念、证据、视角、选择条件，还是现实反馈？
- 是否只选了必要的主方法，而不是机械运行全部模板？
- 输出是否包含可检查的中间产物？
- 是否把事实、推论、假设和价值判断分开？
- 角色观点、类比和多数意见是否被误当成证据？
- 结论是否写明成立条件、反例和不确定性？
- 下一步行动是否验证最关键的未知，并且结果真的会改变决策？

# 第 2 章：大模型的本质

> [!abstract] 核心问题
> GPT 如何逐个生成 Token？“大模型就是两个文件”应该怎样理解？

## 本章结论

- GPT 通过预测下一个 Token 学习语言规律，并采用自回归方式逐个生成 Token。
- 参数是训练得到的大量数字，分布式地编码语言模式，不是一条条可直接查询的知识。
- 训练负责更新参数，推理负责使用固定参数生成内容。
- 模型本体可以抽象为参数文件与推理代码。

## 知识框架

### 1. GPT 的生成过程

```text
已有上下文
  -> 计算下一个 Token 的概率分布
  -> 选择或采样一个 Token
  -> 追加到上下文
  -> 重复
```

GPT 不是先想好完整答案再输出，而是逐个生成 Token。真实 Token 不一定等于一个汉字或单词，具体切分由 tokenizer 决定。

### 2. 自回归生成

自回归表示根据序列已经出现的内容预测后续内容：

```text
P(下一个 Token | 前面的所有 Token)
```

例如：

```text
中华人民       -> 共
中华人民共     -> 和
中华人民共和   -> 国
```

训练时通常使用真实前文；推理时使用模型自己已经生成的内容，因此前面的错误可能继续影响后文。

### 3. 参数、训练与推理

参数是训练得到的数字，可以理解为模型的“统计记忆”。语言规律分布在大量参数中，不能从某一个参数直接读取某条知识。

| 对比项 | 训练 | 推理 |
| --- | --- | --- |
| 目标 | 根据数据学习参数 | 使用参数生成内容 |
| 参数 | 持续更新 | 通常保持不变 |
| 输入 | 大规模训练数据 | 用户输入和已有上下文 |

```text
训练：数据 -> 预测误差 -> 调整参数 -> 参数文件
推理：输入 + 参数 -> 概率分布 -> 逐个生成 Token
```

### 4. 大模型就是两个文件

| 组成 | 作用 |
| --- | --- |
| 参数文件 | 保存模型训练得到的数字 |
| 推理代码 | 加载参数并执行模型计算 |

这一抽象有助于理解：

- 部署：加载参数并运行推理代码。
- 量化：降低参数的表示精度，减少存储和运行资源。
- 微调：在原有参数基础上继续调整参数。

“两个文件”是对模型本体的简化，不表示生产系统严格只有两个文件。实际系统通常还包含 tokenizer、配置、推理框架和服务代码等。

### 5. 本章辅助概念

- **生成速度**：自回归生成具有顺序依赖，生成 100 个 Token 通常需要 100 个连续解码步骤。
- **KV Cache**：保存已经计算过的 Key 和 Value，减少对历史上下文的重复计算。
- **MoE**：每个 Token 只激活部分专家网络，在较大总参数量下控制实际计算量。
- **训练规模**：本章以 LLaMA-2-70B 说明训练需要大量数据、算力和工程投入；具体成本要区分公开数据与估算值。

## 面试问题与答案

### 1. GPT 是怎样生成回答的？

GPT 根据当前上下文计算下一个 Token 的概率分布，选择或采样一个 Token，将其追加到上下文，然后继续预测，直到生成结束符或达到长度限制。

### 2. 为什么语言模型采用下一个 Token 预测？

完整句子的可能组合非常多。将任务拆成连续的下一个 Token 预测后，每一步只需计算词表上的概率分布，连续执行即可生成完整序列。

### 3. 模型参数是什么？参数中是否保存着一条条知识？

参数是训练得到的大量数字，分布式地编码语言规律和数据模式。它们不是数据库中的事实记录，通常不能从某个单独参数直接读取某条知识。

### 4. 大模型的训练和推理有什么区别？

训练使用大量数据计算误差并更新参数，最终得到参数文件；推理固定已经训练好的参数，根据用户输入进行前向计算并生成 Token。

### 5. 如何理解“大模型就是两个文件”？

这是对模型本体的抽象：参数文件保存训练结果，推理代码定义如何使用参数完成计算。真实生产系统还会包含 tokenizer、配置、服务、安全和监控等组件。

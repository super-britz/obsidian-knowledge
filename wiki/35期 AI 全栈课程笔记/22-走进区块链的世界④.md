# 22 走进区块链的世界④

> [!abstract] 核心问题
> 如何从 Remix 演示过渡到可测试、可验证、可接入前端的合约工程？

## 本节结论

- 合约能部署不代表安全；源码验证、权限检查和异常路径测试只是最低门槛。
- 本地链用于快速开发，测试网用于接近真实网络验证，生产网络需要更严格审批。
- 合约工程应管理源码、部署脚本、测试、网络配置和编译产物。
- 前端必须同时确认网络、合约地址和 ABI，任何一个错配都会产生错误行为。
- 链上数据可以保存在状态中，也可以通过 Event 形成日志；读取方式和成本不同。

## 知识框架

### 1. 先检查资金出口

高风险合约常见特征包括：

- 普通用户可以转入，却没有对应提款路径。
- 管理员拥有无限制转账、铸造或暂停权限。
- 授权目标和额度不透明。
- 源码未验证，代理实现或升级管理员不清楚。

源码公开不等于安全，但无法检查会进一步放大风险。

### 2. 三类开发环境

| 环境 | 主要用途 |
| --- | --- |
| 本地链 | 快速重置、测试账户和自动化调试 |
| 公共测试网 | 验证 RPC、钱包、部署和真实区块确认 |
| 生产网络 | 承载真实资产，需要审计、审批和监控 |

测试私钥也不应进入仓库；生产私钥应由安全系统管理。

### 3. 合约项目的基本组成

```text
contracts/   Solidity 源码
scripts/     部署与管理脚本
test/        合约测试
artifacts/   ABI 与 Bytecode 等编译产物
config       编译器、网络和插件配置
```

Truffle、Hardhat 等工具实现细节不同，但解决的是相似的工程问题。

### 4. 前端调用必须绑定网络

```text
chainId + contractAddress + ABI
  -> Contract Client
  -> read / simulate / write
  -> transaction receipt
```

部署新版本后，应同步更新地址清单和前端配置。

### 5. 状态与 Event 的取舍

状态适合合约后续逻辑必须直接读取的数据；Event 适合记录历史事实并由前端或索引服务查询。日志不能被合约当作普通状态读取，因此不能替代业务状态。

## 实践任务

**建议产出：**

- 将一个 Remix Demo 迁移为本地工程并接入前端。

**完成标准：**

- [ ] 本地链可以重复部署并自动测试。
- [ ] 前端按网络读取正确地址和 ABI。
- [ ] 测试覆盖权限、提款失败和错误输入。
- [ ] 使用 Event 记录操作，并能从日志查询。

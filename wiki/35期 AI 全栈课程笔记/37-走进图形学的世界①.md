# 37 走进图形学的世界①

> [!abstract] 核心问题
> 一个 3D 场景如何从几何数据、材质和光照最终变成屏幕像素？

## 本节结论

- Three.js 是 Web 图形 API 的上层抽象，学习它仍需要理解坐标、渲染管线和 GPU 基本职责。
- 最小 3D 场景由 Scene、Camera、Renderer 和可渲染对象共同组成。
- Mesh 将 Geometry 与 Material 结合，Texture、Light 和 Shader 共同影响最终外观。
- 顶点处理、光栅化和片元处理构成从几何数据到像素的核心过程。
- 模型加载不仅是显示文件，还要处理格式、坐标、缩放、材质、动画、压缩与交互。

## 知识框架

### 1. Web 图形技术的层次

```text
Three.js 等引擎 / 库
  -> WebGL 或 WebGPU API
  -> 浏览器图形实现
  -> GPU
```

Three.js 降低了常见场景开发成本，但复杂效果和性能问题仍会回到底层概念。

### 2. 最小场景结构

```text
Scene
  + Camera
  + Mesh(Geometry + Material)
  + Light
  -> Renderer
  -> Canvas
```

相机决定观察方式，物体变换决定位置、旋转与缩放，渲染器负责把场景绘制到目标表面。

### 3. 从顶点到片元

```text
顶点数据
  -> 顶点着色器
  -> 图元组装
  -> 光栅化
  -> 片元着色器
  -> 深度、混合等测试
  -> 像素
```

顶点着色器主要处理位置和顶点属性；片元着色器计算候选像素的颜色等结果。

### 4. Geometry、Material 与 Texture

- Geometry：顶点、索引、法线、UV 等几何数据。
- Material：表面如何响应光照和渲染规则。
- Texture：颜色、法线、粗糙度等表面数据来源。
- Light：参与部分材质的光照计算。

模型“形状正确”不代表材质、光照和颜色空间已经正确。

### 5. 模型格式进入运行时

GLTF / GLB 常用于传递网格、材质、贴图和动画。加载后应检查：

- 坐标方向、单位和模型原点。
- 缩放、包围盒与相机取景。
- 贴图路径、颜色空间与材质。
- 动画、骨骼和形变数据。
- 文件体积和解码成本。

### 6. 交互依赖空间计算

Raycaster 可将屏幕指针转换为场景射线，与对象求交后实现选择。交互还需处理遮挡、层级、包围体和不同坐标空间的转换。

## 实践任务

**建议产出：**

- 搭建一个可加载并选择 GLB 模型的最小 Three.js 场景。

**完成标准：**

- [ ] 场景包含相机、灯光、网格和渲染循环。
- [ ] 模型缩放、位置与取景正确。
- [ ] 点击能识别具体对象并显示反馈。
- [ ] 窗口变化后画布和相机比例正确更新。

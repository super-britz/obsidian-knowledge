# 09 阶段一 AIGC 实战课需求讲解

> [!abstract] 核心问题
> 如何把“生成一段视频”的想法，拆成可以设计、开发、测试和交付的 AIGC 产品？

## 本节结论

- AIGC 项目的交付对象是完整产品链路，不是一次成功的图片或视频生成。
- 生成链路可以先稳定关键图，再用关键图约束分镜、人物和场景的一致性。
- 用户素材、景点素材、模型输入、生成结果和订单必须分别管理，不能混成一次临时请求。
- 原型可以借助参考图和 AI 快速生成，但组件边界、交互状态和异常流程仍要补齐。
- 肖像、声音、定位、版权、支付和内容审核是需求本身的一部分，不能留到上线前再处理。

## 知识框架

### 1. 从内容生成扩展到产品闭环

```text
登录
  -> 上传头像与声音
  -> 选择或定位景点
  -> 选择模板与素材
  -> 生成关键图
  -> 生成短视频
  -> 预览与审核
  -> 支付 / 下载
  -> 在个人中心查看记录
```

每一步都需要正常态、加载态、失败态、重试规则和数据留存策略。

### 2. 图片到视频的生成链

先生成少量关键图，有助于提前确认人物、服装、景别和场景。随后再把关键图与镜头描述组合成分镜，生成短片并做一致性检查。

影响结果的主要输入包括：

- 人物与场景描述。
- 参考图和素材授权。
- 镜头顺序、时长和运动。
- 正向约束与需要避免的内容。
- 生成失败后的重试与版本记录。

### 3. 产品数据需要分对象管理

| 对象 | 需要保存的核心信息 |
| --- | --- |
| 用户素材 | 所属用户、授权、存储位置、有效期 |
| 景点素材 | 地点、模板、版权和可用范围 |
| 生成任务 | 输入、模型配置、状态、错误和重试次数 |
| 生成结果 | 版本、审核状态、预览和下载地址 |
| 订单 | 商品、金额、支付状态和对应结果 |

### 4. 原型不是最终界面

参考图可以快速建立 H5、官网和个人中心的视觉方向，但正式开发还需补齐响应式布局、表单校验、上传进度、生成等待、支付结果和历史记录等状态。

### 5. 风险约束要进入验收标准

- 用户必须有权使用上传的肖像和声音。
- 素材与生成平台的商业使用条款必须明确。
- 定位只收集完成业务所需的最小信息。
- 支付回调、重复提交和订单状态必须由服务端校验。
- 生成内容需要审核、投诉与删除机制。

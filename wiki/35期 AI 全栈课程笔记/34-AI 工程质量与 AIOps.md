# 34 AI 工程质量与 AIOps

> [!abstract] 核心问题
> 当 AI 加快代码生成后，如何同步建立质量、安全和线上故障处理能力？

## 本节结论

- AI 提高了变更速度，也放大了未经理解的依赖、权限、错误处理和资源问题。
- 生成代码必须进入与人工代码相同的评审、测试、安全扫描和上线流程。
- 系统健壮性来自输入校验、权限、资源限制、降级、监控和恢复能力的组合。
- 性能优化应先减少工作量和影响范围，再考虑更复杂的技术方案。
- AIOps Agent 的价值是连接可观测数据、诊断、通知和工单，不是未经审批自动修改生产系统。

## 知识框架

### 1. 生成速度不能替代工程门槛

每次 AI 变更至少应回答：

- 为什么需要这项改动？
- 修改了哪些信任边界？
- 正常和失败路径如何验证？
- 新增依赖与权限是否必要？
- 上线后如何观察和回滚？

无法解释的代码不应因为“能够运行”就直接合并。

### 2. 健壮性是分层防御

```text
输入层：格式、大小、类型与业务规则校验
权限层：认证、授权与最小权限
执行层：超时、重试、幂等与资源限制
数据层：事务、备份、一致性与恢复
运行层：日志、指标、Trace、告警与降级
```

例如文件上传不仅要看扩展名，还要检查真实类型、大小、内容处理和敏感元数据。

### 3. 性能优化先“变小”

- 减少传输的资源与字段。
- 减少单次查询和渲染的数据范围。
- 拆分长任务与大批处理。
- 使用缓存减少重复计算。
- 使用队列削平突发流量。
- 区分热数据与冷数据。

目标是减少系统必须同时完成的工作，而不是堆叠工具。

### 4. 可观测性提供共同事实

日志描述事件，指标描述趋势，Trace 描述跨服务链路。三者加上版本、部署和用户上下文，才能支持可靠排障。

敏感数据不得直接写入日志，采集范围和保留时间也需要治理。

### 5. AIOps 的最小闭环

```text
错误与指标输入
  -> 聚类和去重
  -> 关联最近变更
  -> 生成根因假设
  -> 提供证据与修复建议
  -> 人工确认
  -> 工单、执行与验证
```

Agent 输出应保留证据、置信度和审计记录；生产操作需要明确审批。

### 6. Workflow 与 Skill 要能复用

可视化流程适合展示编排，Skill 更适合保存稳定的输入、步骤、工具边界和验收标准。选择形式取决于是否可维护、可测试和可追踪。

## 实践任务

**建议产出：**

- 为一个 AI Coding 项目补齐质量门禁与 AIOps 最小闭环。

**完成标准：**

- [ ] AI 变更必须通过测试、评审和安全检查。
- [ ] 上传、权限、外部调用和资源使用有失败测试。
- [ ] 日志、指标和 Trace 能关联到部署版本。
- [ ] Agent 只提出有证据的建议，高风险操作需要审批。

# 32 DEX 与永续合约系统

> [!abstract] 核心问题
> 一个永续合约交易系统由哪些模块协作，前端为什么必须理解其业务状态？

## 本节结论

- 永续合约系统不仅是交易页面，还包含流动性、价格、仓位、风险、清算和结算等模块。
- LP 模型、订单簿模型和混合模型的交易对手方与价格形成方式不同，前端状态不能混用。
- 预言机价格、标记价格和成交价格承担不同职责，风险计算不能只依赖界面最后成交价。
- 杠杆会放大盈亏与清算风险，界面必须清楚展示保证金、风险和状态变化。
- 复杂金融项目的学习重点是系统建模与技术实现，不是交易、返佣或资金操作。

## 知识框架

### 1. 先划分系统边界

```text
市场数据：价格、K 线、盘口、成交
交易服务：下单、撤单、撮合或定价
账户服务：余额、保证金、仓位、盈亏
风险服务：限额、风险率、清算、保险机制
结算服务：费用、资金费率、收益与损失
外部输入：预言机、链上状态、流动性
```

前端是这些状态的交汇处，需要显示来源和更新时间。

### 2. 流动性模型影响交易行为

| 模型 | 交易对手方 | 前端关注点 |
| --- | --- | --- |
| 订单簿 | 其他挂单用户或做市商 | 深度、成交顺序、滑点 |
| LP 池 | 资金池或协议模型 | 池状态、定价、风险敞口 |
| 混合模式 | 多种流动性来源 | 路由、价格差异、失败回退 |

不能把 LP 凭证简单理解为无风险存款，它代表对某种资金池规则的权益和风险。

### 3. 价格具有不同用途

- 成交价格：实际成交发生的价格。
- 指数价格：来自外部市场的参考价格。
- 标记价格：常用于计算未实现盈亏与清算风险。
- 预言机价格：链上或协议使用的外部价格输入。

具体定义取决于系统规则，前端必须与后台或合约保持一致。

### 4. 仓位是一组持续变化的状态

```text
方向 + 数量 + 开仓均价 + 保证金
  -> 未实现盈亏
  -> 风险率
  -> 可用余额
  -> 减仓、平仓或清算状态
```

行情变化、资金费率和用户操作都会改变仓位状态。

### 5. 风控与清算需要可观察

用户界面应展示风险提示，运营后台则需要监控价格源异常、集中仓位、流动性不足、清算失败与系统敞口。风险规则必须在服务端或合约侧执行。

## 实践任务

**建议产出：**

- 绘制一个教学用永续合约系统的模块与状态图。

**完成标准：**

- [ ] 区分行情、交易、账户、风险和结算模块。
- [ ] 说明订单簿与 LP 模型的差异。
- [ ] 前端状态能追溯到明确的数据来源。
- [ ] 使用 Mock 数据，不连接真实资金与交易账户。

## 复习检查

- [ ] LP 池与订单簿的交易对手方有何差异？
- [ ] 为什么清算不能只使用最后成交价判断？
- [ ] 前端需要理解哪些仓位和风险状态？

# 41 大模型微调

> [!abstract] 核心问题
> LoRA、QLoRA 与量化分别改变训练链路的什么部分，什么时候值得微调？

## 本节结论

- 微调适合改变稳定行为、格式、语气或特定任务表现，不适合保存频繁变化的事实。
- LoRA 冻结大部分基座模型参数，只训练附加的低秩适配器。
- QLoRA 在量化加载基座模型的基础上训练 LoRA，以降低训练显存需求。
- 量化减少存储与计算资源，但可能影响质量，必须通过任务评估决定是否可接受。
- 训练效果首先取决于目标、数据和评估设计，不是模型越大、训练越久越好。

## 知识框架

### 1. 先判断是否需要微调

按较低成本到较高成本依次尝试：

```text
改 Prompt
  -> 增加结构化输出与验证
  -> 接入 RAG 或 Tool
  -> 改工作流
  -> 仍有稳定行为问题时再微调
```

知识错误、实时状态错误和接口数据错误通常不是微调问题。

### 2. SFT 定义训练目标

监督式微调使用输入与期望输出样本，让模型学习特定响应行为。SFT 可以全量更新模型，也可以通过 LoRA 等参数高效方法实现。

数据应覆盖典型任务、边界情况、拒答、转人工和错误输入。

### 3. LoRA 的结构

```text
冻结的基座权重 W
  + 可训练的低秩增量 BA
  -> 微调后的等效行为
```

训练产物通常是适配器，推理时需要与兼容的基座模型一起加载，也可以在验证后合并。

### 4. QLoRA 降低基座模型占用

QLoRA 以较低精度加载冻结的基座模型，同时训练 LoRA 参数。它降低了训练门槛，但不会消除激活、优化器、上下文和批大小带来的资源占用。

### 5. 量化是一种质量与资源权衡

降低权重精度可以减少存储和显存，并可能提高吞吐。实际影响取决于模型、量化方案、硬件和任务，不能只依据位数判断好坏。

### 6. 微调评估要有对照

- 保存未微调基线。
- 划分训练、验证和测试数据。
- 检查目标任务是否改善。
- 检查通用能力、拒答和安全是否退化。
- 记录模型、数据、参数和适配器版本。

只看几条主观对话容易误判训练效果。

## 实践任务

**建议产出：**

- 用小规模数据跑通一次 LoRA 或 QLoRA 实验。

**完成标准：**

- [ ] 明确要改变的行为和成功指标。
- [ ] 数据不包含未经授权的隐私或版权内容。
- [ ] 对比基座模型与适配器模型的测试集表现。
- [ ] 保存可复现配置、日志和适配器版本。

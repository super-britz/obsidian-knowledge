# 39 走进图形学的世界③

> [!abstract] 核心问题
> 如何把本地生成、Blender 后处理、GLB 导出和 Web 交互串成完整 3D 资产工作流？

## 本节结论

- 本地 3D 生成受操作系统、GPU、驱动、显存、模型大小和依赖环境共同约束。
- AI 或 MCP 可以辅助操作 Blender，但资产质量仍需通过拓扑、材质、尺度和导出检查验证。
- GLB 是建模工具与 Web 运行时之间的交付物，导出设置应成为可重复流程。
- 简单嵌入、通用交互、工业场景和大规模地理场景需要不同的展示工具。
- 图形学作业的核心不是安装最多工具，而是完成“生成、处理、导出、加载、交互、测量”的闭环。

## 知识框架

### 1. 本地生成先检查运行条件

```text
操作系统与 Linux 环境
  -> GPU 驱动与计算工具链
  -> Python / 模型依赖
  -> 模型文件与缓存空间
  -> 推理服务
```

具体硬件需求由模型决定，不能把课堂中的单一配置当作普遍门槛。

### 2. AI 辅助 Blender 的责任边界

AI 可以执行创建物体、摆放场景、修改材质和调用导出等操作。使用时应限制可访问目录和脚本权限，并在每一步检查场景状态，避免错误操作累积。

### 3. GLB 导出是资产契约

导出前确认：

- 模型单位、坐标方向与原点。
- 是否应用变换。
- 材质、贴图与颜色空间。
- 动画、骨骼和形变是否包含。
- 是否启用压缩以及运行时能否解码。
- 文件名、版本和许可证记录。

前端应通过固定资产清单加载，而不是依赖本地绝对路径。

### 4. 展示工具按需求选择

| 需求 | 可考虑的工具类型 |
| --- | --- |
| 简单查看与旋转 | `<model-viewer>` 一类 Web Component |
| 自定义场景与交互 | Three.js、Babylon.js |
| 地球与地理空间 | Cesium 等地理引擎 |
| 点云或高斯泼溅 | 对应的专用渲染器 |

选择依据是场景规模、交互、格式、团队经验与目标设备。

### 5. Web 加载后的验收

```text
加载 GLB
  -> 检查材质和动画
  -> 调整相机与灯光
  -> 添加选择或操作
  -> 测量下载、解码、内存与帧率
  -> 处理失败与降级
```

模型无法加载时，应能显示进度、错误和替代内容。

## 实践任务

**建议产出：**

- 完成一个从 Blender 到 Web 的可交互 3D 场景。

**完成标准：**

- [ ] 保存可重复的资产处理和导出步骤。
- [ ] GLB 在独立查看器和 Web 项目中都能正确加载。
- [ ] 页面至少包含一次对象选择或动画控制。
- [ ] 记录模型体积、加载时间和运行帧率。

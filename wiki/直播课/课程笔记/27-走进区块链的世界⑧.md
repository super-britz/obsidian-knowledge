# 27 走进区块链的世界⑧

> [!abstract] 核心问题
> 多角色 AI 工作流如何交付 Web3 项目，同时守住钱包、合约和部署权限？

## 本节结论

- Web3 项目需要前端、合约、测试、审查和部署共同完成，单一“写代码 Agent”不足以覆盖全部责任。
- Skill 应沉淀稳定的角色边界、步骤和验收标准，而不是只保存一段临时提示词。
- 钱包自动化涉及扩展状态、账户隔离、签名弹窗和链上交易，测试难度与风险都高于普通页面。
- AI 可以准备部署配置和检查清单，但高权限云资源与生产部署必须设置审批边界。
- 工作流是否有效，应由可运行结果、测试证据和审查记录证明。

## 知识框架

### 1. 按责任拆分角色

| 角色 | 主要职责 |
| --- | --- |
| 前端工程 | 钱包连接、状态展示、交易交互与错误处理 |
| 合约工程 | 状态、权限、支付逻辑与 Event |
| 测试工程 | 正常路径、失败路径和环境隔离 |
| 安全审查 | 授权、重入、输入、密钥和权限检查 |
| 发布工程 | 网络配置、部署、验证、监控与回滚 |

角色可以由人或 AI 承担，但责任不能因自动化而消失。

### 2. Skill 的最小结构

```text
适用条件
  -> 必要输入
  -> 执行步骤
  -> 禁止事项
  -> 验收证据
  -> 失败后的升级路径
```

前端、合约和审查 Skill 应引用同一份需求与接口约定，避免各自生成不同系统。

### 3. 钱包测试需要隔离环境

自动化测试至少要控制：

- 独立浏览器 Profile 和测试钱包。
- 固定测试网络与可重置账户。
- 连接、拒绝、签名、切网和交易失败状态。
- 弹窗与主页面之间的上下文切换。
- 测试结束后的状态清理。

真实钱包、真实私钥和真实资金不应进入自动化测试链路。

### 4. 合约测试与端到端测试互补

合约单元测试验证状态转换与权限；端到端测试验证钱包、前端、RPC 和合约的集成。两者不能互相替代：

```text
合约测试 -> 逻辑正确
前端测试 -> 界面状态正确
端到端测试 -> 整条交易链路可用
人工审查 -> 高风险操作与业务语义可信
```

### 5. 自动部署必须受权限约束

生产部署应明确资源范围、费用上限、审批者、审计日志和回滚方式。AI 或 MCP 获得的权限越大，验证与审批越不能省略。

## 实践任务

**建议产出：**

- 为 Web3 Shop 建立多角色工作流和测试矩阵。

**完成标准：**

- [ ] 前端、合约、测试、安全与发布职责清晰。
- [ ] 钱包测试使用隔离账户和测试网络。
- [ ] approve、购买、拒签和失败路径都有验证。
- [ ] 高权限部署需要人工审批并保留记录。
- [ ] 用流程图和测试结果说明整个交付闭环。

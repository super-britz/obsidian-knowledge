# 17 企业 AIGC 工程提效第二季（补充课）

> [!abstract] 核心问题
> 长时间自动执行的 Agent，怎样记录进度、调用外部系统并避免权限失控？

## 本节结论

- 长任务的进度必须写入可恢复的任务文件，不能只依赖会话记忆。
- Markdown Todo 是简单有效的状态载体，但每项仍需附带完成证据。
- 跳过权限确认会扩大误删、误发和越权风险，应使用隔离环境与命令策略控制。
- CLI、MCP、浏览器协议和 Computer Use 是不同工具通道，应优先选择结构化且可审计的接口。
- 本地或持续运行设备只解决“在哪里执行”，不能替代模型、工具、权限和监控设计。

## 知识框架

### 1. Task 文件保存可恢复进度

```markdown
- [x] 完成接口契约
  - evidence: tests/api-contract.txt
- [ ] 完成浏览器回归
  - blocked_by: 测试账号不可用
```

勾选表示状态，证据和阻塞原因说明为什么处于该状态。

### 2. 工具通道按确定性排序

| 通道 | 优点 | 主要限制 |
| --- | --- | --- |
| API / SDK | 结构化、稳定、易测试 | 需要正式接口 |
| CLI | 可脚本化、易记录 | 参数和环境需严格控制 |
| MCP | 为模型暴露结构化工具 | 依赖服务质量与权限设计 |
| CDP / 浏览器自动化 | 可验证真实网页行为 | 登录态、页面变化和等待问题 |
| Computer Use | 能覆盖缺少接口的应用 | 脆弱、慢且权限范围较大 |

有结构化接口时，不应默认使用模拟点击。

### 3. 危险权限需要多层防护

- 在容器、虚拟机、测试账号或临时目录中运行。
- 限制可读写目录、网络目标和云权限。
- 对删除、发布、转账、发送和部署设置确认。
- 记录命令、结果和执行身份。
- 提供超时、中止和恢复机制。

### 4. 浏览器登录态属于敏感凭据

CDP、浏览器插件或 Computer Use 可能复用现有会话。工作流要区分测试账号与个人账号，禁止把 Cookie、Token 或页面隐私写入日志和模型上下文。

### 5. 执行设备只是运行层

设备选型应根据持续运行、内存、能耗和任务类型决定。本地小模型可以承担有限的离线任务，但复杂工作的质量仍取决于整个系统设计。

## 实践任务

**建议产出：**

- 为现有 AI 工作流补充任务状态和权限策略。

**完成标准：**

- [ ] 每个 Task 有状态、证据和阻塞说明。
- [ ] 外部动作优先使用结构化接口。
- [ ] 高风险命令和目录有拦截规则。
- [ ] 浏览器自动化只使用隔离测试账号。

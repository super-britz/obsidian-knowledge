# 38 走进图形学的世界②

> [!abstract] 核心问题
> AI 生成的 3D 模型如何经过拓扑、材质、压缩和运行时验证，变成可用工程资产？

## 本节结论

- AI 生成模型降低了建模起点，但不能自动保证内部结构、拓扑、材质、动画和性能可用。
- 模型资产进入项目之前，需要经过检查、清理、重拓扑、贴图与导出等后处理。
- 三角网格适合最终渲染，规则四边形拓扑通常更利于编辑、细分和连续形变。
- WebGPU 提供更现代的 GPU 接口和通用计算能力，但选型仍要验证兼容性和真实收益。
- Worker、SharedArrayBuffer 与 Atomics 适合特定并行场景，必须同时考虑隔离策略、同步复杂度和数据复制成本。

## 知识框架

### 1. AI 输出只是模型草稿

检查维度包括：

- 轮廓与比例是否符合目标。
- 是否只有外壳，内部结构是否缺失。
- 网格是否破面、重叠或包含非流形结构。
- UV、贴图、法线和材质是否完整。
- 拓扑是否支持骨骼动画和形变。
- 面数、贴图和文件体积是否适合目标设备。

图片看起来正确，不代表模型可以编辑、动画或实时渲染。

### 2. Blender 承担资产后处理

典型流程：

```text
导入生成模型
  -> 清理网格
  -> 调整拓扑与法线
  -> 修复 UV 和材质
  -> 简化面数
  -> 设置原点、单位与坐标
  -> 导出 GLB / GLTF
```

导出后还需要回到浏览器环境验证，不能只在建模软件中检查。

### 3. 拓扑服务于后续用途

三角形是 GPU 渲染的基础图元；四边形拓扑有利于建模工具中的环线、细分和形变。最终资产可以在导出或渲染阶段三角化，两种表述不应混为“只用其中一种”。

### 4. 模型优化是端到端权衡

- 减面降低传输与顶点处理成本。
- 纹理压缩降低下载和显存压力。
- Draco 等几何压缩减少文件体积，但增加解码成本。
- 分级加载可以优先展示关键模型。
- 包围体和空间索引可以减少交互求交范围。

应在目标设备上同时测量下载、解码、内存和帧率。

### 5. WebGPU 扩展 GPU 使用方式

除了图形渲染，Compute Shader 可以处理适合并行的数据任务。WebGPU 的价值来自更明确的资源与命令模型，但开发复杂度、浏览器支持和团队经验也是成本。

### 6. 浏览器并行能力有不同边界

| 能力 | 适合场景 | 主要限制 |
| --- | --- | --- |
| Web Worker | 独立计算与数据处理 | 不能直接操作 DOM |
| SharedArrayBuffer | 多线程共享内存 | 需要安全隔离配置 |
| Atomics | 共享内存同步 | 容易引入等待与竞态 |
| GPU Compute | 大规模并行计算 | 数据传输与适配成本 |

先确认主线程瓶颈，再选择并行方式。

## 实践任务

**建议产出：**

- 将一个 AI 生成模型处理成可在浏览器交互的 GLB 资产。

**完成标准：**

- [ ] 记录原始模型的拓扑、材质与体积问题。
- [ ] 在 Blender 中完成清理并保留导出设置。
- [ ] 浏览器中验证加载、内存、帧率和点击交互。
- [ ] 对压缩前后进行体积与解码时间对比。

# Tree-of-Thoughts 多路径搜索

> [!abstract] Tree-of-Thoughts（ToT）不是把推导写得更长，而是在**早期选择不确定且会影响全局**时，将候选方案视为可搜索的状态：生成少量分支、用明确标准评估、优先扩展更有希望的分支，并在预算内剪枝、回溯或停止。

## 第一性原理

单一路径的推导会把早期选择当作既定事实。若问题存在多个合理方向，而前序错误会污染后续步骤，继续沿原路径补充论据通常无法纠偏；但穷举所有路径又会使调用次数和延迟随分支数、深度快速增长。

```text
多个候选方向
→ 用可检查的标准比较当前价值
→ 优先扩展高价值候选
→ 剪去低价值、重复或不可行分支
→ 在预算、深度与完成条件约束下选择结果
```

因此，ToT 的本质是**在有限计算预算下分配探索机会**。它降低“过早承诺一条错误路径”的风险，但不能替代对候选的验证。

## 何时值得搜索

同时满足以下条件时才考虑 ToT：

1. **解空间存在真实分歧：** 有多个可行的方案、假设或排查方向，而非只是执行固定步骤。
2. **早期选择影响大：** 一开始选错方向，会令后续工作大多失效，例如架构权衡、复杂故障根因分析或策略设计。
3. **中间状态可评估：** 能用约束、测试、证据覆盖度、模拟结果或清晰量表判断“是否值得继续”。

若已有成熟流程、错误位置明确，或中间优劣无法可靠判断，应优先使用 [[wiki/AI Agent 架构/12：结构化推导与证据验证|结构化推导与验证]] 或直接执行。搜索不是“更聪明”的默认选项。

## 节点、队列与剪枝

一个候选节点至少要有：**当前状态或方案、来源节点、深度、评分、消耗预算、终止状态**。这些字段使系统能回答：这个候选从何而来、为何继续、花了多少、何时结束。

- **生成：** 每次仅扩展少量有差异的候选；重复表达同一路径不应算作新分支。
- **排序：** 可用 Best-First Search，从待探索集合中优先选择当前评分更高的候选，而不是机械地按深度展开。
- **剪枝：** 丢弃低于阈值、违反硬约束、与已知候选重复或无法再推进的分支。
- **回溯：** 当前高分路径在验证后失败或置信不足时，回到仍在队列中的备选，而不是硬把错误路径修补到底。

最坏搜索规模近似随分支数 `b` 与深度 `d` 按 `b^d` 增长；因此深度、分支数和总探索节点数必须共同受限，不能只设置其中一个。

## 评分不是装饰

搜索只能像评分器一样好。评分应优先依赖能区分候选的证据，而非“语言听起来像结论”的表面形式。

| 评分方式 | 优点 | 主要边界 |
| --- | --- | --- |
| 硬约束、测试、检索证据、模拟 | 可复现、可审计 | 只覆盖已形式化的目标 |
| 启发式规则 | 快、成本低 | 容易奖励套话或短期局部最优 |
| LLM 评审或投票 | 能处理复杂语义 | 成本高，也可能继承同类偏见 |

高风险或代价高的分支，应以外部验证作为继续或采纳的门槛。[[wiki/AI Agent 架构/11：结果反思与质量控制|反思]]解决“已有结果怎样评估并修正”，ToT 解决“尚未确定方向时，有限预算该探索哪条路”；两者可以组合，但不能互相替代。

## 预算、终止与失败

ToT 的控制面必须先于扩展逻辑定义：

- **预算：** 限制总节点、每节点 Token、并发和总时长；达到上限时返回当前最优候选及未验证风险，而不是静默无限搜索。
- **终止：** 找到满足验收条件的结果、没有可扩展候选、达到最大深度或预算耗尽时停止。
- **剪枝风险：** 阈值过高会过早丢掉潜在好分支，最终退化成单路径；阈值过低则保留太多噪声，造成分支爆炸。
- **可追溯性：** 记录被采纳和被剪去的关键理由、评分依据、验证结果和预算消耗，便于复盘评分器是否误导了搜索。

## 工程决策

1. 先定义目标与硬约束，再生成候选；没有可评估目标时，不要先建树。
2. 从浅树、小分支、严格预算开始，只有发现早期路径误判确实是主要瓶颈时再扩大搜索。
3. 让候选有意覆盖不同假设或策略，避免多个 Agent 只改写同一个答案。
4. 将“生成候选”“评分”“最终验证”分开；最终选择不能仅因当前分数最高。
5. 对简单任务先走低成本路径；若发现是方向错误而非答案润色问题，再升级到 ToT。

## 常见误解

- **“多生成几次就是 ToT。”** 不是。缺少状态、比较、选择和预算控制的多次生成只是采样。
- **“评分高就是正确。”** 评分只表示在当前指标下更值得探索；正确性仍取决于验证。
- **“树越大越好。”** 覆盖率的收益会递减，评分误差和成本却会累积。
- **“ToT 能替代规划。”** [[wiki/AI Agent 架构/10：任务规划与控制|规划]]分解目标和依赖；ToT 只在某个不确定决策点探索候选。

## 复习

- ToT 要解决的失败是什么？——单路径在关键早期选择错误后难以纠偏。
- 何时值得使用？——有多个方向、早期选择影响大，并且中间状态可评估。
- 核心循环是什么？——生成候选 → 评分排序 → 扩展高分 → 剪枝/回溯 → 在预算内停止。
- 最重要的工程风险是什么？——评分不可靠与搜索规模失控；前者误导方向，后者耗尽成本。

# Deep Research 证据驱动研究

> [!abstract] Deep Research 不是把搜索结果多看几条，而是把开放问题转成一条可检查的证据链：先界定要回答的维度，再迭代检索、访问原文、评估来源和补足缺口，最后让每个关键结论能回到真实来源。研究的产出不是“看似完整的答案”，而是带范围、证据和不确定性的报告。

## 第一性原理：搜索片段不能自动变成可靠结论

复杂问题通常包含多个维度、时效要求和互相冲突的说法。一次搜索得到的只是候选线索；若直接摘要，系统既不知道哪些维度没覆盖，也无法证明引用真的支持结论。

```text
问题与约束
→ 拆成研究维度、时间范围和交付标准
→ 检索候选来源，并实际访问原文核验
→ 评估相关性、来源质量、时效与覆盖缺口
→ 针对空白或冲突继续探索，直到满足停止条件
→ 按证据写结论、标注引用、限制和未决冲突
```

因此，Deep Research 的核心是**受预算约束的证据获取与综合闭环**，而不是“更多搜索”或“更长回答”。

## 研究闭环：计划、验证和综合必须是不同步骤

- **计划：** 根据问题类型拆分维度，规定时间范围、地域/语言、需要的一手来源和报告结构；这避免所有检索都围绕最显眼的关键词打转。
- **检索与适应：** 每轮依据已知内容、空白维度和冲突生成下一步查询；实体研究可同时使用其主场语言获取本地一手信息，并用其他语言补充全球视角。
- **验证：** 搜索摘要只是“页面可能包含答案”的承诺。必须访问 URL，处理失效、付费墙和内容不符，并把实际使用的原文与结论关联。
- **综合：** 以证据组织报告，而非让模型补全叙事；来源冲突应被呈现，低质量或过时来源支撑的结论要降级或标注不确定性。

引用追踪使读者能复查“这句话来自哪里”；它不等同于来源正确或结论适用于所有场景。

## 停止与成本：覆盖率决定方向，硬上限防止失控

固定轮数便于控制成本，却会让简单问题过度研究、复杂问题过早停止。覆盖率方法先定义关键维度，再评估哪些维度已有足够证据、哪些仍是空白；它可引导后续搜索，但本身也是近似判断。

实际应组合两类约束：**软标准**是关键维度、引用质量和冲突是否已被处理；**硬标准**是最大轮数、页面数、墙钟时间与 [[wiki/AI Agent 架构/23：Token 预算与成本护栏|Token 预算]]。达到硬限制时，应返回已覆盖范围与未解决缺口，而不是把不完整研究伪装成定论。

## 单 Agent 与多 Agent：并行探索要能抵消协调成本

强推理单 Agent 将规划、检索、回退和综合集中在一个上下文中，结构较简单；Lead/Sub-agent 架构把可独立的维度并行探索，再由 Lead 综合。后者的关键不是“多”，而是**任务契约与语义压缩**：子 Agent 接收明确目标、边界和输出格式，回传摘要、证据与完整发现的引用，而不是倾倒全部中间文本。

仅当问题维度足够独立、覆盖要求高且预算允许时，多 Agent 才值得采用；简单事实查询优先有限轮的单 Agent。长任务还应使用检查点、可恢复状态和单步失败降级，避免一个 URL 或子任务失败迫使全部重来，可借鉴 [[wiki/AI Agent 架构/21：Temporal 持久化工作流|持久化工作流]]的恢复思想。

## 工程决策

1. 在执行前把研究问题写成可验证的研究契约：范围、时间截点、维度、目标读者、允许的来源类型、预算与停止条件；范围不清时先追问，不直接开搜。
2. 为每条关键结论保存“结论 → 已访问来源 → 支撑片段/结构化事实”的映射；搜索结果标题、模型记忆和未访问 URL 不得直接充当引用。
3. 建立来源分级与冲突处理规则：优先官方、原始数据和一手材料；二手报道用于补充；无法核验、低质量或过时的信息必须显式降级。
4. 将覆盖缺口、访问失败、迭代轮数、来源质量、Token 与耗时接入 [[wiki/AI Agent 架构/22：Agent 可观测性与诊断闭环|可观测性]]；这些数据用于评估“研究是否值得继续”，不是只为事后展示。
5. 先用单 Agent 验证研究契约、引用链和停止策略；只有在独立维度确实需要并行、且压缩接口可用时，再引入多 Agent。

## 常见误解

- **“多搜几次就是 Deep Research。”** 没有计划、验证、缺口判断和证据化综合，只是重复搜索。
- **“带引用就不会幻觉。”** 引用可能失效、不相关或质量很低；必须核对原文并标注适用范围与冲突。
- **“多 Agent 一定更好。”** 它往往也增加 Token、协调和上下文传递；优势应由任务并行性和覆盖收益证明。
- **“覆盖率达到阈值就代表研究完成。”** 阈值只是停止信号；报告仍应说明范围外内容、时间截点和未解决问题。

## 复习

- 为什么不能直接综合搜索摘要？——摘要不是已验证证据，无法保证内容、时效和引用对应关系。
- 为什么需要同时使用覆盖率与硬上限？——前者避免盲目固定轮数，后者限制模型误判或循环造成的时间和成本失控。
- 多 Agent 研究的真正接口是什么？——可组合的任务契约、压缩后的发现和可回溯证据，而不是把更多 Agent 堆到同一问题上。

# 记忆架构

> [!abstract] 记忆不是“把内容存进向量库”。它是一套可治理的信息生命周期：决定什么值得写入、属于谁、何时召回、如何验证、何时纠正或删除。

## 第一性原理

当前上下文会结束，跨任务经验却可能仍有价值；但把所有历史长期保存并在每轮全量注入，会带来噪音、成本、隐私和错误传承。

```text
候选信息 → 判断价值与范围 → 持久化
→ 按当前任务过滤并召回 → 验证后使用
→ 纠正、过期或删除
```

记忆的目标是帮助当前决策，不是模拟无限、绝对正确的“记住一切”。

## 四类信息各归其位

| 信息 | 权威位置 | 用途 |
| --- | --- | --- |
| **业务事实** | 数据库、系统记录 | 权限、订单、余额、审计等可验证事实 |
| **任务/会话状态** | 状态机或会话存储 | 当前目标、步骤、审批、未完成工作 |
| **可召回经验** | 记忆存储、文档、向量索引 | 偏好、成功模式、失败教训、摘要 |
| **当前上下文** | 本次请求 | 为当前一步挑选的工作集 |

向量检索适合找“可能相关”的候选，不能替代业务事实、精确查询或授权判断。

## 生命周期的关键控制点

1. **写入：** 只保存对未来任务有复用价值的信息，并附来源、范围、时间、敏感级别和保留期。
2. **召回：** 先按 tenant/user/project/agent 与权限过滤，再按当前任务、时效和相关性排序；不要先全局相似度检索再补权限。
3. **使用：** 将召回内容标为线索或事实；关键结论仍需回到权威记录、来源或工具回执验证。
4. **纠正与遗忘：** 允许更新、撤销、过期、删除与审计；错误记忆不应因“被多次召回”而变成事实。

## 工程决策

- **记忆条目应有元数据。** 至少保存范围、来源、写入时间、有效期、敏感等级和可删除标识。
- **写入少于召回更重要。** 低价值、重复、未验证或短期临时内容不应进入长期记忆。
- **以权威记录覆盖经验。** 当偏好、摘要或向量候选与业务系统冲突，以权威系统为准并触发纠正。
- **敏感数据治理覆盖派生物。** 摘要、缓存、Embedding、检索日志同样需要脱敏、访问控制、保留期和删除能力。
- **观测记忆是否真的有用。** 记录命中率、被采纳率、纠正率、过期召回、跨租户拒绝和删除完成率。

## 常见误解

- “相似”不等于“正确”，也不等于“有权访问”。
- 存得更多不代表记得更好；写入、分块、去重和过期策略决定噪音上限。
- PII 脱敏不能替代访问控制、范围隔离和审计。

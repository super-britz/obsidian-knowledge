# Computer Use 的多生命周期上下文

> [!abstract] Computer Use 的上下文不是一份统一预算：当前视口、旧 GUI 观察、浏览器截图、用户上传图像和单页 DOM 转储，价值与老化速度都不同。可靠管理要分别限制单项大小、历史数量、来源专属图像与全局图像，并以稳定占位保留对话配对；裁剪的是模型视图，不是删除证据或文件。

## 第一性原理：可操作性决定保留，载荷类型决定控制方式

导航 Agent 需要最新视口来点击当前界面；十一个已失效视口通常只是昂贵负担。相反，“比较十二张截图”时，每张图都是任务对象。最新 DOM 转储也可能巨大到单独主宰 Prompt，即使只保留三条观察仍会超限。

```text
观察/图像进入会话
→ 按载荷类型与生成方判断可操作性
→ 限制单项大小、文本历史、GUI 图像与全局图像
→ 以明确占位替换过期载荷并保留调用配对
→ 用稳定视图进入下一次模型请求
```

因此“最多 N 条上下文”是错误抽象：一条超大观察与许多普通观察、过时浏览器截图与用户图像，分别是不同故障，需要独立控制。

## 四类控制：先限制异常大，再淘汰失效历史

1. **单次观察文本上限：** GUI/浏览器结果进入上下文时，按 rune 截断异常大的 DOM 或无障碍树，并附带原始长度标记。按 rune 而非字节，避免切断多语言字符或 emoji。
2. **文本观察窗口：** 组装请求时保留最近观察，把更早文本换成单行存根。前者解决“新鲜时已过大”，后者解决“曾经有用、如今老化”。
3. **浏览器/GUI 图像窗口：** 只对由 GUI 工具产生的旧截图执行紧裁剪，通常保留最新可操作视口。
4. **全局含图消息上限：** 作为更宽松的兜底，约束其他图像历史；不能替代浏览器专属窗口，也不应误伤用户上传和批量视觉任务。

来源专属老化应在通用上下文压缩之前执行：[[wiki/AI Agent 架构/37：分层压缩与相关性衰减|通用压缩]] 不应抢先把仍可操作的当前页面变成元数据；但已经失效的旧视口也不该继续占据其保护预算。

## 按生成方裁剪，并保留对话契约

截图虽然位于 `tool_result` 中，却不代表所有图像都属于浏览器历史。过滤器应先识别 GUI 工具族，再用 `tool_use_id` 找到对应结果，只替换这些旧截图；全局图像规则随后处理剩余图像。先窄后宽，才能把有限预算留给真正需要多图比较的任务。

不能直接删除结果块：Assistant 的 `tool_use` 仍需要匹配的 `tool_result`。正确方式是保留轮次结构与 ID，仅把旧像素或文本换成说明原因的占位，例如“旧截图已为节省上下文移除”。模型知道证据已丢失，Provider 配对仍合法，审计也能解释后续决策为何没有看到原内容。

## 幂等视图与独立保留：避免缓存漂移，也不要误删证据

同一历史会反复组装 Prompt。过滤器应把完整观察一次性变成确定占位，之后不再改写：

```text
完整观察 → 一次稳定占位 → 后续请求字节不变
```

这既避免每轮反复压缩，也保护 [[wiki/AI Agent 架构/39：Prompt Cache 的字节稳定性|Prompt Cache]]。首次裁剪应记录类别、前后哈希等事件；重复访问无变化则不制造噪声。

Prompt 保留、会话/审计保留、临时截图文件清理与用户上传所有权是不同生命周期。上下文过滤只改变模型下一次看见的消息视图，不应顺手删除原始截图、审计事件或用户素材；否则“节省 token”会意外变成“销毁证据”。

## 工程决策

1. 为单项文本大小、文本历史、GUI 图像历史和全局图像设置独立配置、所有者与边界测试；不要合并成一个 `max_context_items`。
2. GUI 观察在采集时按 rune 截断，在请求组装时按新鲜度存根化；占位须说明丢失类型、原因及必要的原始长度信息。
3. 按工具身份和 `tool_use_id` 对浏览器截图实施紧预算，随后再应用更宽的全局图像控制；保留用户图像与批量视觉任务的独立空间。
4. 只替换 `tool_result` 内载荷，不破坏调用/结果配对；过滤器必须幂等、可观测，并以稳定字节保护缓存。
5. 用真实导航、状态比较、批量图像、多语言大页面和重复组装测试调参，同时观察任务成功率、重取截图率、token、缓存漂移和审计可重建性。

## 常见误解

- **“所有图像只保留一张。”** 最新浏览器视口与用户上传、视觉比较图像有不同任务价值，不能混为一类。
- **“有观察窗口就不需要单项上限。”** 一份异常大的 DOM 转储仍可独占 Prompt；反过来，只有单项上限也挡不住大量合法观察累积。
- **“删掉旧结果块最省 token。”** 会破坏 `tool_use`/`tool_result` 配对，并让记录错误暗示模型见过已移除证据。
- **“裁剪 Prompt 就等于清理文件。”** 模型视图、审计、磁盘清理与用户素材各有生命周期，必须分别治理。

## 复习

- 为什么要区分采集时截断和组装时老化？——前者处理新鲜但异常大的单项，后者处理曾有价值但已失效的历史。
- 为什么浏览器截图不能与用户图像共用紧窗口？——前者通常只需当前可操作视口，后者可能正是用户要求比较或分析的任务对象。
- 为什么过滤器必须幂等？——同一历史会重复进入请求；占位若不断变化，会污染缓存前缀、增加成本并制造难追踪差异。

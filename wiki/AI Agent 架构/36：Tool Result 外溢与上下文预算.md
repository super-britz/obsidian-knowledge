# Tool Result 外溢与上下文预算

> [!abstract] 大工具结果的关键不是“删掉多少”，而是“模型现在不需要的全文怎样仍可精确取回”。截断会销毁信息并诱发重复调用；外溢把原文迁移到受控存储，仅在 Prompt 留下预览和指针，再用单结果与单 Turn 两层预算控制并行结果的总负担。

## 第一性原理：未被模型带入 Prompt，不等于内容必须消失

工具结果常包含模型当前只需少量片段、但后续仍可能需要全文的信息。直接截断会让模型失去检索路径；它不知道缺失内容是否重要，往往只好以更窄条件重跑同一工具，既增加成本又可能仍找不到原文。

外溢改变的是**内容位置**而不是内容存在性：

```text
工具产生完整结果
→ 超过预算时写入受控的 Session 范围存储
→ Prompt 留下可读预览 + 可取回指针
→ 模型先判断是否相关
→ 只在需要时按目标读取原文或局部内容
```

预览提供方向，指针保留可恢复性。模型不再默认携带所有“可能有用”的内容，而是在问题收窄后做一次更精确的取回。这是削减上下文负担而不把信息当垃圾删除的根本区别。

## 两层预算：单个异常与并行总量是不同故障

单个结果阈值处理“一条输出异常大”的情况；但并行批次可由许多各自不过阈值的中等结果共同撑爆同一 Turn。因此还需要聚合预算：在工具批次完成后计算全部结果的总量，并从符合条件的候选中逐步外溢，直到接近目标或没有可处理对象。

```text
单条结果过大 → 单结果外溢
多条结果合计过大 → 单 Turn 聚合削减
仍超过目标 → 记录原因并进入后续压缩/停止策略
```

聚合预算是控制目标而不是绝对天花板：工具可能声明“自行设界”而被豁免，或者外溢操作本身失败。系统不应假定总量永远不会超标，而应记录实际大小、候选选择和未达标原因，交由 [[wiki/AI Agent 架构/35：上下文压缩的多层防线|上下文压缩]] 的分级治理继续处理。

## 工具契约：谁能恢复原文，谁应负责设界

并非所有工具结果都该外溢。返回文件路径、对象 ID、分页游标或其他稳定引用的读取类工具，原文已经可取回；再把结果写到另一份文件，只是增加一层间接和额外往返。此类工具应在自身契约中限制输出大小、支持范围读取或分页。

外溢适合“输出只存在于本次返回中”的工具。工具应显式声明：是否有稳定来源、是否自行控制结果大小、适合的预览形式以及敏感级别；分发器不应仅根据工具名称维护一份容易过期的豁免清单。[[wiki/AI Agent 架构/03：工具与行动边界|工具契约]]决定结果如何被消费，不只是参数 Schema。

预览必须按 Unicode 字符边界切分，而不是按字节。否则会损坏 UTF-8 字符；对中日韩等多字节文本，还会让同样字节预算得到远低于预期的可读预览。

## 外溢替换必须跨 Turn 持久化

工具结果会进入 Session 历史。若外溢仅是当前 Turn 的内存变换，下一轮重建历史时原始大结果会重新回到 Prompt，然后被再次外溢，形成隐蔽的重复写入、上下文膨胀和延迟问题。

因此持久化状态至少需要保存：原结果是否已处理、它被替换成什么预览/指针、外溢内容的作用域与生命周期。单独保存替换表还不够；“未处理”和“已处理但替换记录缺失”必须可区分，否则恢复逻辑会在重复外溢与静默丢失之间摇摆。

这是一条通用规律：**任何改变 Prompt 历史的操作都必须与 Session 一起可恢复地保存。** 它同样约束压缩、脱敏和后续的分层重写。

## 存储与生命周期：外溢文件也是新的敏感资产

外溢目录保存的是工具输出副本，可能包含代码、文档、搜索结果或受权限控制的数据。它不是无害缓存，应按 Session/租户/工作区隔离，限制读取主体，记录创建与访问，并设置取消、过期、完成后的清理策略。持久化时间越长，泄露面和合规成本越高；过早清理又会使 Prompt 中的指针失效。

因此外溢存储需要与 [[wiki/AI Agent 架构/25：安全执行与能力沙箱|安全执行]]、[[wiki/AI Agent 架构/30：Background Agents 持久化后台任务|后台任务]]使用相同的作用域、权限和终态治理，而不能只是临时目录。

## 工程决策

1. 先区分“截断”与“外溢”：对后续可能需要的原文保留预览与可取回指针；只有确认无需恢复的内容才可真正丢弃。
2. 同时设置单结果与单 Turn 聚合预算，并在并行工具批次完成后测量合计大小；记录豁免和失败导致的超标原因。
3. 让工具声明是否自我设界、是否有稳定引用及支持的范围读取；已有可取回引用的读取类工具优先优化自身输出，不重复外溢。
4. 以 Unicode 字符边界生成预览，保留可读上下文；不要按字节切字符串。
5. 将外溢替换、已处理标记、存储位置和生命周期与 Session/Checkpoint 一起持久化，保证跨 Turn 重建的仍是替代视图。
6. 为外溢目录定义 Session/租户范围、访问控制、加密或受控存储、审计和清理；将指针失效视作需要处理的明确终态。

## 常见误解

- **“截断大结果更简单。”** 它删除模型可能需要的部分，常诱发相同工具的重复调用；外溢以按需读取换取信息可恢复性。
- **“每条结果都有限制，就不会撑爆上下文。”** 并行的多条中等结果可以合计超标，必须另设 Turn 级预算。
- **“总量预算就是不可突破的硬上限。”** 豁免工具、可恢复引用和外溢失败会产生合理例外；系统应可观测，而非假定绝不越界。
- **“外溢文件只是缓存，不需要安全治理。”** 它是工具输出的明文副本，必须与原始数据一样隔离、审计和清理。

## 复习

- 为什么外溢优于截断？——外溢保留预览和原文取回路径，使模型不必为找回缺失信息重复调用工具。
- 为什么必须有 Turn 级预算？——并行批次可让每条中等结果都通过单条阈值，却在合计上耗尽上下文。
- 为什么替换要持久化？——Session 重建会重放历史；未保存的 Prompt 整形会在每一轮重复执行或让大结果重新出现。

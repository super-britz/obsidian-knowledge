# Debate 多视角对抗与综合

> [!abstract] Debate 不是让多个 Agent 重复发表意见，而是把一个存在真实争议的决策拆成**相互冲突的假设、利益与证据要求**：先独立陈述，再交叉质疑，最后输出条件化结论、未决分歧和少数派风险。它的价值是暴露盲点，而不是用多数票制造“真相”。

## 第一性原理

有些问题没有唯一可由规则直接求出的答案：不同目标、约束或受影响方会给出不同的合理判断。单个 Agent 往往会沿着最先形成的叙述继续生成，难以主动提出能推翻自身前提的反例；若多个 Agent 接收相同提示、扮演相似角色，它们也只会把同一偏见放大。

```text
争议问题中的假设、利益或证据标准不同
→ 为每一类分歧定义独立且相互张力的视角
→ 先独立提出主张、依据和适用条件
→ 再针对对方前提、证据与后果交叉质疑
→ 区分可验证事实、价值取舍与仍未知的问题
→ 综合条件化建议，并保留少数派与证据缺口
```

因此，Debate 的本质是**受控的反证与观点覆盖机制**。它提升的是决策过程发现盲点的机会，不能让没有证据的主张因“辩赢了”而变成事实。

## 何时值得辩论

适合 Debate 的问题通常同时具备：

1. **存在真实分歧：** 多个立场对应不同目标、风险承受度或利益相关者，而非同一答案的措辞差异。
2. **结论需要权衡：** 例如产品方向、投资判断、政策与伦理议题；重要的是条件和影响分布，不只是一个数值答案。
3. **分歧能被具体化：** 各方可以提交可追溯的主张、证据、反例、前提与退出条件。

事实检索、法规适用、确定性计算和已有明确验收标准的执行任务，不应使用 Debate；应直接走 [[wiki/AI Agent 架构/12：结构化推导与证据验证|结构化验证]]。若问题是“多条解决路径哪条更值得继续”，用 [[wiki/AI Agent 架构/17：Tree-of-Thoughts 多路径搜索|ToT]]；若已有一个结果需要改进，用 [[wiki/AI Agent 架构/11：结果反思与质量控制|反思]]。

## 视角不是人设

每个辩论者应代表一种可检查的**决策函数**，而非泛泛的“乐观派”或“保守派”。一个有效视角至少声明：

| 要素 | 要避免的失败 |
| --- | --- |
| 关注目标与受影响方 | 只换语气，实际仍采用同一目标 |
| 必守约束与风险阈值 | 为赢辩论而忽略不可接受的代价 |
| 可接受的证据标准 | 将未经核验的说法当作论据 |
| 关键假设与反例 | 看不到什么条件会使自身立场失效 |

例如技术选型可分成“性能与交付速度”“总拥有成本”“安全与合规”；三者必须能对同一方案给出相互张力的评价。角色相似时，辩论会退化为假共识。

## 三阶段：覆盖、对抗、综合

1. **独立陈述：** 各方在尚未被他人文本锚定前，分别给出结论、证据、假设、可接受条件与主要风险。
2. **交叉质疑：** 要求每一方明确挑战对方的前提、因果链、证据质量或遗漏后果，并承认哪些反驳成立、哪些信息仍不足；不能只重复自己的观点。
3. **受控综合：** 主持人或规则化流程把材料拆成事实主张、价值取舍、共识、分歧、少数派预警和待验证项，输出带条件的建议，而非把最强措辞拼成一个结论。

投票可在无法收敛时帮助选择下一步行动，但票数只能表达当前偏好或评分结果，不能证明主张为真。对关键决策，应保留少数意见及其触发条件。

## 证据与裁决边界

辩论中“论证流畅”“引用很多”都不等于证据可靠。裁决应优先依据来源质量、可复核数据、约束满足、实验或模拟结果；无法验证的判断应以不确定性和适用条件呈现。

```text
主张 → 证据/假设 → 反驳 → 可验证检查 → 综合结论或保留分歧
```

主持人负责组织和标注，不应成为无依据的权威裁判。若所有参与者依赖同一错误上下文或同类评分器，所谓共识可能只是相关性很高的重复错误。

## 收敛、预算与持久化

多 Agent、多轮辩论的调用次数和上下文会随参与者、轮次和互相可见的历史增长。应在开始前明确：

- **上限：** 人数、轮次、每轮上下文、Token、时长和并发；优先传递结构化争点摘要，而不是累积完整历史。
- **停止：** 新一轮没有引入新证据或新反例、关键分歧已转为待验证项、达到预算或出现人工中止时停止。
- **兜底：** 不强制共识；无法收敛时输出分歧地图、少数派风险和需要补充的证据，再由负责人决定。
- **复盘：** 保存视角定义、主张来源、关键反驳、结论条件、未决问题与预算，而不是把“获胜立场”直接写入长期事实库。

## 工程决策

1. 先写清决策问题、不可触碰的约束和最终负责人；没有明确决策对象时，不启动辩论。
2. 以相互冲突的目标或利益设计 2～4 个视角，并让它们独立给出初始判断，降低首个答案的锚定效应。
3. 把轮次设计为“质疑与让步”，要求引用或标记证据缺口；禁止只要求“说服对方”。
4. 最终产物固定包含：建议、成立条件、关键证据、反对意见、未决风险与下一步验证，而不是只有赢家。
5. 涉及安全、合规、资金或对外承诺时，将 Debate 作为决策输入，不替代授权、审计和人工审批。

## 常见误解

- **“多个 Agent 一致就更可靠。”** 若角色、模型或上下文高度相同，一致性可能只是同源偏差。
- **“强制共识代表高质量。”** 真实分歧可能无法消除；强制收敛会隐藏条件和风险。
- **“投票能裁定事实。”** 投票只能聚合判断，事实仍需独立验证。
- **“辩论与 ToT 相同。”** ToT 在同一目标下搜索候选路径；Debate 保留不同价值和解释框架之间的对抗。

## 复习

- Debate 要弥补什么失败？——单一叙述及相似视角容易遗漏反例、利益冲突和风险。
- 最小闭环是什么？——独立主张 → 交叉质疑 → 事实/取舍/未知分层 → 条件化综合。
- 何时不该用？——问题有可直接验证的客观答案，或各视角无法形成真实且可检查的分歧。
- 最重要的控制是什么？——视角差异、证据可追溯、有限轮次与保留少数派。

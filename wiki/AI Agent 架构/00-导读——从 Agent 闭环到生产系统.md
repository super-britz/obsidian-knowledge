# 从 Agent 闭环到生产系统

[[wiki/AI Agent 架构/00-索引|返回专题索引]] · [[wiki/00-索引|知识库首页]]

这套笔记的学习目标是：面对一个真实任务，能说明需要哪些能力、它们解决什么失败，以及怎样验证结果。无需平均读完 45 章。

## 怎样读

1. **选一个具体任务。** 例如“研究一个主题”，先写目标、允许动作、完成证据和停止条件。
2. **走一遍[[wiki/AI Agent 架构/00-索引#先从这里开始|索引中的基础路径]]。** 每读一篇，就补上这个任务缺少的一项机制。
3. **遇到瓶颈再扩展。** 用[[wiki/AI Agent 架构/00-索引#按问题查|问题入口]]定位；需要升级架构时，先查[[wiki/AI Agent 架构/附录-模式选择与渐进复杂度|模式选择]]。

读完一篇只需说清四件事：**原来会怎样失败 → 新机制怎样修复 → 增加什么代价与边界 → 用什么结果证明值得采用。** 不必重新摘录整章。

## 学会的标准

| 学到哪一步 | 能完成的判断 |
| --- | --- |
| 最小闭环 | 为任务写清目标状态、工具、真实回执和停止条件；能区分“生成了回答”和“任务已完成”。 |
| 状态与上下文 | 说明一条信息应放在当前上下文、会话状态还是长期记忆；超预算时知道哪些必须保留，哪些可压缩或外置。 |
| 可靠运行 | 面对卡住、重复调用、成本异常或中断，能指出需要检查的状态和证据，以及何时停止或恢复。 |
| 治理与副作用 | 区分“模型提议”“策略允许”“工具执行成功”和“业务完成”；说明权限、审批与沙箱各自控制什么。 |

项目涉及真实写入或外部动作时，应同时阅读[[wiki/AI Agent 架构/24-策略治理与授权决策|授权决策]]和[[wiki/AI Agent 架构/25-安全执行与能力沙箱|安全执行]]。权限边界不能留到最后补。

## 什么时候继续学

能指出已观察到的失败，再进入对应章节：

- **已知依赖需要稳定调度：** 看[[wiki/AI Agent 架构/14-DAG 依赖调度|DAG]]；任务还需要持久化恢复时，再看[[wiki/AI Agent 架构/21-Temporal 持久化工作流|Temporal]]。
- **角色、权限或上下文确实需要分开：** 看[[wiki/AI Agent 架构/13-多 Agent 编排与协调|多 Agent]]和[[wiki/AI Agent 架构/16-Agent Handoff 与数据交接|Handoff]]。
- **早期选择不确定且影响全局：** 看[[wiki/AI Agent 架构/17-Tree-of-Thoughts 多路径搜索|多路径搜索]]；需要暴露相互竞争的观点时，看[[wiki/AI Agent 架构/18-Debate 多视角对抗与综合|Debate]]。

复习时，把任务换成另一个场景，重新回答：**最小方案是什么？它在哪种条件下会失败？新增机制的收益如何验证？** 能迁移这三个判断，比记住模式名称更有用。

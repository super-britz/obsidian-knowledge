# 多轮对话与会话状态

> [!abstract] 多轮对话不是不断增长的消息数组，而是有身份、范围、顺序和生命周期的状态系统。连续体验来自服务端可恢复状态与受控历史选择，而不是把整段聊天记录反复塞给模型。

## 第一性原理

HTTP 请求和模型调用天然无状态，但用户会持续追问、修改目标、等待审批或中断后恢复。若系统不显式保存会话归属和任务状态，下一轮无法可靠判断“谁在做什么、已发生什么、能否继续”。

```text
身份与权限 → 定位会话 → 读取权威状态
→ 选择本轮必要历史 → 执行并追加事件/产物
→ 设置过期、恢复与删除边界
```

Session ID 只用于定位对象，**不是授权凭证**；每次访问仍需验证 tenant、user、project 和权限。

## 三层信息分工

| 层 | 保存什么 | 不能替代 |
| --- | --- | --- |
| **消息事件** | 用户输入、助手输出、工具交互 | 当前任务的权威状态 |
| **会话/任务状态** | 目标、步骤、审批、产物、失败与恢复点 | 长期经验 |
| **当前上下文与长期记忆** | 本轮工作集 / 跨会话可召回内容 | 会话身份与授权 |

消息历史是证据之一，不应成为唯一状态机；重要目标、审批和副作用回执必须结构化保存。

## 历史与隐私的控制

- **按决策价值选历史。** 最近消息并不总是最重要；任务目标、关键约束、审批、工具回执和未决问题优先。
- **先治理敏感数据，再产生派生物。** 脱敏应发生在摘要、缓存、日志、Embedding 和检索之前；同时保留访问控制、保留期与删除机制。
- **体验层可失败。** 标题、语义去重、推荐和摘要应幂等、异步或有确定性降级，不阻断身份校验和核心执行。
- **依赖故障要安全降级。** 缓存或存储不可用时不能伪造连续会话、跳过审批或静默创建空状态；应返回恢复指引或安全停止。

## 工程决策

1. 服务端维护会话契约，并在每次读写时校验范围和权限。
2. 将事件、任务状态、当前上下文与长期记忆分层；关键状态可恢复、可审计。
3. 为历史、摘要、回执和记忆分配 Token 预算，保留原始记录的恢复指针。
4. 对会话创建、写入、标题生成和恢复使用幂等键、超时、重试与熔断。
5. 观测串会话拒绝、恢复成功率、历史截断、PII 拦截、缓存/存储故障和人工重启次数。

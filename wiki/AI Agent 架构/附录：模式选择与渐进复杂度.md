# 模式选择与渐进复杂度

> [!abstract] 模式不是能力清单，而是为某种不确定性付出的控制成本。先用能验证完成的最小闭环；只有工具、依赖、质量、搜索空间、协作边界或恢复需求确实超出它时，才逐层增加 ReAct、规划、校验、搜索、工作流或多 Agent。

## 第一性原理：复杂度只应购买确定的控制收益

LLM 每增加一个循环、角色或编排器，系统同时增加调用次数、上下文、状态、失败路径和排障成本。若任务的目标、步骤与验收已经清楚，额外模式只会引入更多不确定性。

```text
目标状态与完成证据
→ 判断下一步、依赖和风险是否可预知
→ 选择刚好补足缺口的最小机制
→ 用预算、权限、停止条件和回执限制它
→ 从真实任务指标验证收益是否超过新增复杂度
```

因此，先问“当前最小闭环为什么会失败”，不要先问“该用哪个热门模式”。

## 从任务特征到最小机制

| 任务特征 | 最小机制 | 它补的缺口 | 不应借此解决 |
| --- | --- | --- | --- |
| 单轮即可产出，且不需改变外部状态 | 直接生成/结构化输出 | 表达与格式 | 事实验证、外部执行 |
| 需要读写外部环境，下一步取决于观察 | [[wiki/AI Agent 架构/02：ReAct 循环\|ReAct]] | 行动—观察反馈 | 长链依赖的预先统筹 |
| 目标可拆，依赖与产物可预先定义 | [[wiki/AI Agent 架构/10：任务规划与控制\|Planning]] 或 [[wiki/AI Agent 架构/14：DAG 依赖调度\|DAG]] | 子任务、依赖与验收 | 下一步完全未知的动态策略 |
| 草稿可按明确标准检查并有限改进 | [[wiki/AI Agent 架构/11：结果反思与质量控制\|Reflection]] | 质量校验与受限重试 | 缺少外部事实依据的自证 |
| 早期选择高度不确定，且不同路径会改变结果 | [[wiki/AI Agent 架构/17：Tree-of-Thoughts 多路径搜索\|ToT]] | 候选生成、比较、剪枝 | 有唯一确定步骤的普通任务 |
| 结论存在价值冲突或相互竞争的合理观点 | [[wiki/AI Agent 架构/18：Debate 多视角对抗与综合\|Debate]] | 独立论证、质疑与条件化综合 | 可由工具事实直接判定的问题 |
| 角色权限、上下文或专长真正不同 | [[wiki/AI Agent 架构/13：多 Agent 编排与协调\|多 Agent]] / [[wiki/AI Agent 架构/16：Agent Handoff 与数据交接\|Handoff]] | 隔离、专业分工或控制权转移 | 对单一小任务的机械拆分 |

**顺序比名称重要：** 先确认工具和回执，再确认依赖；先确认质量标准，再引入反思；先确认角色边界和并行收益，再引入多 Agent。

## 编排选择：依赖形状决定控制结构

```text
子任务完全独立        → 有界并行
后续必须使用前序产物  → 串行
依赖在开始前已知      → DAG
下一步与角色在运行中才确定 → Agent Loop / Supervisor
需要把责任交给另一专长或权限域 → Handoff
```

并行不是“更快”的同义词。只有输入独立、工具可安全并发、汇合语义明确且预算足够时，并行才缩短关键路径；否则会扩大竞态、重复和审计难度。DAG 适合把已知依赖变成可检查承诺；运行时才出现的分支应留给 [[wiki/AI Agent 架构/34：DAG 与 Agent Loop 的控制流边界|Agent Loop]]。

## 先做减法：高频反模式

1. **为了多 Agent 而拆分：** 若没有独立权限、上下文、专长或并行收益，保留单 Agent；协调本身也是工作。
2. **把不确定问题伪装成 DAG：** 依赖未知时先用 Loop 探索，再把稳定部分固化为 DAG。
3. **把 Reflection 当事实验证：** 自评只能找出部分结构问题；关键结论仍须工具回执、测试或人工审核。
4. **无限探索或无限重试：** ToT、Debate、反思和研究都必须有候选数、轮次、时间与 [[wiki/AI Agent 架构/23：Token 预算与成本护栏|预算]]上限，以及可解释的停止条件。
5. **用模式掩盖工具与治理缺陷：** 工具不可靠、权限不清或状态不可恢复时，增加 Agent 只会放大错误。

## 工程决策

1. **先写任务契约。** 明确目标状态、外部完成证据、允许动作、风险等级、预算和停止条件；未定义这些前不升级架构。
2. **按“不可预知的部分”选模式。** 已知依赖用确定性编排；未知下一步用反馈 Loop；只有高价值且早期不可逆的选择才值得多路径搜索或对抗。
3. **为升级设准入指标。** 记录基线任务成功率、人工介入、延迟、Token、工具错误与恢复成本；复杂模式必须在真实验收集上证明净收益。
4. **把治理作为所有模式的外层约束。** 预算、权限、审批、超时、观测和恢复不属于某一种模式的附加选项，而是每种执行形态都要回答的问题。

## 常见误解

- **“复杂任务必然需要多 Agent。”** 复杂可能来自工具不可靠、上下文不足或验收不清；先修真实瓶颈。
- **“Planning 比 ReAct 更高级。”** 二者分别适应已知依赖与基于观察的动态决策；不存在脱离任务形状的高低。
- **“成本表能直接决定选型。”** 书中的 Token、延迟和并发数只能作为假设；实际取舍取决于模型、工具、任务分布与验收目标。

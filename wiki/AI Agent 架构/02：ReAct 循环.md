# ReAct 循环

> [!abstract] ReAct 不是让模型“多想几步”，而是用“推理 → 行动 → 观察”的反馈闭环，让模型持续获取新证据并修正下一步。它降低静态猜测带来的不确定性，但正确性仍取决于工具、观察、验收和终止控制。

## 第一性原理：为什么单次生成无法处理未知环境

多步任务开始时，模型通常缺少完成任务所需的真实信息：竞争对手的定价、日志中的异常、文件当前内容、API 的执行结果。若直接要求它给答案，模型只能在既有上下文和训练先验中猜测。

要减少这种不确定性，系统必须反复执行这个因果链：

```text
当前目标与已知状态
→ Reason：识别还缺什么，并选择最有价值的下一步
→ Act：调用工具、修改环境，或向人追问
→ Observe：记录客观结果与状态变化
→ 将新证据写回状态
→ 下一轮 Reason，直到满足完成或停止条件
```

因此，ReAct 的本质是一个**以外部观察修正决策的反馈控制循环**：

- **Reason** 决定如何降低当前的不确定性；
- **Act** 使系统获得信息或改变环境；
- **Observe** 提供对行动结果的事实回执；
- **控制器** 决定是否继续，并限制循环的资源和风险。

它把“猜”变成“查 + 证据 + 可回滚”，而不是把概率性模型变成正确性保证。

## 循环中必须显式保存什么

一个可调试的 ReAct 运行时至少需要明确以下状态：

| 状态 | 用途 | 缺失后的典型失败 |
| --- | --- | --- |
| 目标与完成证据 | 判断什么叫完成 | 模型用一段看似合理的文本提前收工 |
| 当前假设与待验证问题 | 决定下一步信息价值 | 反复搜索、行动没有方向 |
| 工具动作与参数 | 让副作用可追溯、可重试 | 无法复盘“做过什么” |
| 客观观察结果 | 为下一轮提供新证据 | 把模型判断误当事实，或 Reason 与 Act 脱节 |
| 迭代、时间与成本 | 限制资源 | 无限循环、超时、Token 外溢 |
| 权限与人工接管状态 | 限制高风险行动 | 越权、不可逆操作失控 |

**观察应先记录事实，再在下一轮解释。** 将判断混入 Observe，会把未经验证的推测伪装成环境状态，污染后续决策。

## 终止不是附属条件，而是循环的一半

Agent 的问题不只是“下一步做什么”，也是“什么时候不再做”。终止条件可分为两类：

### 业务完成条件

- 已得到外部完成证据，例如官方定价页、通过的测试、已写入的文件或订单状态；
- 新观察不再带来进展，结果已经收敛；
- 用户明确中断或转交人工。

### 硬护栏

- 最大迭代次数；
- 时间或超时上限；
- Token、工具调用或金额预算；
- 权限策略拒绝继续执行。

前者防止**过早停止**：没有证据却声称完成；后者防止**过晚停止**：重复无效动作直到成本或风险失控。二者缺一不可。

## 约束与失败表现

- **无限循环：** 搜索词或工具输入不变，观察也没有新信息，却持续重试。
- **过早收工：** 模型没有调用工具、没有完成证据，就直接基于先验生成答案。
- **上下文膨胀：** 所有 Observation 原样累积，导致成本上升且关键信息被淹没。
- **思考与行动脱节：** 计划说要验证 A，实际却调用 B；常见原因是状态和工具参数没有被结构化关联。
- **把工具成功当任务成功：** API 返回 200 或文件写入成功，不等于用户目标已经被满足。

## 工程决策

1. **先定义完成证据，再设计循环。** 例如“调查竞品”要求引用官方来源，“修复故障”要求测试通过或人工确认，而不是仅输出一段总结。
2. **每轮优先选择信息价值最高、风险最低的动作。** 对象不明确时先追问；可从官方页面获得数据时，不应先调用高权限工具。
3. **为循环设置下限、上限和收敛检测。** 下限防止未查即答；上限限制迭代、超时和预算；收敛检测用于识别连续重复或没有新信息的观察。
4. **管理 Observation，而非无界累积历史。** 保留近期原始回执，把稳定结论压缩为摘要；摘要必须区分事实、推断和待验证项。
5. **高风险行动放在循环外部审批。** ReAct 可以提出付款、发布、删除等动作，但策略层必须决定是否允许执行与如何审计。
6. **将循环状态结构化并持久化。** 这样才能恢复任务、复盘失败、比较策略，并为后续的并发与长期运行打基础。

## 不要把实现示例当成原理

- `MaxIterations`、`MinIterations`、`ObservationWindow` 是将“停止、证据和上下文边界”落实为配置的常见方式；具体数值不是通用答案。
- Shannon 的提前停止、LangGraph 的状态图、LangChain 的 Agent Executor 都是实现差异；稳定不变的是“行动后必须以外部观察更新状态，并由控制器决定是否继续”。
- ReAct 适合下一步未知、需要根据新信息调整路径的任务；步骤稳定且可预先定义时，确定性工作流通常更简单、更可测。

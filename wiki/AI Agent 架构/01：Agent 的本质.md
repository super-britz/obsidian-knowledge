# Agent 的本质

> [!abstract] Agent 不是会聊天的模型，也不是装了工具的 Chatbot；它是在目标、状态、工具回执和治理约束构成的反馈循环中，由 LLM 决定下一步行动、并以真实世界结果持续修正的执行系统。

## 第一性原理：模型为什么不能天然完成任务

LLM 的直接能力是在**当前上下文**下生成下一个 Token。它不会天然保存任务状态、调用外部能力、判断动作是否真的生效，也不会自行遵守预算、权限和审批规则。

因此，Agent 的关键增量不是更长的 Prompt、更多角色或更像人的表达，而是把模型置于一个受控闭环中：

```text
用户目标 + 当前环境
→ 选择并组织当前上下文
→ LLM 提议下一步行动
→ 权限、预算与策略检查
→ 执行工具或请求人工输入
→ 读取真实回执，更新外部状态
→ 决定继续、重试、转交或停止
```

模型负责提出候选动作；运行时负责让动作安全地发生，并用观察结果证明或推翻模型的判断。

## 什么使系统成为 Agent

### 1. 任务以“目标状态”而非“文本回复”定义

Chatbot 的主要产物是一段回答；Agent 要让外部世界进入某个可验证状态。

以订机票为例，任务不是生成航班信息，而是让系统达到“已成功出票”：搜索和筛选只是中间动作，付款需要用户确认，订单号与出票状态才是完成证据。

### 2. 最小增量是任务闭环

单次模型调用只能产生一次输出。多步任务需要外部运行时保存状态、执行动作、读取结果，再决定是否进行下一次调用。ReAct、Planning、Reflection、DAG 和多 Agent，都是对这个闭环不同位置的扩展，而不是 Agent 的先决条件。

### 3. 工具把语言意图变成外部行动，也带来验证责任

工具使模型能够检索、读写文件、调用 API 或操作浏览器；工具结果让系统观察真实环境。但动作可能失败、延迟、部分成功或不可逆，所以模型声称“已完成”不能作为完成依据。关键任务应以订单状态、测试结果、文件变化等外部回执为准。

### 4. 上下文是当前决策的工作区，不等于记忆

每轮决策都依赖目标、历史、工具结果和环境信息，但它们会竞争有限的上下文与成本预算。长期信息应外置、选择性检索、压缩或摘要；否则系统会遗忘关键信息，或被无关历史与长工具结果污染。

### 5. 自主性是受约束的决策权，不是越高越好

原文以 L0～L5 描述从纯对话到长期自主运行的连续谱系，并注明这不是学术标准。第一性原理上，自主性表示系统允许模型自行选择下一步行动的范围：范围越大，人工介入越少，但路径不确定性、成本、权限风险和排错难度也越高。

## 约束与失败表现

- **没有工具或真实回执：** 系统只能给建议，或把猜测误当成已完成的事实。
- **没有状态与停止条件：** 容易重复搜索、重复执行、无止境重试或丢失任务进度。
- **没有上下文边界：** 关键信息被遗忘，或无关历史污染当前判断并推高成本。
- **没有治理：** 概率性决策可能越权访问、超出预算，或执行删除、付款、群发等不可逆副作用。
- **任务本身不可验证：** 目标含糊、依赖主观审美或责任极高时，系统无法稳定自行迭代到“正确”。

## 工程决策

1. **先定义目标状态和外部完成证据。** 在写 Prompt 或接入框架前，先明确成功后环境应如何变化、由什么回执验证。
2. **从最小闭环开始。** 任务明确时，优先使用“单 Agent + 少量工具 + 显式状态 + 完成校验”。
3. **按不确定性增加控制机制。** 步骤稳定时使用确定性工作流；下一步未知时才引入 Agent Loop；只有角色、上下文、权限或并行需求确实不同，才考虑多 Agent 或 Handoff。
4. **按风险授予最小自主性。** 搜索、归类、生成草稿等低风险动作可自动执行；付款、发布、删除、群发和高风险决策应人工确认或直接禁止。
5. **把模型输出视为候选判断。** 工具契约、状态检查、预算与权限控制、可观测日志和恢复机制，才是系统可控性的主要来源。

## 别误解

- **Agent = ChatGPT + 插件。** 插件只提供单次行动能力；Agent 的必要特征是能根据观察结果，在目标与边界内持续决定下一步。
- **模型越强，Agent 就越可靠。** 更强模型只能改善候选决策；外部回执、工具契约、权限和停止条件才决定系统是否可控。
- **多 Agent 天然更先进。** 若没有明确的角色边界、控制权差异或并行收益，多 Agent 只会增加协调成本、重复工作和排错难度。

## 复习

2. 为什么工具调用成功与任务完成仍是两件不同的事？

# 结果反思与质量控制

> [!abstract] Reflection 为质量不稳定的生成结果增加一次受限检查和定向修复机会：评估候选结果、指出可操作缺口、带反馈重生成。它能减少明显缺陷，却不能替代测试、来源校验、策略治理或人工审批。

## 第一性原理

同一请求的单次生成可能遗漏要求、表达不清或格式不合格。若直接交付，用户可能得到质量分布中的较差样本。对高价值产物，可增加生成后的质量闭环：

```text
任务目标 + 验收标准 + 候选结果
→ 硬规则/证据检查 → 模型辅助评价
→ 具体反馈 → 有限次重生成 → 再验收
```

有效反思依赖明确的验收项。没有目标、证据和可判断标准的“请改好一点”，只是随机改写。

## 反思的最小契约

| 要素 | 作用 |
| --- | --- |
| **候选版本** | 确定检查哪一版结果，并保留版本关联 |
| **质量准则** | 区分完整性、格式、引用、边界条件、安全等要求 |
| **具体反馈** | 指出缺什么、哪里错、依据是什么、应如何修复 |
| **硬验证结果** | 测试、解析、来源、策略和工具回执等可复现证据 |
| **重试与停止** | 最大次数、预算、超时、回退与人工升级条件 |

反馈应定位到验收缺口，例如“缺少两项必填字段”“关键结论无来源”，而不是只给一个总分。

## 反思不等于验证

| 机制 | 回答的问题 | 权威依据 |
| --- | --- | --- |
| [[wiki/AI Agent 架构/10：任务规划与控制|任务规划]] | 接下来该做什么？ | 目标、依赖、预算、任务状态 |
| **Reflection** | 当前产物有哪些可修复缺口？ | 质量准则与候选结果 |
| **确定性验证** | 是否满足硬性规则或事实？ | 测试、解析器、数据库、工具回执、策略 |
| **人工审批** | 风险与责任是否可接受？ | 授权人的业务判断 |

模型自评是候选信号，不是事实证明。代码优先跑测试；研究优先核对来源；不可逆动作优先检查权限和审批。

## 受限循环与成本

反思至少多一次评估调用，重生成时通常接近再做一次生成。因此它是质量优化层，不应默认加入所有请求。

```text
硬验证通过 → 交付
存在可修复缺口且预算允许 → 反馈后重试
评估/重生成失败 → 回退到上一份可用结果，标记状态
预算或重试耗尽 → 交付已验证部分，或安全停止
高风险/证据冲突 → 人工审批
```

适合高价值、标准清楚且允许延迟的报告、文档与复杂综合；简单问答、实时对话、强主观创作或成本敏感路径默认关闭或只做轻量检查。

## 工程决策

1. **先写验收标准，再开启反思。** 将格式、测试、权限等硬要求与清晰度、完整性等软指标分开。
2. **硬验证优先。** 规则、测试、来源和回执先过滤；模型评价补充规则难覆盖的质量维度。
3. **将反思做成可失败附加层。** 超时或错误时回退到上一版本，不让优化层中断核心任务。
4. **限制最坏成本。** 配置最大重试、Token/时间预算、并发和取消条件；重复低收益时提前停止。
5. **记录实际收益。** 观察触发率、重试后验证通过率、人工抽检差异、成本、延迟和回退率，校准阈值。
6. **高风险结果进入责任链。** 反思只能帮助发现问题；不确定性必须升级给验证器或有权审批的人。

## 常见误解

- 高分不等于正确；评分可能偏好文风、遗漏事实或过度自信。
- 用多个模型投票不保证真相；共同前提错误时会一致出错。
- 保存冗长“自我批评”不如保存版本、缺口、证据和验收结果。

# 分层压缩与相关性衰减

> [!abstract] 旧工具结果通常更少被再次使用，但“通常”不是事实。分层压缩只能把年龄当作相关性的代理：近期保留完整，中期保留语义，陈旧结果只留元数据；承载正文的工具设保底，并在相关性不随时间衰减时改用可按需取回的外溢。

## 第一性原理：要缩减的是未来决策价值，而不是单纯的字节数

长会话中，近期工具结果更可能参与当前推理，较早内容通常只需提醒“曾经查过什么”。年龄因此可用作预算优化的代理，但它会失效：一个早期读入的文件、堆栈或对比样本，可能正是当前任务的核心。若只按时间一刀切，模型会重读原内容，省下的 token 又以一次工具调用和额外延迟返还。

所以分层策略首先回答“未来还需要保留什么”，再决定保留多少：

```text
近期结果 → 保留完整正文：当前工作记忆
中期结果 → 保留语义：知道发现了什么，丢弃冗余形式
陈旧结果 → 保留元数据：知道做过什么、参数为何、结果体量如何
正文工具的保底 → 至少保留可用内容，不直接降为元数据
```

这是信息类型的逐级降级，而非把所有历史按相同比例缩短。[[wiki/AI Agent 架构/36：Tool Result 外溢与上下文预算|外溢]]则保留了年龄代理不可靠时的精确回看路径。

## 一次分类后稳定：避免反复损失与缓存漂移

对原生工具结果，层级应在**第一次处理时**按其与当前末尾的距离决定，并持久记录已经采用的压缩层。进入“保留语义”层的内容不应随着时间继续自动降为元数据：后续再次处理只能进一步污染摘要、打散缓存前缀，却不一定带来足够预算收益。

一次处理后保持字节稳定有三项收益：

- 防止同一信息被多次摘要造成累积失真；
- 让 Prompt 重建可复现，避免每轮都产生不同文本；
- 限制重写对 [[wiki/AI Agent 架构/23：Token 预算与成本护栏|成本]] 与 Prompt Cache 的持续破坏。

“陈旧层”应理解为首次遇到时已足够遥远且尚未压缩的结果，而不是保证所有内容最终都会被降为最小存根。

## 工具下限：正文是证据，不是可随手删除的装饰

读取文件、搜索匹配、目录遍历和浏览器页面等工具的正文，往往就是调用它们的原因。将其变成“工具名 + 参数 + 大小”的存根，会让模型知道自己曾阅读过，却无法利用其发现；重新读取既浪费预算，也可能因环境变化得到不一致结果。

通用分层策略应让这类工具在最老层仍至少保留受限正文，例如首尾片段或可用摘录，而不是直接清空为元数据。也有工具应完全跳过微压缩：页面快照、可导航结构或其他丢掉形态就失去用途的结果，需要在其工具契约中声明。

下限不是说正文永远都要留在 Prompt；当模型需要精确回看、关联并不按年龄衰减时，应使用外溢指针按需读取，而不是无限调大分层阈值。

## 压缩预算与消息完整性：优化不能制造更贵的故障

语义摘要是模型调用。若每趟会话对所有中期结果都摘要，压缩本身会变成隐蔽的调用瀑布。因此每趟要限制**尝试次数**而非仅限制成功次数；即使摘要器持续失败，也不能无限重试。超出预算或摘要器不可用时，可选择零模型调用的机械首尾截断，并标记降级原因。

工具调用与工具结果是一对协议消息。重写前要建立 `tool_use_id → 工具名/参数` 映射，确保元数据存根仍与原调用对应，且绝不删除或错配任意一侧；否则 Provider 可能直接拒绝整个请求。每次改写还应记录层级、原因、节省量与 cache 影响，才能把缓存命中下降归因到具体整形机制，而不是在多种改写之间盲猜。

## 何时不用年龄分层：相关性不是单调函数

长期对比、复杂调试、跨文件重构或回看早期错误时，早期结果可能比最新消息更重要。此时“越老越不相关”的代理从前提上失效，保底片段也未必覆盖关键中段。正确选择不是调整更精细的层级边界，而是将完整内容外溢并保留可检索引用，让模型在明确知道所需信息时取回。

短会话也不需要分层：没有超过近期工作记忆的历史时，额外机制只增加分支、测试和失败面。分层压缩只应在确实存在长会话压力且内容价值随时间大致衰减时启用。

## 工程决策

1. 将年龄只作为相关性代理，而非删除依据；先分析不同工具的结果在任务后期是否仍承载正文决策价值。
2. 为工具结果定义完整、语义、元数据三类保留形态；首次处理后持久记录层级和替换内容，避免重复压缩与缓存漂移。
3. 为文件、搜索、目录、浏览器等正文工具设置最低正文保留，或让结构性输出声明跳过微压缩；不要仅按通用年龄规则删除。
4. 对语义压缩设置每趟尝试上限和无模型调用的降级路径；指标同时记录尝试、成功、失败、节省量和质量回退。
5. 重写前验证 tool_use/tool_result 配对，并为每次改写发出带层级标签的遥测事件，关联 Prompt Cache、延迟和成本变化。
6. 当任务需要精确回看旧证据、或会话较短时，分别选择外溢或不启用分层，不靠微调年龄边界解决错误模型。

## 常见误解

- **“最旧的内容总是最不重要。”** 年龄只是统计代理；当前正在修改的文件可能很早读入，却始终是核心证据。
- **“所有内容最终都应该压成元数据。”** 已经保留语义的内容可以保持稳定；强制继续降级只会增加失真和缓存失效。
- **“多调用摘要器就能换更多上下文。”** 模型摘要也有成本和失败概率，必须以尝试预算限制，必要时采用机械降级。
- **“重写结果只影响文本质量。”** 破坏工具调用配对会让 Provider 拒绝请求；缺少事件标记又会使缓存问题无法诊断。

## 复习

- 为什么年龄不能作为唯一压缩规则？——它无法识别早期但仍被当前任务依赖的证据，会引发重复读取和上下文抖动。
- 为什么要在首次处理后保持层级稳定？——避免重复摘要、Prompt 反复变化和缓存持续失效，同时保持历史重建可复现。
- 为什么正文工具需要下限？——只留元数据会删掉调用该工具的主要价值；模型无法利用发现，只能重新取回。

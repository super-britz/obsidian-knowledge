# 案例：研究助手的渐进实验

> [!abstract] 这是一个待实践的实验模板：用同一个研究助手验证工具、记忆、编排和治理何时真正值得增加。开始实验后，每一版只增加一个可观测能力，并记录它解决的痛点与带来的新风险。

## 先看流程

```text
最小问答
→ 可调用工具
→ 可保存与检索状态
→ 可规划和校验
→ 可协作处理复杂任务
→ 可恢复、观测并受治理地长期运行
```

原书首页给出从 Part 1 到 Part 9 的研究助手演进。当前实际导航还包含 Part 10 的 Agent Loop 工程，可作为长期运行能力的后续验证方向。

## 实验路线

| 版本 | 新增能力 | 要验证的核心问题 | 典型风险 |
| --- | --- | --- | --- |
| v0 | ReAct 基础循环 | 模型能否基于观察结果完成多步任务？ | 无法停止、任务状态不清 |
| v1 | 搜索、文件读取等工具 | 意图怎样可靠变成外部行动？ | 工具失败、结果不可用、权限过宽 |
| v2 | 记忆与历史召回 | 什么状态需要跨轮次保留？ | 过期信息、上下文污染、成本增长 |
| v3 | 任务分解与反思 | 不确定任务怎样提高完成率？ | 过度推理、额外调用不带来收益 |
| v4 | 搜索、分析、写作协作 | 何时需要分配角色与控制权？ | 协调成本、责任模糊、重复工作 |
| v5 | 持久化、可观测性、预算与权限 | 系统怎样在失败和约束下继续运行？ | 观测缺失、成本失控、恢复不一致 |
| v6 | 浏览器操作、代码生成、后台运行 | 长时间、跨环境任务怎样保持可控？ | 副作用扩大、超时、卡循环、上下文外溢 |

## 每版的最小实验记录

```md
## 本次新增能力

## 它修复的旧失败

## 输入、状态、动作与完成条件

## 观测指标
- 成功率 / 人工返工：
- Token 与工具成本：
- 总耗时：
- 失败类型与恢复率：

## 新增风险与保护措施

## 是否值得保留
```

## 工程决策

- **先做可验证的最小版本。** 只有当上一个版本的失败已被观察到时，才引入下一层复杂性。
- **每次只新增一个主要变量。** 例如先验证工具回执，再引入记忆；否则无法判断效果来自哪里。
- **为回退保留简单路径。** 若 Planning、多 Agent 或长上下文不能提升可观测指标，应回到单 Agent、确定性工作流或人工确认。

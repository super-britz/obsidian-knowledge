# Computer Use 受控界面操作

> [!abstract] Computer Use 用视觉理解和键鼠动作突破 API 边界：Agent 不再只调用结构化接口，还能操作人类界面。但界面是模糊、异步且充满副作用的环境；可靠性不来自“看见按钮就点击”，而来自把每个动作限制为可授权、可验证、可中止的闭环。

## 第一性原理：看见界面不等于知道动作正确

界面没有稳定的 API 契约。截图中的按钮可能因缩放、加载、弹窗或页面变化而移动；网页文字还可能诱导 Agent 执行与用户目标无关的操作。一旦点击提交、付款、删除或发送，错误已成为外部副作用。

```text
当前界面与任务边界
→ 感知可见状态，提出带目标与预期结果的候选动作
→ 用策略、权限和风险级别决定允许、阻止或要求确认
→ 在隔离浏览器中执行受限动作
→ 等待稳定并验证真实状态
→ 成功继续；失败恢复、交给人工或在上限处停止
```

因此，Computer Use 的本质是**在不可靠视觉环境中执行受控副作用**，不是把坐标点击能力直接交给模型。

## 执行闭环：感知、决策、动作、验证各有职责

- **感知：** 截图、OCR 或元素识别只描述当前可见状态；敏感区域要遮盖，界面内容不能天然当作可信指令。
- **决策：** 输出结构化动作（点击、输入、滚动、等待、结束）、目标说明、置信度和预期结果；Agent 与执行层传递归一化坐标，实际像素由执行层按分辨率和 DPI 换算。
- **执行：** 浏览器/桌面运行在隔离会话中，只允许必要域名、账户和输入能力；每步有最大迭代、页面访问与时间边界。
- **验证：** 操作后等待加载和动画稳定，再重新观察；对不可逆业务操作，优先核验系统状态或回执，不能只看截图“似乎变了”。

这条闭环与 [[wiki/AI Agent 架构/02：ReAct 循环|ReAct]] 相同：观察必须改变下一步决策；不同之处是每次行动都可能立刻影响外部世界。

## 风险边界：模型置信度不能代替授权与确认

[[wiki/AI Agent 架构/24：策略治理与授权决策|策略治理]]决定某个账户是否可访问特定域名、执行特定动作；Computer Use 只在获准范围内行动。删除、提交、支付、发送、登录及敏感信息输入等高后果步骤应要求用户确认，并记录动作、页面、账户、原因与结果。

同时需要把浏览器当作不可信工具环境：域名白名单和操作策略限制访问面，敏感截图遮盖减少泄露，[[wiki/AI Agent 架构/25：安全执行与能力沙箱|沙箱]]限制执行器与宿主的能力。三者分别解决“应否做”“只能在哪做”“执行器能碰什么”，不能相互替代。

## 恢复与成本：失败要有终点，视觉要花在关键处

常见失败包括坐标偏移、页面未稳定、弹窗遮挡、点击无效和重复重试。恢复应先区分“仍在加载”“状态未变化”“目标消失”等原因，再采取等待、重新感知、回退或有限重试；达到尝试上限则停下并暴露当前状态，避免无限点击。

视觉理解的成本通常高于稳定的 DOM 自动化。已知、稳定界面优先使用 API 或 DOM 选择器；只有缺少可靠接口或界面变化难以维护时再启用 Computer Use。可降低成本的手段是按状态变化截屏、连续输入后再验证、缓存未变界面、用小模型处理简单定位；但高风险动作不能为了省钱跳过验证。成本与失败数据应接入 [[wiki/AI Agent 架构/22：Agent 可观测性与诊断闭环|可观测性]] 和 [[wiki/AI Agent 架构/23：Token 预算与成本护栏|预算护栏]]。

## 工程决策

1. 先选最窄、最稳定的交互方式：API 优先，其次 DOM 自动化，最后才是 Computer Use；“能点”不是采用视觉自动化的充分理由。
2. 为每个动作定义结构化契约：允许的动作类型、目标、归一化位置、输入内容、预期结果、置信度、风险等级和确认要求；执行器不得接受自由文本命令。
3. 使用隔离浏览器、最小权限账户、域名白名单、敏感信息遮盖和最大循环上限；不要让 Agent 继承用户的完整桌面、Cookie 或宿主凭证。
4. 对不可逆或高金额/高影响动作设置策略审批和人工确认；确认界面应展示将要影响的对象与结果，而不只是“是否继续”。
5. 将前后状态、动作决策、验证结果、重试原因、耗时和视觉调用成本结构化记录；用回归场景覆盖缩放变化、异步加载、弹窗、拒绝确认和失败恢复。

## 常见误解

- **“Computer Use 就是视觉版 Playwright。”** 它会在视觉不确定性下自主决策，必须比脚本自动化增加授权、验证和恢复边界。
- **“模型很有把握就可以自动提交。”** 置信度是模型信号，不是业务授权；高后果动作仍需策略和确认。
- **“截图验证成功就证明业务成功。”** 页面变化可能是本地动画或错误提示；关键结果要核验真实系统状态。
- **“所有界面都该改成视觉自动化。”** 稳定 API/DOM 通常更快、更便宜、更可测试；视觉能力只补接口缺口。

## 复习

- 为什么 Computer Use 必须在动作后再观察？——界面和坐标不可靠，只有验证后的新状态才能说明动作是否真的生效。
- 为什么要把策略、沙箱和人工确认叠加？——它们分别限制授权范围、执行环境和不可逆决策，任一单独使用都留下缺口。
- 何时不该使用 Computer Use？——已有稳定 API 或 DOM 契约、且界面操作没有带来额外价值时，应选择更确定、低成本的方法。

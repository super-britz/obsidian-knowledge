# 概念建模笔记检查清单

用于新建或实质性维护正式 `wiki/` 知识页。目标不是把每篇笔记写长，而是保证它能形成并检验“机制 → 约束 → 表现 → 工程决策”的可迁移心智模型。

> [!important] 适用边界
> - `raw/` 原始资料保持原貌，不套用本清单。
> - 临时摘录、阅读草稿、索引页和纯术语速查页可以简化；成为正式长期知识页前必须补齐核心链条。
> - 课程笔记使用 [[_meta/templates/课程笔记模板|课程笔记模板]] 的课程化结构，但仍需覆盖适用的机制、约束、表现与决策。
> - 不适用的部分应明确写“本页不适用”及原因，不能为了填模板而编造结论。

## 一、来源与认识边界

- [ ] 关键事实能链接到 `raw/` 或其他可靠来源。
- [ ] 明确区分了“来源事实”“机制推导”“工程建议”和“待验证项”。
- [ ] 没有把推测、经验或推荐写成来源事实。
- [ ] 写出了概念、方案或结论的适用边界；必要时说明不适用场景。

## 二、概念建模链条

- [ ] 说明了它解决的核心问题，以及它在完整系统中的位置。
- [ ] 说明了输入、关键过程和输出；读者能顺着因果关系复述机制。
- [ ] 至少保留一项能力限制、资源代价、可靠性风险或安全边界。
- [ ] 至少保留一个用户、开发者或系统可观察到的现象，包括可能的失败表现。
- [ ] 至少给出一条有条件的工程决策：何时使用、何时不使用，以及相应代价或保护措施。

## 三、可迁移性与验证

- [ ] 至少给出一个具体场景、反例、实验或可验证任务。
- [ ] 自测问题覆盖“为什么”“如果……会怎样”“因此如何决策”三个层次。
- [ ] 关联了真正必要的前置、后续或相邻概念，避免孤立术语页。
- [ ] 完成后不看原文，仍能用自己的话解释因果链和工程取舍。

## 四、完成判定

- **可发布**：一、二部分全部通过；三部分至少通过三项；来源、边界和决策均清晰。
- **草稿**：来源已有但机制或工程决策尚未得到足够支撑；应在 `status` 中标为 `草稿` 或 `待验证`。
- **退回为摘录**：只有定义、原文节选或术语罗列，无法形成机制链条时，不作为正式长期知识页。
